# WP 13.12.0 — v0.13.0 Academy Retrospective Completion

## 1. Introduction

`WP 13.12.0` is a governance and documentation Work Package. It closed
the single Release Blocking finding raised by `v0.13.0`'s own release-gate
review: sixteen of the release's twenty-five delivered Work Packages had
shipped with no Academy retrospective at all.

It created those sixteen retrospectives, registered them, and corrected
the false compliance claims that had allowed the gap to persist. It
changed **zero** `src/` and `tests/` files.

## 2. Purpose

To make `v0.13.0` compliant with Engineering Governance §6 — "A Work
Package retrospective (`docs/academy/03 Work Packages/`) is created for
**every future work package**" — and thereby clear the Governance
readiness category's Release Blocking status.

## 3. Background

The release-gate review classified the gap as Release Blocking on two
grounds: `docs/architecture/Engineering Readiness Review Architecture.md`
§2.4's Academy completeness row states plainly "**Blocking if:** a Work
Package shipped with no retrospective", and Engineering Governance §6 is
unconditional.

The sixteen were `WP 13.2B`, `WP 13.9.0`–`WP 13.9.7`, `WP 13.10A`–`WP 13.10C`,
and `WP 13.11A`–`WP 13.11D` — the entire trust-boundary remediation chain,
which is the security substance of the release.

## 4. The Problem

Two problems, and the second was worse than the first.

**The gap itself.** Sixteen Work Packages existed only as commit messages
and `WorkPackages.md` rows. The knowledge-loss risk was already
demonstrated once: `WP 13.9.1` had to reconstruct `WP 13.3B`'s
retrospective from commit `88e41a2`'s message because the article had
never been written.

**A false claim of compliance.** `PROJECT_STATUS.md` recorded, twice,
that these Work Packages were exempt — "Confirmed, by convention check
against `Academy Index.md`'s own maintenance rule and the `WP 13.2B`/
`WP 13.9.1` precedent". `Academy Index.md` contains no such rule; its
stated obligation is the opposite. The cited "precedent" was the gap
itself, used to justify its own continuation. That is not work left
undone — it is work recorded as not required, citing a rule that does not
exist.

## 5. The Design

**Evidence first, drafting second.** Primary sources were fixed before
any drafting began: each Work Package's own commit message; its row in
`docs/releases/v0.13.0/WorkPackages.md`; `PROJECT_STATUS.md`'s retained
strata; the Technical Debt Register; and direct reads of real source
where a claim was checkable from code.

**Disjoint file ownership.** Drafting was distributed across sub-agents,
each owning a disjoint set of new files and forbidden from touching any
existing file. All shared-file integration — Index, Register,
`WorkPackages.md`, `PROJECT_STATUS.md` — was performed centrally.

**The 13-section template**, per §6, for all sixteen, adapted in content
to Work Package kind: for a review Work Package, "The Design" describes
the design of the *review*; for an integration Work Package, it describes
the integration discipline; only remediation Work Packages describe a
software design.

**Central fact-checking.** Every cited commit SHA was verified to exist
and to map to the claimed Work Package. Every test figure was traced to a
permitted source. Figures appearing only in a commit message were
attributed to that commit message rather than asserted as independent
fact.

## 6. Alternatives Considered

**Record a governance exemption instead.** Rejected — and it was not this
Work Package's decision to make. Amending §6 is a governance decision
above the Technical Review tier; the Work Package's own instruction
forbade creating an exemption.

**Write shorter, summary-only articles.** Rejected: §6 names the
13-section template explicitly, and the blocking finding was
non-compliance with §6.

**Backfill only the most significant Work Packages.** Rejected: §2.4's
blocking condition is per-Work-Package, so any remaining gap keeps the
category Not Ready.

## 7. Why This Solution Was Chosen

Because the finding was compliance with an unconditional rule, and the
only conforming remedy was the artefacts themselves. The false exemption
claims had to be corrected in the same pass, since leaving them would
have left the record asserting that the work just completed had never
been required.

## 8. Architectural Principles

- **Engineering Governance §6 is unconditional.** A precedent of
  non-compliance is not an exemption.
- **Disclose, don't fabricate.** Where sources disagreed, both readings
  were recorded rather than one silently chosen.
- **Retention over deletion.** The false claims were struck through and
  annotated, never removed, preserving the audit trail.
- **Central integration.** Shared registers were edited by one owner.
- **Documentation-only means documentation-only.** Zero `src/`/`tests/`
  files touched.

## 9. Benefits

All twenty-five delivered Work Packages have exactly one retrospective —
verified programmatically, zero missing, zero duplicates. The Academy
Index gained eighteen entries (the sixteen, plus `WP 13.3A`/`WP 13.3B`,
which had retrospectives but no walkthrough-list entry). The Academy
Register gained sixteen rows, with counts re-derived by direct file count
rather than carried arithmetic (113 → 129; 178 → 194).

The false exemption claims are corrected at both `PROJECT_STATUS.md`
sites and in the two `WorkPackages.md` rows that repeated them. The
`TD-56` grade wording, which collided with `ADR-0106` §4's formal term
"Release Blocking", was normalised to **"Disclosed, Non-Blocking for
`v0.13.0`; mandatory precondition to enabling third-party plugin
support"** with the underlying technical classification unchanged.

## 10. Trade-offs

Sixteen retrospectives written after the fact are necessarily
reconstructions. They are grounded in primary evidence and attribute
every figure to its source, but they cannot recover reasoning that was
never written down — sub-agent-level detail, in particular, exists only
where a commit message happened to record it. Each carries an explicit
provenance note saying so.

The retrospectives also use the 13-section template uniformly, whereas
the repository's own precedent for review Work Packages
(`WP 13.0B`, `WP 13.0.0A`, `WP 13.1B`, `WP 13.3B`) is a lighter
six-section shape. §6 and the commissioning instruction both specify
thirteen sections; the divergence from local precedent is deliberate and
disclosed.

## 11. Common Mistakes

- **Treating a precedent of omission as an exemption.** Three separate
  Work Packages recorded that no retrospective was required, each citing
  the previous one. None checked whether the rule they cited existed.
- **Citing a rule without reading it.** The claimed `Academy Index.md`
  "maintenance rule" was never verified against the file.
- **Assuming a green health-check means compliance.** `governance-healthcheck.ps1`
  compares Academy *file count to link count*; it structurally cannot
  detect a missing retrospective, and passed throughout the gap.
- **Introducing a defect while correcting one.** This Work Package's own
  first health-check run failed: the correction text quoted §6's
  `` `03 Work Packages/` `` as a backticked path, which the
  `PROJECT_STATUS.md` path check requires to resolve from the repository
  root. Corrected to the full path.
- **Trusting drafted text over the tree.** One drafted retrospective
  asserted it had no Register or Index entry — true when drafted, false
  by the time integration finished. Caught and corrected centrally.

## 12. Future Evolution

`WP 13.12.1` re-executed the readiness review mechanically against the
result and confirmed Governance readiness moves from **Not Ready** to
**Pass, with observations** once this work is committed.

One pre-existing gap was disclosed rather than closed: the Academy
Register's `03 Work Packages` table carries fewer rows than there are
files (a deficit unchanged by this pass — sixteen rows added for sixteen
files), with `WP 13.0.0` and `WP 13.0.0A` among the unrowed. That is
register coverage, not Academy completeness, and is recorded in the
Register itself.

## 13. Key Takeaways

- An unconditional governance rule cannot be waived by precedent, and a
  precedent that is itself the gap is not evidence of anything.
- A written claim that work was not required is more damaging than the
  missing work: it stops the next reviewer from looking.
- A machine check that passes is not evidence of compliance unless it
  actually measures the obligation.
- Reconstructed retrospectives are worth writing, but they must say
  plainly what they could not recover.
