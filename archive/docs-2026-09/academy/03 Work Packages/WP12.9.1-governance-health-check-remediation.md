# WP 12.9.1 — Governance Health Check Remediation

## What This Document Is

The retrospective for `WP 12.9.1`, commissioned directly to repair the
four genuine `[FAIL]` results `governance-healthcheck.ps1` (`WP 11.2A`)
was reporting against `main` — `Academy Index.md`, `Documentation
Register.md`, `PROJECT_STATUS.md`, and `Governance Index.md`. The
controlling brief was explicit: treat the checker as the source of
truth, prove root cause for every failure before touching anything, and
repair the repository rather than weaken, bypass, or suppress the
checks. Documentation/governance only — no production code, no tests,
no workflow change. See `scripts/governance-healthcheck.ps1`, `WP11.2A
Governance Health-Check Tool.md`, and `ADR-0106` for the philosophy this
Work Package continues.

**One correction made before any other work began.** The controlling
brief's own supplied evidence (a CI run against commit `86b99f3`) was
stale — that commit is `WP 12.1A`/`WP 12.1B`'s own merge, several merges
behind `main`'s actual tip (`fb76ce8` at the time this Work Package
began). Running the checker directly against `main` first, before
investigating any individual finding, is what this Work Package did —
and it changed the result set: the brief's own named "missing version
tags `v0.3.0`…`v0.10.0`" finding had **already been resolved** by
intervening work (`main` carries all nine real tags, `v0.3.0`–`v0.11.0`;
`Test-ReleaseRegisterMatchesTags` passes outright) and required no
action here. The four findings below are the ones that genuinely
reproduce against `main`.

## Phase A — Investigation (Root Cause, Every Finding)

Per the controlling brief: independently determine root cause for each
failure, and prove whether it is genuine documentation drift, genuine
repository drift, a checker false positive, or an obsolete structural
assumption — never assume the checker is right, and never assume it is
wrong.

### A.1 — Academy Index (`Test-AcademyIndexMatchesArticles`)

**Finding:** 63 real Academy articles exist under `docs/academy/` with
no link from `Academy Index.md` — 15 concept guides (`02 Runtime
Architecture/17`–`31`) and 48 Work Package retrospectives (the tail of
`v0.7.0` through all of `v0.8.0`/`v0.9.0`/`v0.10.0`, plus all ten
completed `v0.12.0` Work Packages).

**Root cause — genuine documentation drift, proven, not assumed.**
Directly confirmed by `ls "docs/academy/02 Runtime Architecture"` and
`ls "docs/academy/03 Work Packages"`: every one of the 63 files is real,
substantive content, not a stray or placeholder. `Academy Index.md`'s
own "Work Package Walkthroughs" section — a chronological list, by its
own stated purpose the canonical index of every retrospective — silently
stopped being maintained at `WP 7.3A`, several releases ago; no
Work Package since then updated it, despite `Academy Index.md`'s own
opening paragraph stating the obligation explicitly ("a work package
that adds or rewrites an Academy document updates this index as part of
the same change, not as a separate, later pass"). This is the same
"Academy Index" gap `WP 11.2A` first found and explicitly declined to
fix, deferring it by name.

**Checker correctness:** confirmed correct. `Get-ResolvedMarkdownLinks`
correctly parses every real markdown link in the index and resolves it
relative to the index's own directory (the same rule a browser applies);
`Test-AcademyIndexMatchesArticles` correctly diffs that set against a
real, recursive `Get-ChildItem` of `docs/academy/`. No false positive
found anywhere in this check's own logic.

**Fix:** `Academy Index.md`'s "Work Package Walkthroughs" section
extended with four new/completed phase blocks (closing `v0.7.0`, adding
`v0.8.0`, `v0.9.0`, `v0.10.0` in full, and `v0.12.0`'s ten completed Work
Packages in their actual completion order, not numeric order); two new
`###` topic sections added for the 15 previously-unlinked concept
guides, cross-referenced from the relevant Work Package entries the same
way every existing topic section already does. This document's own
entry was added in the same pass, so this Work Package does not
reproduce the exact drift it exists to close.

### A.2 — Documentation Register (`Test-DocumentationRegisterReferences`)

**Finding:** nine referenced paths reported missing — six were
bare numbered-folder shorthand (`01 Engineering Principles/` …
`06 Engineering Standards/`), plus `docs/diagrams/`, `docs/roadmap/`,
`docs/releases/v0.2.0/`.

**Root cause 1 — a checker scope limit, not a defect, confirmed by
direct code reading, not by rerunning it and guessing.**
`Get-PathLikeReferences`'s own comment explicitly documents that it
*deliberately keeps* the bare `"NN Category Name/…"` shorthand this
project's prose uses "when the `docs/academy/` prefix is already
established by context," rather than filtering it as noise — the same
comment calls it "a real (if ambiguous) reference." `Test-RepoPath`,
however, always resolves a candidate by joining it directly against the
repository root; nothing in the checker ever supplies the implied
`docs/academy/` prefix. `WP 11.2A`'s own original verification section
(`WP11.2A Governance Health-Check Tool.md`) says so directly: "the bare
items… are the disclosed, known scope limit (ambiguous shorthand this
tool correctly cannot resolve without more context) — kept visible
rather than suppressed." That is a documented, deliberate design choice
from this tool's own author, re-confirmed here, not a bug — resolving it
by editing the checker to guess a folder from context it does not have
would be exactly the "weakening" the controlling brief prohibits.
**Fix:** the repository's own prose, not the checker — every bare
shorthand reference fully qualified to begin `docs/academy/…` inside the
same backtick span, removing the ambiguity at its source.

**Root cause 2 — genuine repository drift, two different shapes,
confirmed by direct filesystem inspection.**
`docs/diagrams/` and `docs/roadmap/` do not exist in a fresh checkout at
all — `git cannot track an empty directory`, exactly as `WP 11.2A`
already disclosed and explicitly declined to fix. `docs/releases/
v0.2.0/`, by contrast, is not an empty-directory case at all: `git
ls-tree` shows it was always a *tracked file* — `docs/releases/v0.2.0`,
no extension, no folder, containing a never-completed release-notes
skeleton (every section present, every field blank). `WP 11.2A`'s own
finding conflated this with the other two — a real, if narrow,
inaccuracy in that Work Package's own disclosure, corrected here in
`PROJECT_STATUS.md`'s historical narrative rather than silently
rewritten.
**Fix:** `docs/diagrams/README.md` and `docs/roadmap/README.md` added —
each a tracked, honest "purpose Unknown, disclosed, not guessed at"
marker, so the directories these documents already describe as existing
actually survive a fresh checkout. `docs/releases/v0.2.0` renamed to
`docs/releases/v0.2.0.md`, matching the naming convention its own
neighbour `docs/releases/v0.3.0.md` already established. `src/Plugins/`
— the identical class of gap, outside this register's own `docs/`-only
scope but confirmed the same way — also gains a tracked
`src/Plugins/README.md`, closing the fourth item `WP 11.2A` named.

### A.3 — `PROJECT_STATUS.md` (`Test-ProjectStatusReferences`)

**Finding:** the same shorthand/empty-directory classes as A.2, plus
three references broken by a different, previously-undiscovered defect:
`scripts/governance- healthcheck.ps1`, `docs/academy/03 Work
Packages/WP6.8-platform-services-integration- review.md`, and `02
Runtime Architecture/17-engineering- workspace.md` — each with a stray
space in the middle of an otherwise-correct filename.

**Root cause — genuine documentation drift, a real defect, confirmed by
reading the raw file.** All three are one inline-code span (a path in
backticks) hard-wrapped across a line break exactly at a hyphen already
present in the real filename. `PROJECT_STATUS.md`'s own prose hard-wraps
at ~72–80 columns; markdown collapses a line break inside an inline code
span to a single space when rendered, so each of these renders, and was
extracted by the checker, as a filename with a literal space inserted —
wrong either way, not only for the checker. Not a checker defect:
`Get-PathLikeReferences`'s own whitespace-normalisation step exists
specifically to let a genuine inline code span survive being split by
this project's own hard-wrap (documented in its own comment), and does
exactly that here — correctly reporting that the resulting, rendered
text does not name a real file.
**Fix:** each of the three (plus one further occurrence, `WP7.1F-…`,
found by the same read that does not reach a `/` and so was never
flagged by the checker's own path-shape filter, fixed anyway for the
same reason) rewrapped so the inline code span no longer breaks across a
line. The bare-shorthand and empty-directory findings shared with A.2
fixed the same way, in the same pass, including the two places
`PROJECT_STATUS.md`'s own historical narrative quotes `WP 11.2A`'s
original (partly imprecise, per A.2) finding — corrected in place with a
disclosed, dated annotation, this document's own established convention
for a later Work Package correcting an earlier entry, not a silent
rewrite of history.

### A.4 — Governance Index (`Test-GovernanceIndexOrphans`)

**Finding:** `docs/governance/Engineering/Engineering Vocabulary
Register.md` exists and is not linked from `Governance Index.md`.

**Root cause — genuine documentation drift, the simplest of the four.**
`Engineering Vocabulary Register.md` was created by `WP 12.1B`
(realising `ADR-0105`'s own Component 2) and populated with 46 declared
values across 11 declaring classes — real, substantive content, directly
confirmed by reading it. `Governance Index.md`'s own "## Engineering"
section lists the other ten `docs/governance/Engineering/` registers by
name but was never extended for this one. `WP 12.9.0` had already found
and disclosed this exact gap (its own Phase A repository assessment,
same register) but, being an architecture-only Work Package with no
implementation scope, correctly did not fix it — recorded, not silently
dropped.
**Checker correctness:** confirmed correct — the same resolved-markdown-
link diff `Test-AcademyIndexMatchesArticles` uses, applied to
`docs/governance/`; no false positive.
**Fix:** one new bullet added to `Governance Index.md`'s own "##
Engineering" section.

## Phase B — Trade-Offs Considered

**For A.1 (Academy Index):** the only real alternative to writing 63
real entries was declaring the gap "acceptable drift" and leaving the
`[FAIL]` in place with a documented rationale — rejected outright; the
controlling brief is explicit that a failure must become "genuinely
resolved," and this project's own Academy Index states its own
completeness obligation in its first paragraph. Writing the entries
directly, cross-checked against each real file's own title and opening
content (not invented from the filename alone), was the only option
consistent with that.

**For A.2/A.3 (`docs/diagrams/`, `docs/roadmap/`):** considered deleting
the claim these directories exist (editing the registers to stop
describing them) instead of making them real. Rejected: both directories
have been referenced, as intentional, disclosed, purpose-unknown
placeholders, across at least six other governance documents since `WP
11.2A` first found them — deleting the claim would either orphan those
five other documents' own claims or require rewriting all of them for a
directory whose only actual defect is "never committed with a tracked
file inside it." Adding one honest marker file per directory closes the
gap without erasing or duplicating that institutional record, and
mirrors exactly how `src/Plugins/` — the fourth, better-documented
member of the same `WP 11.2A` finding — is already understood.

**For the shorthand fix (A.2/A.3):** the alternative to fully-qualifying
every bare reference was teaching `Test-RepoPath` to infer a
`docs/academy/` prefix for any candidate matching the numbered-folder
shape. Rejected, and not attempted: the checker's own author already
documented this exact shape as a **deliberate, disclosed scope limit**,
not an oversight — inferring the prefix would require the checker to
guess which of several numbered-folder conventions a reference means
whenever context is genuinely ambiguous elsewhere in the repository (this
project uses `NN name/` shorthand only for `docs/academy/`'s own six
top-level folders today, but nothing enforces that staying true), which
is precisely the kind of silent, unverifiable inference this tool's own
design philosophy (`WP11.2A Governance Health-Check Tool.md`) rejects
elsewhere. Fully-qualifying the prose is strictly safer and, per that
same document, was already the anticipated resolution.

**Scope not taken:** `scripts/governance-healthcheck.ps1` was not
modified. Every finding above resolved with evidence that the checker's
own behaviour is either already correct or a documented, deliberate
scope limit — never with evidence of an actual defect. Per the
controlling brief, that means it stays untouched.

## Key Takeaways

1. **The stale-CI-run trap was real and worth checking first.** Running
   the checker directly against `main`'s actual tip, before touching
   anything, immediately removed one of the brief's own named findings
   (missing version tags) from scope — investigating a finding that no
   longer reproduces would have been wasted, misleading work.
2. **All four failures were genuine.** Zero checker defects were found
   in eight checks' worth of logic read line by line. One check
   (`Test-DocumentationRegisterReferences`/`Test-ProjectStatusReferences`'s
   shared shorthand-resolution gap) looked, briefly, like a candidate
   defect — until its own author's contemporaneous design note
   (`WP11.2A Governance Health-Check Tool.md`) was found to have already
   named and accepted it as a scope limit, not an oversight.
3. **`WP 11.2A`'s own finding needed one small correction.** Lumping
   `docs/releases/v0.2.0/` in with the two genuinely-untracked-empty-
   directory cases was itself a minor inaccuracy — it was a tracked,
   misnamed file the entire time. Disclosed and corrected in place, the
   same discipline this project applies to every other finding.
4. **Every fix targeted the repository, not the checker.** No check was
   weakened, relaxed, or suppressed; `governance-healthcheck.ps1` is
   unmodified.
