# WP 10.1B — Architecture Review

## Purpose

The required, dedicated Architecture Review — confirming this Work
Package's own explicit "No Engineering Domain changes / No Workspace
contract redesign / No UX redesign" constraints were honoured, and that
every fix was placed at an architecturally appropriate layer.

## 1. Scope Constraints — Independently Confirmed

- **No Engineering Domain changes:** `git diff --stat` re-run
  independently against `src/Tempest.Core/EngineeringDomain/` — zero
  matches. `TD-38`'s own two candidate fixes (uniqueness enforcement on
  `EngineeringObjectFactory<T>`; durable-store rehydration for
  `IEngineeringObjectRepository`) were correctly recognised as
  Engineering Domain changes and deliberately not attempted, disclosed
  instead — the architecturally correct outcome given this Work
  Package's own explicit constraint, not an oversight.
- **No Workspace contract redesign:** none of the twelve `WP 8.0B`
  frozen Workspace contracts changed shape. `IWorkspaceManager.StartAsync`'s
  own public signature is byte-for-byte unchanged — only
  `WorkspaceManager`'s own private `WaitForServicesAsync` implementation
  changed, invisible to any contract consumer.
- **No UX redesign:** `Tempest.Desktop`'s only surface change is the
  removal of an internal, private method
  (`WorkspaceHost.WaitForHostRunningAsync`) and one new, optional,
  defaulted constructor parameter consumed only by test code — no
  visible control, layout, or interaction changed.

## 2. Fix Placement — Each at Its Own Correct Layer

- **`TD-26`:** fixed in `Tempest.App.Workspace` (`WorkspaceManager`) —
  the actual owner of the readiness contract every `IWorkspaceManager`
  consumer depends on, not `Tempest.Desktop` (a mitigation layer, `WP
  10.0B`/`WP 10.1A`) and not `Tempest.Core.Runtime` (`TempestHost`
  itself already exposes the correct, authoritative signal via
  `IDiagnosticsProvider` — no Runtime Host change was needed or made).
- **`TD-37`:** fixed in `Tempest.Samples` — the actual owner of the
  literal, fixed business identifiers that collide; correctly not
  fixed in `Tempest.Core.Materials`/`Tempest.Core.Requirements` (both
  Platform Services' own uniqueness enforcement is a real, deliberate,
  correct feature — `ADR-0055`/`ADR-0058` — not the defect) and
  correctly not fixed by changing `PersistenceStore`'s own default root
  path (a production behavioural change with a much larger blast
  radius than this Work Package's own scope justifies, and not what a
  real, durable, cross-launch persisted engineering platform should
  do).
- **Test isolation:** fixed in `Tempest.Desktop.Tests` itself, mirroring
  `Tempest.Core.Tests`' own already-established, already-correct
  pattern (`TempDirectory` per test, `WP 7.3A`) rather than inventing a
  new one — the smallest, most consistent architectural choice
  available.

## 3. New Architectural Surface — Minimal and Additive

Two new, optional, `null`-defaulted parameters
(`EngineeringWorkspaceComposer.Build(configurationSources)`,
`WorkspaceHost(persistenceRootPathOverride)`) are the only new public
surface this Work Package introduces. Both are pure widening — every
existing call site continues to compile and behave identically without
change; neither introduces a new interface, a new contract, or a new
cross-project dependency direction (`Tempest.Desktop.Tests` still only
depends on `Tempest.Desktop`/`Tempest.App`, unchanged).

## 4. `TD-38` — Correctly Deferred, Not Silently Absorbed

Confirmed `TD-38` was registered as a distinct Technical Debt item
(`docs/governance/Quality/Technical Debt Register.md`) rather than
folded into this Work Package's own fix, and confirmed its two named
candidate resolutions are both explicitly out of scope here — the
correct architectural discipline: a Work Package's own scope boundary
is honoured even when a nearby, related, cheaper-looking fix is
visible, mirroring this project's own established `TD-26` precedent
(disclosed for multiple Work Packages before finally being fixed at its
own source, here).

## 5. Recommendation

**Sound, complete.** Every fix placed at its architecturally correct
owning layer; zero scope-constraint violations; the one new finding
correctly deferred rather than over-reached into forbidden territory.
