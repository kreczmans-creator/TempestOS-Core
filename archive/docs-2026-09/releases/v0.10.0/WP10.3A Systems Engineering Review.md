## 2. Integration — Workspace, Cockpit, Property Inspector

- **Workspace**: every write dispatches through the real, unmodified
  `IWorkspaceManager`/`CommandHandlerTable` (extended additively,
  `ADR-0097`); every read goes through the real, unmodified
  `EngineeringDomainContext`.
- **Cockpit**: `ObjectEditorView.ActionCompleted` → `MainWindow`'s own
  handler calls `_cockpitView.Refresh()`, the identical pattern
  `_inspectorView.ActionCompleted`/`_explorerView.ActionCompleted`
  already establish (`WP 10.0B`–`WP 10.2A`) — a Save/Cancel in the
  editor keeps the Cockpit's own KPI cards current, never stale.
- **Property Inspector**: same `ActionCompleted` handler also calls
  `_inspectorView.Refresh()` — a Rename committed from the editor is
  reflected in the Property Inspector's own Identity section
  immediately, without requiring the user to re-select the object.

Independently confirmed by direct read of `MainWindow.BuildDocumentContent`
— all three integration points wired from one shared handler, not
duplicated or inconsistently applied.
