# WP 10.2A — Architecture Review

## Purpose

The required, dedicated Architecture Review — confirming this Work
Package's own explicit "No Engineering Domain redesign / No Runtime
redesign / No Workspace contract redesign unless genuinely required"
constraints were honoured, and that the one genuine contract extension
(`ADR-0096`) was placed correctly and justified proportionately.

## 1. Scope Constraints — Independently Confirmed

- **No Engineering Domain redesign**: `git diff --stat` re-run
  independently against `src/Tempest.Core/EngineeringDomain/` — zero
  matches.
- **No Runtime redesign**: zero matches against `src/Tempest.Core/Runtime/`,
  `src/Tempest.Core/Modules/`, `src/Tempest.Core/Diagnostics/`.
- **No Workspace contract redesign unless genuinely required**: exactly
  one contract, `IWorkspaceManager`, was extended — additively, five new
  members, zero existing member changed. Every other Workspace contract
  (`IWorkspace`, `IWorkspaceView`, `IProjectExplorer`,
  `IPropertyInspector`, `IWorkspaceLayout`, `IWorkspaceState`,
  `ISelectionService`, `INavigationService`) is byte-for-byte unchanged,
  confirmed by direct diff.

## 2. `ADR-0096` — Was This Extension "Genuinely Required"?

Yes, independently confirmed: the controlling instruction names "inline
rename" (Project Explorer) and "editable controls where appropriate"
(Property Inspector) as required, real capabilities. No existing
Workspace contract offered any path from the Desktop presentation layer
to a discipline's own real, parameterised mutating command — the only
existing invocation surface (`ICommandRegistry.InvokeAsync`) is
`CreateDefault`-based and structurally incapable of carrying a
runtime-selected target Id and user-typed text (`CreateDefault` is a
parameterless `Func<ICommand>`). Building "inline rename" honestly,
rather than as UI with nothing to dispatch to, required exactly this
class of extension. The alternative — not building real inline
rename/editable controls at all — was rejected: it would have left two
explicitly-required capabilities undelivered.

## 3. Fix Placement — Correct Layer

`ADR-0096`'s five new members live on `IWorkspaceManager`
(`Tempest.App.Workspace`) — the same interface `RegisterFacetProvider`
(`ADR-0082`, `WP 9.0A`) already extended for an analogous reason
(read-side, Kind-keyed extensibility). Placing Rename/Delete dispatch
there, rather than inventing a new interface or exposing
`CommandHandlerTable` directly to `Tempest.Desktop`, keeps the
Workspace's own existing "composition root registers, presentation
layer consumes" pattern intact (`ADR-0067`, `ADR-0071`) — `Tempest.Desktop`
never gains a new dependency on `Tempest.Core.Commands` internals
beyond what it already had (`ICommandRegistry`, unchanged).

## 4. New Presentation-Layer Surface — Minimal and Additive

`Tempest.Desktop/Theming/DesignTokens.cs` (new, values-only, no new
theming mechanism) and the `ProjectExplorerView`/`PropertyInspectorView`
constructor signature changes (`+IWorkspaceManager manager` parameter)
are the only structural additions. Both existing call sites
(`MainWindow.cs`, one test file) were updated; no other project
references either constructor.

## 5. `PanelHostControl` Visual Restructuring — Confirmed Non-Breaking

`PanelHostControl`'s own header was wrapped in an additional
`StackPanel` (to host a new `Separator` beneath it) — confirmed, by
direct re-read, that `HideRequested`'s own event contract and the
`DockPanel.SetDock`/`Children.Add` ordering both remain unchanged in
effect; only the header's own internal visual composition changed.

## 6. Recommendation

**Sound, complete.** The one genuine contract extension was correctly
justified, minimally scoped, and placed at its architecturally correct
layer, mirroring an already-established precedent (`ADR-0082`) rather
than inventing a new extensibility pattern; every other scope
constraint independently confirmed honoured.
