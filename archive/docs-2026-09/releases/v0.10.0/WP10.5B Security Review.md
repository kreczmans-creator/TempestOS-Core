# WP 10.5B — Security Review

## Purpose

A dedicated security assessment of `WP 10.5B`'s own new surface —
dialogs that mutate real Engineering data (Delete, Create, Duplicate),
a new notification-consumption path, and an unhandled-exception hook,
none of which should widen this platform's own trust boundary, but
verified directly rather than assumed.

## 1. Scope

`InputDialog.cs`, `MessageDialog.cs`, `SettingsDialog.cs`, `UserSettings.cs`,
`WindowUiState.cs`, `PlatformNotificationToastBridge.cs`; the
`ConfirmDeleteAsync`/`ObjectCreationHandlers` wiring in `RibbonView.cs`/
`ProjectExplorerView.cs`; `MainWindow.cs`'s own Closing gate and
unhandled-exception hook. No Engineering Domain, Runtime, or Workspace
contract file is in scope — none was touched.

## 2. Delete Confirmation — Reduces, Never Increases, Risk

Every Delete path already reached `IWorkspaceManager.DeleteObjectAsync`
directly, with no confirmation, before this Work Package — a real,
pre-existing risk of accidental data loss (mitigated only by the
platform's own soft-delete design, `IDeletable.IsDeleted`, §4 of the
Engineering Review). `ConfirmDeleteAsync` adds a real, opt-out-able
safety gate; it cannot be used to delete anything that was not already
deletable, and declining it changes nothing. No new capability, a
strict risk reduction.

## 3. The Real Create/Duplicate Dispatch — No New Mutation Path

`ObjectCreationHandlers`'s own two wired flows dispatch
`CreateMechanicalObjectCommand`/`DuplicateMechanicalObjectCommand`
directly via `ICommandDispatcher.DispatchAsync` — the identical,
already-registered, already-permission-checked dispatch path every
other real Workspace mutation already uses (`ADR-0063`). No new
command, no new handler, no bypass of any existing validation
(`MechanicalObjectFactoryRegistry.CreateAsync`'s own `ArgumentException`
checks are unchanged and still enforced).

## 4. `InputDialog` — No Injection Surface

The collected text is used exactly as `CreateMechanicalObjectCommand`'s
own `displayName` parameter already accepted from every other caller
(Rename, the Command Palette) — no new parsing, no new interpretation
as markup/code/a file path. The 200-character length check is a UX
guard, not a security boundary (the underlying `EngineeringObjectBase`
already accepts any string `DisplayName`, unchanged).

## 5. `PlatformNotificationToastBridge` — No New Trust Boundary

`IPlatformNotification` is already publishable by any module holding
an `IEventBus` reference — an existing, unchanged capability. This
class only adds a new *subscriber*, never a new *publisher* — it
cannot be used to trigger anything, only to display what something
else already chose to publish. The displayed text
(`$"[{Category}] {Message}"`) is rendered as literal `TextBlock.Text`,
identical to every other Toast consumer — no markup/HTML rendering
exists anywhere in `ToastNotification`.

## 6. `TaskScheduler.UnobservedTaskException` Hook — No New Surface, Real Safety Improvement

Calling `e.SetObserved()` prevents a genuinely unexpected exception
from crashing the process in older .NET behaviour patterns (a real,
disclosed safety improvement, not new risk) — the exception's own
message/type is shown to the *same* local user already running the
application, never transmitted anywhere. No stack trace, no
environment/credential data is included in the shown Details text —
confirmed directly, only `exception.GetType().FullName`/`.Message`.

## 7. `UserSettings`/`WindowUiState` — No New Data-Exposure Surface

Both persist through the identical `ISettingsProvider` substrate every
other Desktop-local state already uses — no new storage mechanism, no
new file, no new network call. Neither ever holds Engineering Domain
content (confirmed directly, §7 of the Implementation Report).

## 8. Honest, Disclosed Absences

- No new authorization check was added anywhere, because no new
  privilege boundary was crossed — every dialog gates or presents an
  already-permitted action.
- `SettingsDialog`'s own Theme change delegates entirely to
  `ThemeService.ToggleAsync`, already-existing, unmodified.

## 9. Recommendation

**Accept.** No new attack surface, no new mutation path beyond the
already-permitted `ICommandDispatcher` route, no new data-exposure
surface — the one new subscriber (`PlatformNotificationToastBridge`)
only displays what an already-trusted publisher already chose to
publish.
