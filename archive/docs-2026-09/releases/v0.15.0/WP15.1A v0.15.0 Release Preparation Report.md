## 4. Findings — Verified / Inferred / Unknown

**Finding 1 (Verified).** Two real, already-fixed production defects from
this range had never been given a Technical Debt Register entry: a
Windows startup crash (`WP 15.0A`, `Dispatcher.VerifyAccess` thrown off
the UI thread) and the Ribbon's horizontal scrollbar never rendering at
compact widths (`WP 15.0D`). Both added as `TD-121`/`TD-122`, status
**Resolved**, for traceability — not because either needs further work.

**Finding 2 (Verified).** Three commits in this range (`257bac7`,
`ee15986`, `0151f35` — all `WP 15.0B`) embed test pass-count figures in
their own commit messages (e.g. "373/386 passing", "3056/3088, identical
32-failure set") obtained via a local `global.json` SDK-substitution
technique later found to be flawed: **deleting** `global.json` to work
around this sandbox's unavailable pinned SDK version also breaks
`DesktopTestHelpers.RepositoryRoot`'s marker-file search, manufacturing
failures unrelated to the code under test. The corrected technique —
editing the SDK version field **in place**, then restoring the file
byte-for-byte before any commit — was adopted starting with `WP 15.0D`'s
own commit (`0451369`: "408/408 passing (0 failures)"). **The true,
currently-verified baseline for every commit in this range is 0 failures
both configurations** — confirmed independently by real GitHub-hosted CI
on every push in the range (§3), which never used the flawed local
technique at all. This retrospective disclosure does not change any test,
only the reliability of a historical commit-message claim.

**Finding 3 (Verified).** `WP 15.0A`'s own commit message, and `docs/
design/Tempest Engineering Design System Reference.md`, both cite
`FCR-0092` as the Future Capability this Work Package's brand recovery
closes. `FCR-0092` does not exist in this repository's `Future Capability
Register.md` — the real, confirmed range is `FCR-0001`–`FCR-0088`.
**Inferred, not confirmed** (the `Tempest.Companion` branch was not
reviewed by this Work Package): the same design-system document
describes `Tempest.Companion` as living "on its own branch," so the most
likely explanation is that `FCR-0092` belongs to a separate,
Companion-scoped capability numbering never translated into this
register. Not fixed — disclosed in both the Future Capability Register
itself and this report, since neither this Work Package nor a prior one
has reviewed the Companion branch to confirm.

**Finding 4 (Verified, already known, re-confirmed).** `v0.11.0`'s own
ten Work Packages (`WP 11.0A`–`WP 11.4B`) still have no Academy
retrospectives — `ls "docs/academy/03 Work Packages" | grep "^WP11\."`
returns nothing beyond `WP 11.5A` itself. Already disclosed by `WP-Z3`
§12 and re-confirmed by `WP 11.5A`; not this Work Package's to close
either — writing ten new retrospectives from a release five versions
past is a distinct, substantial undertaking of its own.

**Finding 5 (Verified — a disclosed scope limit, not a fixed gap).** The
Future Capability Register had gone unreviewed since `WP 13.11A`
(2026-08-17) — through all of `v0.13.1`, `v0.14.0`, and this range. This
Work Package reviewed it for currency (added the `Last Reviewed` entry
recording Finding 3) but did **not** perform a full, line-by-line
re-verification of all 88 entries' own `Status` fields against current
`main` — that is a distinct, substantial Future Capability Review, out of
a release-preparation Work Package's own scope, and is named here as the
real remaining gap rather than silently left unstated.

**Finding 6 (Verified).** The Delivery/Release Register's own summary
paragraph had never counted `v0.14.0` at all: its own row (added by `WP-
Z4`) was accurate, but the "Total: 14 versions referenced — 12 confirmed
released" tally undercounted by exactly one, omitting `v0.14.0` from its
own list. Found while adding the `v0.15.0` row; corrected in place (now
13 confirmed released, 15 total, plus `v0.15.0` itself as a distinct
"in preparation, not yet tagged" category).

**Finding 7 (Verified, disclosed, not fixed).** `docs/governance/
Documentation/Academy Register.md` — a register distinct from `Academy
Index.md`, tracking per-article originating-Work-Package and
"transferable lesson" annotations — was not updated with entries for the
five retrospectives this Work Package added, despite its own stated
`Review Frequency` ("in practice, every Work Package"). `Academy Index.md`
itself (the reader-facing navigation this deeper register cross-checks
against, and the only Academy artifact `governance-healthcheck.ps1`
verifies) was updated and is orphan-free (§5). Backfilling five
proper "transferable lesson" entries into `Academy Register.md`'s own
established, denser annotation style is a further, separable piece of
work this report names rather than performs, to avoid a shallow,
box-ticking entry that would not meet that register's own real standard.

**Unknown.** Whether `WP 15.0A`'s cited `FCR-0092` corresponds to a real,
numbered entry in `Tempest.Companion`'s own governance suite — that
branch was not reviewed by this Work Package (Finding 3).
