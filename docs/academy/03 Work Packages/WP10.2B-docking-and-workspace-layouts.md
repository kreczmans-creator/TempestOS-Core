# `WP 10.2B` — Docking & Workspace Layouts

## 1. Introduction

`v0.10.0`'s own sixth Work Package — a professional dockable
workspace over the existing `Tempest.Desktop` shell: resizable panels
extended to a third edge, Collapse, Auto-Hide, three predefined
layouts, Reset Layout given a real affordance, and a new dockable
Output panel — built entirely without touching any of the twelve
frozen `WP8.0B` Workspace contracts.

## 2. Purpose

Implementation retrospective, mirroring `WP10.2A`'s own two-part
(Concept Guide, Implementation Retrospective) structure. See
`24-docking-and-workspace-layouts.md` for the design narrative; this
file focuses on what was built, what was already real, files touched,
and honest disclosure of the one genuine finding.

## 3. Background

Commissioned directly after `WP 10.2A` (Workspace Modernisation)
closed with "await Product Owner instruction before `WP 10.2B`." This
Work Package's own controlling instruction named fourteen scope items
and six explicit exclusions, closing with "STOP. Await Product Owner
instruction before `WP 10.3A`."

## 4. The Problem

See `24-docking-and-workspace-layouts.md` §4 for the full three-part
problem statement (no status/output surface, no lightweight
"temporarily out of the way" affordance, no repeatable named
arrangement).

## 5. The Design

See `24-docking-and-workspace-layouts.md` §5 for the full design
narrative. In summary: `DockingGrid` gained a third dock row (Bottom);
`PanelHostControl` gained Collapse (in-place shrink) and Auto-Hide
(unpin, hand space back, flyout-on-click) header affordances, sharing
one visual "thin strip" but behaviourally distinct; `PredefinedLayouts`
defines three named presets over already-legal Workspace values;
`DesktopPanelUiState` persists the genuinely new Desktop-local state
through a second, sibling `ISettingsProvider` key.

Every one of the fourteen named scope items realised; zero changes to
any of the twelve frozen `WP8.0B` contracts (a stronger compatibility

## Architectural Debt Assessment

**One new item**: `TD-39` — `PanelHostControl`'s own opaque overlay
background is a fixed `Brushes.White`, not theme-variant-aware,
mirroring `CommandPaletteOverlay`'s own identical, previously-
unregistered limitation (`WP 10.0B`). Both surfaced and registered
together for the first time. Cosmetic only, no functional defect
(`WP10.2B Engineering Review.md` §4). `FCR-0067` raised as its own
future-fix candidate.

No other new debt. Every pre-existing item (`TD-01`–`TD-38`) reviewed
and confirmed unaffected by this Work Package's own diff.

## Observations

**A genuine, disclosed governance finding, out of this Work Package's
own scope to fully fix**: while updating the Academy Register's own
"Last Reviewed" field, a direct row-count of its `## 03 Work Packages`
table (72 `| WP...` rows) against the real, on-disk file count (84,
including this Work Package's own two new files) found eleven real,
already-shipped retrospective files (`WP9.3A` through `WP10.2A`, plus
both `WP9.9.0` passes) each named exactly once in that field's own
historical narrative, but never actually added as their own table row
— the identical class of gap `WP 9.8B` was commissioned specifically
to close for the Platform Services Register/Map, found here instead in
a sibling register. This Work Package's own row was added; backfilling
the other eleven is named as a candidate for a future dedicated
governance Work Package (reinforcing `FCR-0005`, Governance Register
Health-Check Tooling), not attempted mid-implementation here.

**Saved layouts, restore-on-startup, and persistent visibility/
splitter positions were already fully real since `WP 8.1A`** — a
direct re-read before writing any code confirmed this rather than
assuming it, avoiding both wasted reimplementation and a false "newly
added" claim in the Implementation Report.

**`WorkspaceDockPosition.Bottom` sat unused for four Work Packages**
(`WP 10.0B` through `WP 10.2A`) before this Work Package finally wired
it — a real, disclosed example of a contract member specified ahead
of its first real consumer, resolved cleanly once a genuine need
(the Output panel) arrived, with zero contract change required to
support it.
