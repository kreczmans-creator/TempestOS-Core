# WP 15.0C — Desktop Productisation Phase 2

## 1. Introduction

`WP 15.0C` covers three parallel, worktree-isolated work packages —
`64b0c16` (Ribbon/Property Inspector button hierarchy), `cbde521` (dialog
framework and Command Palette keyboard workflow), `0ba55cb` (`Declared
CapabilityView` icon fix, `DocumentAreaView` tab-close context loss) —
merged sequentially via `ecb1034`, `0f7b7e9`, `2f7baf2`, plus the
supporting `cab540b` (`.gitignore` for `.claude/` worktree state).
Retroactively numbered and retrospected by `WP 15.1A`.

## 2. Purpose

Continue `WP 15.0B`'s UX closure, this time genuinely parallelisable:
three independent problem areas with no shared-file overlap, dispatched
as three background agents in isolated git worktrees.

## 3. Background

`cab540b` was committed first, ahead of the parallel dispatch, so the
Agent tool's per-agent worktree state (`.claude/worktrees/agent-*`) would
not appear as untracked files in the lead session and would not be
captured by any of the three agents' own commits.

## 4. The Problem

- **`64b0c16`** — Ribbon and Property Inspector "Create"-class buttons
  used the same visual weight as secondary actions; the Name field gave
  no affordance explaining *why* it was read-only for non-renamable
  Kinds.
- **`cbde521`** — dialog framework and Command Palette keyboard workflow
  gaps: `Escape`/focus handling, severity-row validation display, a
  `TextChanged`-vs-`PropertyChanged` binding defect, missing
  scroll-into-view behaviour.
- **`0ba55cb`** — `DeclaredCapabilityView`'s icon did not resolve for
  some discipline areas; `DocumentAreaView` lost tab context on close
  (closing a tab could leave the wrong document, or none, focused).

## 5. The Design

`64b0c16`: Create-group buttons moved to `ChromeStyles.Primary`; a
tooltip added to the Name field for non-renamable Kinds, read from the
same eligibility data the command layer already enforces (no new source
of truth). `cbde521`: `Escape` and focus handling corrected per dialog;
severity rows reuse `ObjectEditorView.BuildSeverityRow`
(`InternalsVisibleTo`-shared) rather than a second implementation;
`TextChanged` wiring corrected to `PropertyChanged`; scroll-into-view
added where a validation row could otherwise land off-screen. `0ba55cb`:
`IconRegistry.Resolve` corrected for the affected Kinds; `DocumentAreaView`
tracks the correct successor tab explicitly on close instead of relying
on the docking framework's own default focus behaviour.

## 6. Alternatives Considered

A fourth, combined worktree instead of three independent ones — rejected:
the three problem areas (Ribbon/Inspector, dialogs/palette, two
unrelated view-level bugs) share no files, so combining them would have
serialised work with no coordination benefit.

## 7. Why This Solution Was Chosen

Genuine file-level independence, confirmed before dispatch (unlike
`WP 15.0B`'s tightly-coupled scope), makes parallel, isolated-worktree
execution safe: each agent's own diff was reviewed and merged
sequentially by the lead session, never merged by an agent itself.

## 8. Architectural Principles

`cbde521`'s reuse of `ObjectEditorView.BuildSeverityRow` follows this
project's own "the exception that stayed a reasonable extension of the
existing pattern" discipline (`InternalsVisibleTo("Tempest.Desktop.
Tests")`) rather than adding a second severity-rendering implementation.

## 9. Benefits

Consistent button hierarchy signalling primary actions; dialog and
Command Palette keyboard workflows behave correctly; two real,
independently-found view-level defects closed.

## 10. Trade-offs

**Same test-count caveat as `WP 15.0B`, narrower here.** `64b0c16`'s own
commit message records only "Tests:" without a pass/fail figure;
`cbde521`/`0ba55cb` record new tests added (`DialogFrameworkKeyboardTests.
cs`; `DocumentAreaTabSelectionTests.cs`, 4 tests) without a full-suite
figure either. None of the three claims a specific pass count this
retrospective repeats as fact — the current, verified baseline (408/408
Desktop, 3088/3088 Core) is the authoritative figure; see `WP 15.1A`'s own
Release Preparation Report.

## 11. Common Mistakes

**Relying on a docking framework's default focus behaviour for tab-close
succession.** `DocumentAreaView`'s defect was exactly this: the framework
picks *a* tab, not necessarily the *right* one, and the view must track
intent explicitly when it matters.

## 12. Future Evolution

Retrospective written after the fact by `WP 15.1A`. No Stage 1 audit
report is preserved for any of the three commits; this account is derived
from commit messages and diffs only.

## 13. Key Takeaways

- Confirm genuine file-level independence *before* parallelising —
  `WP 15.0B`'s own coupled scope and this Work Package's genuinely
  independent one are the same programme's two different answers to the
  same question.
- An agent's own worktree diff is reviewed and merged by the lead
  session; an agent never merges itself.
- Reuse an existing internal helper across views (via
  `InternalsVisibleTo`) rather than duplicating rendering logic for the
  same concept.
