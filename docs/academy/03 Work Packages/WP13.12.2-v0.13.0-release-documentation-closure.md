# WP 13.12.2 — v0.13.0 Release Documentation Closure

## 1. Introduction

`WP 13.12.2` closed the documentation and governance items `WP 13.12.1`'s
readiness re-execution enumerated: the missing `WP 13.12.x` records, the
superseding Engineering Release Report, the Release Notes, and eight
named documentation-drift findings. It changed **zero** `src/` and
`tests/` files, bumped no `VERSION`, and created no ADR and no governance
exemption.

## 2. Purpose

To leave `v0.13.0` with a complete, accurate, self-consistent
documentation record, so that the only remaining barrier to release is
the structural one — CI on `main` — rather than any documentation gap.

## 3. Background

`WP 13.12.1` returned **NOT READY** for both committed `HEAD` and the
working tree. The working tree cleared the Academy blocker; one Release
Blocking finding remained (CI never run on `main` at the pre-tag commit),
alongside nineteen Disclosed/Non-Blocking and six Pre-Existing findings.

## 4. The Problem

The finding set mixed three genuinely different kinds of work: artefacts
that did not exist (Release Notes, superseding report, `WP 13.12.x`
records); documentation that was factually wrong (`ADR-0110`'s
Consequences bullet, `Plugin Platform Architecture.md`'s "Unchanged"
claims, `PROJECT_STATUS.md`'s four stale dashboard fields); and
pre-existing debt that must **not** be quietly tidied away
(`Feature Register.md`/`Traceability Matrix.md` staleness, the Academy
Register's row deficit, `TD-42`/`TD-43`/`TD-45`).

Treating all three the same way would either leave the record wrong or
erase the history of how it got that way.

## 5. The Design

**Read-only evidence agents first, central integration only.** Four
parallel read-only agents gathered exact current text and line numbers
for the corrections; no agent edited anything. Every edit was applied
centrally, so no two writers ever touched the same file.

**Correction by annotation, not replacement.** Wrong claims were struck
through and annotated with what is actually true and who corrected it,
never deleted — the retention convention this repository already applies
to superseded status blocks.

**Explicit non-correction where correction would destroy evidence.** The
roadmap-predicted table (`DNB-16`) was left as it stands, with a note
recording precisely how its freeze was broken, because editing it further
would complete the destruction of whatever snapshot value remains.

**Test resource discipline.** No broad parallel test execution was
introduced. The existing serialisation strategy was preserved, and
`TD-34`'s account was *improved* rather than weakened: `WP 13.12.1`
surfaced a second unguarded collider (`LoggerTests.cs`, `Console.SetError`)
that the register did not name.

## 6. Alternatives Considered

**Rewrite the wrong claims in place.** Rejected — it would have hidden
that the record was ever wrong, which is the failure mode that let the
Academy gap persist for three Work Packages.

**Close the pre-existing debt while in the files anyway.** Rejected by
the commissioning instruction and on principle: silently cleaning
unrelated historical debt makes a release's own footprint unmeasurable.

**Skip retrospectives for `WP 13.12.1`/`WP 13.12.2`.** Rejected —
Engineering Governance §6 applies to every Work Package, and adding their
`WorkPackages.md` rows without retrospectives would have re-opened
exactly the finding `WP 13.12.0` had just closed.

## 7. Why This Solution Was Chosen

Because the remaining barrier to release should be a real one. Every item
closed here was a documentation defect with a determinate correct answer;
leaving any of them would have meant a release whose own record
contradicted its code.

## 8. Architectural Principles

- **Annotate, don't overwrite.** A corrected record shows the correction.
- **Disclose deliberate non-action.** Untouched debt is named, not
  omitted.
- **One owner per file.** Evidence gathering parallel and read-only;
  integration central and serial.
- **A documentation Work Package touches no code.**
- **Preserve test serialisation.** Concurrency is a correctness property
  of this suite, not a speed knob.

## 9. Benefits

`v0.13.0` gained its Release Notes and an Engineering Release Report that
supersedes `WP 13.9.0`'s stale **NOT READY** as the authoritative
readiness record. `ADR-0110` and `Plugin Platform Architecture.md` no
longer assert that Module Discovery, Registration, and Lifecycle are
unchanged — a claim false since `WP 13.9.6`. The Ownership Matrix, silent
since `WP 5.2`, records all seven `v0.13.0` Host-owned components with
their single construction sites. `PROJECT_STATUS.md`'s four stale
dashboard fields are corrected. `TD-34` names both unguarded colliders
rather than one.

## 10. Trade-offs

The corrections add bulk to already-long documents: several now carry
strikethrough originals alongside their replacements. That is the price
of an auditable record, and it is the convention already in force.

`DNB-16` is annotated rather than fixed, so the roadmap-predicted table
remains internally inconsistent by design. The note explains why; a
future reader who disagrees has everything needed to decide otherwise.

## 11. Common Mistakes

- **Assuming a substitution applied.** Three of the wording-collision
  fixes silently failed because the target text was line-wrapped and the
  pattern was single-line. Verification after each edit — not before —
  caught them.
- **Correcting only where the search looked.** `WP 13.12.0`'s
  wording-collision pass deliberately excluded `docs/academy/03`, leaving
  three live uses of the colliding term in the very retrospectives it had
  just written. `WP 13.12.1` found them.
- **Editing a frozen artefact to make it consistent.** Five of six rows
  in the roadmap-predicted table had already been edited after
  branch-cut, which is what broke it; a sixth edit would not have fixed
  it.

## 12. Future Evolution

The remaining Release Blocking finding is structural: `Build & Test` and
`CI Gate` have never run on `main` at the pre-tag commit
(`Engineering Readiness Review Architecture.md` §2.3). Clearing it
requires `VERSION` → `0.13.0`, push, PR, green CI, and merge — none of
which is available on a feature branch, and all of which sit behind
explicit per-occasion Product Approval.

Pre-existing debt deliberately preserved: `Feature Register.md` and
`Traceability Matrix.md` (stale since `WP 5.3`); the Academy Register's
row deficit; `TD-42`, `TD-43`, `TD-45`; and the `v0.9.0`/`v0.10.0`
health-check warning.

## 13. Key Takeaways

- A correction that hides the error is not a correction.
- Search scope is part of a fix; excluding a directory excludes the bug.
- Verify each edit landed — line wrapping defeats confident patterns.
- Knowing which debt *not* to touch is as much a part of a closure Work
  Package as knowing which to close.
