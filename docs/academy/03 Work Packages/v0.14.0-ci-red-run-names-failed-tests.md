# CI — Make a Red Run Name the Tests That Failed

## 1. Introduction

`416f2c8` made the CI pipeline's "Publish build & test summary" step
collect and print the name and error message of every failed test, in the
job log and the step summary, so a red run stops meaning only "something
failed". A pre-`v0.14.0` engineering-body-of-work row.

## 2. Purpose

To make a failing `dotnet test` run diagnosable from CI output alone,
without downloading an artefact that the account-level storage quota was
already refusing to store.

## 3. Background

Run `33243303228` got `Tempest.Desktop.Tests` to 260/260 on the Windows
runner — the vocabulary-scan fix (`TD-93`) held — and the Test step still
exited 1, because `dotnet test` runs both assemblies in the solution and
`Tempest.Core.Tests` failed. Which of its 2,569 tests failed was not
answerable from CI: VSTest prints one summary per assembly, and the
`Tempest.Core.Tests` summary was buried several minutes into a 209 KB log
dominated by Desktop host logging, with the `.trx` that would say so
plainly undownloadable because artefact upload was itself being refused
for the same account-level storage quota that `7b53ce6` had already
disclosed.

## 4. The Problem

A red run reported "something failed" and nothing more, so diagnosing it
required either a local reproduction or a long manual search through a
dominated-by-noise log.

## 5. The Design

The existing "Publish build & test summary" step already parsed every
`.trx` for its counters; it now also collects the Failed results and
writes each one's test name and error message to both the job log
(between clear `--- Failed tests (<config>) ---` markers, reachable from
the tail of the log) and the step summary. Diagnostic output only: the
Test step remains the gate, its exit code is untouched, and this step
keeps its existing `if: always()`.

## 6. Alternatives Considered

Fixing the underlying artefact-storage-quota refusal so `.trx` files
could simply be downloaded — outside this row's scope, since the quota is
an account-level limit recalculated on GitHub's own cycle and not this
repository's to fix.

## 7. Why This Solution Was Chosen

Because the information already existed in every `.trx` the pipeline
already parsed for its counters — surfacing the failed-test detail cost
no new artefact, no new step, and no dependency on the artefact-upload
path that was already unreliable.

## 8. Architectural Principles

A CI gate should not require its own log to be manually excavated to say
what it found; the summary step's job is to make the pipeline's own
already-collected data legible, not merely to count it.

## 9. Benefits

Verified locally against two real `.trx` files produced by the full
solution run, executed with the same PowerShell 7 the runner uses: it
names both `Tempest.Core.Tests` failures with their assertion messages and
renders the counter table unchanged.

## 10. Trade-offs

Still dependent on the `.trx` files being produced at all; if a run fails
before tests execute (a build error, for instance), there is nothing new
to name — this row addresses only the "tests ran and some failed"
diagnosability gap, not every possible red-run cause.

## 11. Common Mistakes

Treating a CI counter summary ("X passed, Y failed") as sufficient
diagnostic output — it answers "did it fail" but not "which test, and
why", which is the question anyone investigating a red run actually asks
first.

## 12. Future Evolution

This is the direct diagnosability improvement the investigation inside
`7b53ce6` (the immediately preceding CI fix) had to work around by hand;
`f2600d9`'s vocabulary-check fix and this commit together closed the two
things standing between "the branch is red" and "here is exactly why".

## 13. Key Takeaways

- Surface data a pipeline already collects rather than requiring a
  contributor to re-derive it from a raw log.
- A diagnostic-only change should leave the actual gate (the step's exit
  code) untouched — this step still only reports, never decides.
- Verify a CI-output change against real artefacts from the same tool
  version the runner uses, not a hand-written approximation.
