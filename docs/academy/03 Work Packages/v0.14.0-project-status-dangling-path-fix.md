# PROJECT_STATUS.md Dangling-Path Fix

## 1. Introduction

`e57f1aa` fixed a stale path `TD-75` phase 2 left in `PROJECT_STATUS.md`,
caught by the Governance Health Check in CI run 74 on the author's own
commit. A pre-`v0.14.0` engineering-body-of-work row; documentation-only.

## 2. Purpose

To bring `PROJECT_STATUS.md`'s `WP 8.1B` narrative back into agreement
with where the code it describes actually lives, after `TD-75` phase 2
moved it.

## 3. Background

`PROJECT_STATUS.md` still named `src/Tempest.App/Workspace/Samples/` in
its `WP 8.1B` narrative; phase 2 had moved that directory into the test
project. This is the second stale pointer that move produced — the
Academy guide (`41a171a`) was the first, found by the same category of
check the health check now caught here.

## 4. The Problem

Build and Test passed in both configurations; the Governance Health Check
was the only failure, and it was doing exactly its job — catching a
reference to a path that no longer existed.

## 5. The Design

The narrative is history and stays true, so the fix keeps the file count
and names the namespace those four files were added to, then states where
they went and why. The live path it now cites is the one that exists.

## 6. Alternatives Considered

None recorded beyond the direct correction — there was one wrong path and
one correct replacement.

## 7. Why This Solution Was Chosen

Because the narrative's historical claim (what `WP 8.1B` added, and how
many files) remains true; only the live-location pointer needed
correcting, the same principle `41a171a` applied to the Academy guide.

## 8. Architectural Principles

A governance check that catches a dangling path is doing its job even
when — especially when — the person who introduced the gap is the same
person running the check; the check's value is in not depending on
anyone remembering.

## 9. Benefits

The Governance Health Check passes; `PROJECT_STATUS.md` names a path that
actually exists.

## 10. Trade-offs

None recorded — this is a direct, narrowly-scoped documentation
correction with no disclosed limitation.

## 11. Common Mistakes

Moving code and updating one reference to its old location while missing
a second — the same move (`TD-75` phase 2) produced this stale pointer and
the Academy guide's, both found only by something that checks rather than
by re-reading the affected files by hand.

## 12. Future Evolution

No further pointers to the moved code were found stale after this
commit; the pattern (a move leaving more than one stale reference) is
worth checking for on any future large code relocation in this
repository.

## 13. Key Takeaways

- The governance health check finding a defect in its own author's recent
  commit is the check working as intended, not an embarrassment to route
  around.
- A single code move can leave more than one documentation reference
  stale; search broadly rather than fixing only the first one found.
- Both stale pointers from this move (here and in the Academy guide) were
  caught by automated checking, not by manual review — the argument for
  having the checks at all.
