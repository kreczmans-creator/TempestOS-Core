# WP 13.0.0A — Release Register Reconciliation

## What This Document Is

The retrospective for `WP 13.0.0A`, a narrowly-scoped governance
correction closing the one real finding `WP 13.0.0` (`v0.13.0` Branch
Establishment) disclosed rather than fixed: `docs/governance/Delivery/Release
Register.md` had no row for the `v0.12.0` tag. On `feature/v0.13.0`,
per this project's own established convention that a governance-tool
finding surfaced on a branch, even one unrelated to that branch's own
substantive scope, gets disclosed immediately and closed at the next
opportunity — mirroring exactly how `WP 12.9.1` closed findings
`WP 12.9.0` had disclosed, and `WP 12.9.3B` closed a finding `WP 12.9.2`
had disclosed.

## Root Cause

`Release Register.md`'s own "Last Reviewed" history shows every prior
release's own tag added in a dedicated reconciliation pass (`WP 11.4B`
for `v0.11.0`, `WP 10.9A` for `v0.7.0`–`v0.10.0` together). No `v0.12.0`
Work Package performed the equivalent pass — the closest candidates
(`WP 12.9.0`, `WP 12.9.2`, `WP 12.9.4`, the three real Engineering
Readiness Review executions) each reviewed `governance-healthcheck.ps1`
output directly, but the tag itself did not exist until `WP 12.9.4`'s
own release-completion action, by which point no further `v0.12.0` Work
Package remained to add the resulting row. Confirmed directly, not
assumed: `git show 13a6ce3:"docs/governance/Delivery/Release
Register.md"` — the exact commit the `v0.12.0` tag points to — already
lacks the row, proving the gap is structural (no Work Package's own
scope ever included it) rather than a regression any later commit
introduced.

## What Changed

Added the `v0.12.0` row to `Release Register.md`'s own Entries table,
matching the established density and evidence convention of every
other row (tag object SHA, resolved commit, GitHub Release link,
deliverables list, scope summary, final verdict, test counts) —
independently re-derived from git and this release's own Engineering
Release Reports, not copied from any single prior document. Total
corrected 11 → 12 versions referenced (10 → 11 confirmed released).

**Independently re-verified, all eleven real tags, not carried
forward:** `git tag -l "v*"` cross-checked against the Entries table
row by row; each tag's own resolved commit and date re-derived via
`git rev-list -n1`/`git log -1` directly, not read from the register's
own prior text. `v0.1.0` (cited by commit, no tag) and `v0.2.0`
(genuinely Unknown) reconfirmed as the same two disclosed non-tag
exceptions this register has always carried — neither re-investigated
this pass; their own status was not this Work Package's subject.

## Verification

`governance-healthcheck.ps1`, re-run on `feature/v0.13.0`: **7 passed,
1 warned, 0 failed, exit code 0** — Release Register now `[PASS]` (10
tags, 12 register versions). The one remaining `[WARN]` is the same
pre-existing, already-accepted `v0.9.0`/`v0.10.0` `WorkPackages.md`
exception every review in this project has carried since `WP 11.2A`.
No other check regressed; confirmed directly, not assumed.

## Scope Confirmation

Governance/documentation only. Zero `src/`/`tests/` files touched;
zero architecture, implementation, or release behaviour changed —
confirmed directly (`git diff --stat` for this commit touches only
`docs/governance/Delivery/Release Register.md`, this document, and the
usual closing-action documents `WorkPackages.md`/`PROJECT_STATUS.md`).
No ADR required — correcting a register to match reality that already
exists is not a new either/or architectural choice, Engineering
Governance §5's own ADR-creation criteria not met.
