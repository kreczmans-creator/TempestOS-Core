# `WP 10.6A` — Command Execution & Productivity Experience

## 1. Introduction

`v0.10.0`'s own twelfth Work Package — the professional engineering
workflow layer sitting on top of `Tempest.Desktop`'s own existing UI:
a real Undo/Redo architecture, a Background Task Framework, Command
History, Recent/Favourite Objects, a User Command Macro foundation, and
an External Controller/Input Binding abstraction — while changing zero
Command Framework or frozen Workspace-contract behaviour.

## 2. Purpose

Implementation retrospective, mirroring `WP10.5B`'s own two-part
(Concept Guide, Implementation Retrospective) structure. See
`30-command-execution-and-productivity-experience.md` for the design
narrative; this file focuses on what was built, files touched, tests,
and honest disclosure of this Work Package's own scope boundaries.

## 3. Background

Commissioned directly after `WP 10.5B` (Desktop Workflow & Professional
Interaction) closed. This Work Package's own controlling instruction
named a broad, explicit scope — complete command execution experience,
progress reporting, a background task framework, Undo/Redo, keyboard
productivity, command history, recent objects, favourite objects, user
command macros ("foundation"), and an external controller integration
abstraction — with an explicit "important scope addition": build the
Macro & Controller Abstraction (`ICommandMacro`/`IMacroManager`/
`IInputBindingProvider`/`IExternalControllerProvider`) without
integrating any real vendor SDK (no Stream Deck, no Loupedeck, no MIDI
device, no hardware integration).

## 4. The Problem

See `30-command-execution-and-productivity-experience.md` §4 — before
this Work Package, no Undo/Redo existed anywhere in this platform;
`EngineeringCockpit.FavouriteProjects` was explicitly disclosed as
always empty; a repository-wide `grep` for `createDefault:` confirmed
only `Tempest.Samples` commands were ever Id-invokable; no background
task tracking existed; `KeyboardShortcuts` bound exactly five fixed
actions with no generic binding mechanism.

## 5. The Design

See `30-command-execution-and-productivity-experience.md` §5. In
summary: `UndoableAction`/`IUndoRedoStack` (new, `Tempest.App.Workspace`)
realise Undo/Redo as a Desktop/App-layer delegate stack (`ADR-0098`),
wired real for Rename (all six disciplines, via `ObjectEditorView`'s
own shared commit path) and the new Favourite toggle. `ICommandMacro`/
`IMacroManager`/`RunMacroCommand` (new, `Tempest.Core.Macros`) realise a
Macro as a registered Command (`ADR-0099`), with `MacroManagerDialog`
(new) as its own minimal, real authoring/browsing UI.
`IInputBindingProvider`/`IExternalControllerProvider`/
`IInputBindingRegistry`/`InputBindingRouter` (new, `Tempest.Core.Input`)
realise the External Controller abstraction (`ADR-0100`), with
`KeyboardCommandBindingProvider` (new, `Tempest.Desktop.Input`) as the
one real implementation and `StubExternalControllerProvider` (test-only)
proving the abstraction against a device-shaped provider.
`CommandHistoryLog`/`RecentObjectsState`/`FavouriteObjectsState`/
`IBackgroundTaskRunner` (all new, Desktop-local) complete the set,
surfaced via two new `ProjectExplorerView` sections and two new
`OutputPanelView` sections — no new dock panel.

## 7. Compatibility Verification

Zero changes to `Tempest.Core.Commands` — `ICommand`/`ICommandDispatcher`/
`ICommandRegistry`/`CommandDescriptor`/`ICommandHandler<T>` all
unmodified, confirmed by direct diff. Zero changes to any of the twelve
frozen `WP8.0B` Workspace contracts. `IWorkspaceManager.RenameObjectAsync`
(`ADR-0096`) is called, never modified. `ICommandRegistry.RegisterDescriptor`/
`InvokeAsync`/`Items` are called exactly as already designed by
`MacroManager` — no new registry method needed. Every new Platform
Service (`IMacroManager`, `IInputBindingRegistry`) is registered via the
identical `services.Singleton<TInterface, TImpl>()` pattern every
existing Platform Service already uses.

## 8. Disclosed Scope Reductions — Named Directly, Not Hidden

- **Undo/Redo covers Rename (all six disciplines) and Favourite toggle
  only.** Create/Delete/Duplicate/Move/Status changes remain
  un-undoable; Delete specifically has no defined inverse (already a
  soft delete). `AT-18`/`FCR-0078`.
- **Background Task progress is coarse state only, never a percentage.**
  No `ICommandHandler<TCommand>` anywhere in this platform carries an
  `IProgress<T>` parameter. `AT-19`/`FCR-0079`.
- **Macro steps are limited to `CreateDefault`-eligible commands** —
  confirmed by `grep`, only `Tempest.Samples` commands qualify today; no
  real discipline command is Id-invokable yet, a pre-existing,
  platform-wide limitation this Work Package did not introduce.
  `AT-20`/`FCR-0080`.
- **Command History records only what reaches existing `ActionCompleted`
  UI surfaces**, with a disclosed "contains 'fail'" heuristic for
  `succeeded` (these surfaces carry a string, not a structured
  `CommandResult`) — never a global `ICommandDispatcher` interception.
  `AT-21`/`FCR-0081`.
- **Undo/Redo and Command History are both session-only** — neither
  persists across a restart. `AT-22`/`FCR-0082`.
- **`KeyboardCommandBindingProvider` ships with zero default bindings
  and no remapping UI; no real external controller vendor integration
  exists** — only a real Keyboard provider and a test-only
  `StubExternalControllerProvider`, matching this Work Package's own
  explicit Out-of-Scope. `AT-23`/`FCR-0083`.

## 10. Summary

A real, working, tested professional workflow layer now sits over the
existing Command Framework and Ribbon/Palette/Explorer UI: Undo/Redo
proven end-to-end for Rename across all six disciplines from one shared
call site; a Macro foundation that reuses the Command Framework's own
existing invocation path with zero special-casing; an External
Controller abstraction proven against a real Keyboard provider and a
device-shaped test double, with zero vendor SDK dependency; Command
History, Recent Objects, Favourites, and a Background Task Framework
completing the set. Every named scope reduction is disclosed directly —
six new Future Capability entries, six new Accepted Trade-offs — never
silently narrowed.
