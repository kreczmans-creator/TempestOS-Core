# CI — Close the Build Errors and Governance-Index Gaps That Made the Branch Red

## 1. Introduction

`7b53ce6` fixed the three build errors and two governance-index gaps a
real failing CI run (`33240113523`) reported, confirmed against that run
rather than inferred — the only CI change this release makes to
`.github/workflows/ci.yml`. A pre-`v0.14.0` engineering-body-of-work row.

## 2. Purpose

To get the branch's build, test and governance-health-check gates green
again after several commits of feature work had accumulated failures
nobody had confirmed against a real run.

## 3. Background

Several feature commits had landed in sequence — the Product Spine,
durable object rehydration, project-centric convergence, the data-driven
workspace layout — without anyone confirming the branch still built and
governed cleanly after each one. `Academy articles 32-36` (documenting
that same sequence of work) had accumulated without index links, and
`PROJECT_STATUS.md` had picked up reference paths the governance checker
could not resolve.

## 4. The Problem

Under `TreatWarningsAsErrors`, two build errors and one analyzer warning
were fatal: `MainWindow.cs` had two `CS8602` nullable-dereference warnings
from a macro-runner lambda constructed before the fields it captures were
assigned (only ever invoked after construction completes, but the analyzer
cannot see that); `WorkspaceLayoutTreeTests.cs` used the flagged
`Assert.Single(x.Where(p))` form instead of `xUnit2031`'s prescribed
`Assert.Single(x, p)`. The Governance Health Check failed three of eight
checks: Academy articles 32–36 were orphaned from `Academy Index.md`
(article 36 postdated the original defect list, since it predates
`TD-72`); three `PROJECT_STATUS.md` references used a bare
`02 Runtime Architecture/NN-....md` shorthand the checker resolves from
the repository root, where it does not exist; and two governance reports
were orphaned from `Governance Index.md`.

## 5. The Design

The two `CS8602` sites are annotated with `!` exactly where the same
field-closure lazy-capture pattern already used fifty lines below
(`WP 12.4B`, `ADR-0104`) — nothing relaxed project-wide, the solution
still builds clean at zero warnings in both configurations. The xUnit
assertion is rewritten to the analyzer's own prescribed form with the
assertion unchanged. The Academy section gains links for all five
articles; the three `PROJECT_STATUS.md` references are qualified with the
`docs/academy/` prefix every other reference in the file already uses; the
two governance reports are linked from the Quality section with a line
naming each.

Two further defects were found by running the whole suite, which CI had
not reached since an earlier commit because the build failed first: an
intermittent acceptance test whose premise ("everything present in the
second lifetime arrived through rehydration") was false — the sample
graph re-seeds with fresh identities each lifetime, so the test picked
whichever record happened to come back first — fixed by recording the
first lifetime's ids and examining only those; and the four artefact
upload steps were made `continue-on-error` after a run failed on an
account-level storage-quota limit outside the repository's control, with
Build, Test and the Governance Health Check left as hard gates.

## 6. Alternatives Considered

None recorded beyond the fixes themselves — each defect had one direct
correction (the existing nullable-annotation convention, the analyzer's
own prescribed form, or an `Academy Index.md`/reference-path correction).

## 7. Why This Solution Was Chosen

Because every fix here follows directly from a real, cited CI run rather
than a guess at what might be wrong — the commit names the run number and
the exact failing checks throughout.

## 8. Architectural Principles

A CI gate is only as good as the discipline of checking it after every
change, and a "temporary" workaround for an infrastructure limit
(artefact quota) should be scoped narrowly (upload steps only) rather
than relaxed on the gates that actually verify correctness.

## 9. Benefits

Local validation before the fix: build fails with three errors, health
check fails three of eight checks. After: both build configurations clean
at zero warnings, full unfiltered suite green except the same two
pre-existing Linux-environment cases, governance health check exits 0.

## 10. Trade-offs

The account-level artefact-storage-quota workaround (`continue-on-error`
on upload steps) does not fix the underlying quota problem, which is
outside this repository's control and recalculated on GitHub's own cycle
— disclosed rather than presented as a real fix.

## 11. Common Mistakes

Accumulating feature commits without confirming CI stays green after
each one, so failures compound across several changes before anyone
looks. Adding an Academy article without linking it in the same commit —
the exact orphan pattern the governance check exists to catch, and which
recurred here across five articles at once.

## 12. Future Evolution

`416f2c8`, shortly after, extends the same CI workflow to name which
tests failed on a red run, addressing the exact diagnosability gap this
row's own investigation ran into when tracing the intermittent test.
`WP 16.1A`, later in the v0.16.0 release, makes the Governance Health
Check itself a required CI gate rather than a check a contributor must
remember to run locally — closing the class of drift this row's own
orphan-detection failures exemplify.

## 13. Key Takeaways

- Confirm a fix against the real failing CI run, cited by number, rather
  than inferring the cause from reading the diff.
- An Academy article and its index link belong in the same commit; the
  orphan check is the structural enforcement of that rule.
- Distinguish an infrastructure limitation (artefact storage quota) from
  a correctness gate, and disclose the workaround as a workaround.
