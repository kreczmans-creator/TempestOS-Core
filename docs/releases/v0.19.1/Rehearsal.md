# WP 19.10A — Dress rehearsal of `PHYSICAL_REVIEW.md` §7c on the candidate

Walked D1–D19 in the headless test host (`tests/Tempest.Desktop.Tests/Rehearsal/PhysicalReviewRehearsalTests.cs`, one long `[AvaloniaFact]`), one persistence root for the whole walk, driven through `MainWindow`/`ShellNavigator`/the real dialogs exactly as `QuotationJourneyTests` and `RailSurfaceContractTests` already do. Candidate head `232291ca`. Every visible text §7c names was checked verbatim against what the host actually rendered; every "opens right up" was checked by the document area's own tab count increasing, not by a view's own `RefreshAsync` being called by hand.

Two data-integrity notes that bound how to read this table:

- **The headless host is not a genuinely empty first run.** `Tempest.Samples`, wired into every Desktop test including this one, registers two sample projects (`SAMPLE-PROJ-001` "Sample Project", `MECH-PROJ-001` "Falcon Structural Assembly Project") at start-up — the real shipped `Tempest.Desktop.exe` never does this (§3: "There is no demo or sample data"). This makes three of D1's claims (the project-status chart's "0 open project(s)", the right rail's "No projects yet." / "Nothing has changed yet.") unverifiable as their genuinely-empty forms in this harness; they are marked **Not verified (harness)** below rather than Matches or Differs. Everything else on D1 — the five task tiles, the Commercial snapshot's Quotes line, the Invoices line, Upcoming milestones, the Task list, Recent (session activity, not seeded), Favourite, and the header search — is unaffected by this and was checked for real.
- **Two Add-1/Quote-your-own-service checks corrected two false readings, not the product.** A first pass wrongly flagged D10 (a `DateOnly.ToString()` culture-format mismatch against the refusal's own `:O` format — the real text already names both the completion id and its date) and part of D15 (a `Contains("Calculations")` search that matched the unrelated "Engineering Calculations" tree-node label rather than any content of the Tasks page). Both are corrected in the table below from the actual captured strings, and D13 needed one genuine fix, not a false-positive correction: `QuotesView` scopes to the single currently-open project when one is open (confirmed by reading `QuotesView.RefreshAsync`'s own doc comment and code) — the walk had left a project open from D10–D12, so a second quote under a different project was invisible until the open project was closed first, exactly as a reviewer browsing Business → Quotes with nothing open would already be.

## Blockers

- **D6 — "Open deliverable" does not open right up.** The button renders, is enabled, and its click handler is structurally identical to the working "Open requirement" button one row over, but clicking it never opens a document tab. Reproduced on two independent full runs of this walk, with an explicit wait for the button's own presence added between runs to rule out a render-timing gap. No exception is visible anywhere the test can see it (the click delegate is fire-and-forget off a UI event). This is the one place in the whole walk where a documented "opens right up" claim did not hold; every other "opens right up" in D1–D19 (New Project, Open requirement, Add Deliverable, Create Calculation, New task, Record, Home's own Open) worked every time it was tried.

## Differences

- **D1 — the Commercial snapshot's Quotes line has no £ sign.** `Money.ToString()` renders `"0.00 GBP"`; the document's own quoted text is `"Quotes: 0 open, £0.00 total value."` Whichever is wrong, they disagree.
- **D1 — the Invoices line is mis-punctuated and mis-cased.** `AccountsReadModel.ReadAsync` already returns `UnavailableReason = "No accounts reading yet."` (capital N, its own trailing period) before any accounts reading has ever been attempted; `HomeDashboardView.RenderCommercial` appends a second literal `"."` after it regardless, producing `"Invoices: unavailable — No accounts reading yet.."` — capitalised, and a doubled period. The `?? "no accounts reading yet"` fallback in that same line is dead code: `UnavailableReason` is never actually null.
- **D15 — an empty reference library shows no heading at all**, not "eight libraries, one with zero records" as the document's own "Counts as a failure" column implies ("a library missing" is explicitly named as a failure). `LibrariesView.RefreshAsync` groups only the records that exist and never emits a group for zero. On this run that hid Manufacturing and Components; on the real app's own genuinely fresh install it would also hide Rate Cards (this walk's own setup happened to register one).
- **D15 — the eighth library's own name is "BusinessRateCards", not "Rate Cards".** Every grouping and switch case in `LibrariesView.cs`/`ReferenceRecordView.cs` uses the literal string `"BusinessRateCards"`.

## Disclosed

Matches to the six known limits `docs/releases/v0.19.1/Release Notes.md` (Warnings) already names, as this candidate actually shows them:

- **Business → Invoices groups by status, not the sketch.** D11 confirmed the documented Draft/Sending/Sent/Accepted/Rejected/Unknown/Reauthorise/Voided order, with no "Available to invoice" group — §7c's own D11 text already describes this corrected grouping, so this walk shows it as a plain Match, not a new finding.
- **Header search does not carry typed text into the palette.** D1 confirmed the header's own search control is a `Button`, not a text field — there is nothing to carry. `CommandPaletteOverlay.Open()` explicitly clears its own query box.
- **Engineering → Tasks has no Calculations heading.** D15 confirmed it — only Reviews and Approvals render, both correctly empty.
- **The Finance bucket's 30/7-day heuristic.** Not separately exercised (nothing in this walk aged that far), but no lying zero or invented term was seen anywhere Finance was checked (D1, D14).
- **Archived-project write guards stop at the five Core services.** D19 exercised and confirmed all five guarded services (commercial, quotation, deliverable, timesheet, invoicing) refuse correctly; the milestone/engineering-task, evidence, requirements and task services' own lack of a guard was confirmed by source reading during preparation, not independently re-attempted live in this run (no shell surface offers those writes on an archived project, matching the disclosure).
- **Accounts reads are not proven live.** No live Xero/QuickBooks authorisation exists in this environment; D13/D17 both showed the honest "unavailable"/"Subscriptions unavailable" wording with no fabricated reading, exactly as disclosed.
