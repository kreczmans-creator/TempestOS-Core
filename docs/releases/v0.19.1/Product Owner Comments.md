# TempestOS v0.19.1 — Product Owner comments on the v0.19.0 candidate

The eight comments the Product Owner raised on 2026-09-14 while testing the `v0.19.0` candidate `947c50d`, transcribed by the lead as they arrived, including the nine information-architecture sketches. This is the source of record for what `v0.19.1` builds; `Execution Plan.md` turns it into Work Packages.


1. **Project → Structure tab: the engineering surface sits over other things.** Screenshot: opening a project's Structure tab renders the engineering workspace (menu bar View/Document/Theme/Commands/Help, ribbon with Calculations…Verification categories, Project Explorer / Documents / Properties docking) as a layer that overlaps the project workspace's own header — the project tab strip (Overview, Structure, Documents, Requirements, Tasks, Risks, Timeline, Deliverables) is half hidden under the menu bar, and the surface extends to the window edges rather than sitting inside the tab's content area. Also visible: the Documents panel shows the Engineering Cockpit for the project with "Project health: Unknown — no Engineering data yet" and a KPI period selector; the status bar reads Engineering · Project · P-0001 Test-A · 0 object(s), AREA Calculations.
   Likely cause (to verify at review time): `ProjectWorkspaceView.SetEngineeringSurface` (WP 19.2B) places the surface with negative margins or outside the tab content host, or the surface's own root sizes to the window rather than the tab content bounds; the layout walk passed because it checks bounds against parents, not against sibling overlap across the tab strip.

2. **Calculation attachments: drag and drop.** Screenshot: the Object Editor's Attachments section for a Calculation still takes typed metadata (File Name, Content Type, Size in bytes, an Attach button, "A file name is required"). The Product Owner wants to drag an Excel sheet onto the section and have it saved as the attachment — the same real-file path Evidence already has (WP 18.2A: IFilePicker plus drag-and-drop with bytes, size and hash recorded). Extend that to the generic Attachments section (Calculation first; the v0.18.0 notes already disclosed "Documents still take typed attachment metadata; only Evidence has the real file picker"), with a Browse button alongside the drop target.

3. **Remove the engineering surface's menu bar.** Screenshot: the strip reading View · Document · Theme · Commands · Help on the left and Undo · Redo · View Relationships · Macros · Reset Layout on the right, sitting above the ribbon category row (Calculations, Deliverables, Documents, Evidence, Invoicing, Manufacturing, Mechanical, Projects, Requirements, Timesheets, Verification). The Product Owner's words: "remove this taskbar, lots of generic bits in here that aren't offering anything or even relevant." Scope at review: delete the menu bar (`MainMenuFactory`, WP 19.2B touched it) from the Structure tab's surface; keep any command that still matters reachable elsewhere — Undo/Redo via Ctrl+Z/Ctrl+Y and the ribbon or Command Palette, Reset Layout and Theme already live in Settings/Command Palette, Macros via the palette. Check the ribbon category row too: Deliverables, Invoicing, Projects and Timesheets categories appear inside the engineering ribbon although those commands belong to their own rail areas — likely the same "generic bits" complaint; decide at review whether the ribbon inside Structure shows only the engineering disciplines.

4. **No way to add a deliverable; no quotation anywhere.** Screenshot: the ribbon's Deliverables category offers only a disabled "Complete Deliverable" under Actions — nothing to create one. Deliverables today come only from a milestone's timeline (`ProjectMilestoneWorkflow.CreateDeliverableAsync`), which the Product Owner did not find. The Product Owner's model: **a quote is opened with the project; the quote defines the initial requirement set and defines the deliverables.** So the missing piece is a Quotation element on the project (opened at project creation or from the project), from which requirements and deliverables are derived, with the Deliverables tab and ribbon able to add a deliverable directly. This is new scope (the v1.0.0 programme's WorkPackages.md has no quotation package; ADR-0150's commercial core covers client, PO, budget, rate card, dates, manager only). At review: propose the shape — Quotation as a Kind under the project (reference, date, client, line items each naming a deliverable and its price/basis; accepted/declined; the PO reference on the project links back to it), deliverables and requirement stubs created from its lines, Deliverables tab gains Add; the Product Owner decides the scope and version.
   **Priority (Product Owner, 2026-09-14): "adding that quote section is a huge priority."** Treat the Quotation as the lead item of the review-and-update pass, ahead of the cosmetic items; plan it as its own Work Package with an ADR (quote → requirements → deliverables → completion → invoice request becomes the spine), and size it before starting so the Product Owner can choose hotfix-on-v0.19.0 versus v0.20.0.

5. **Library records need a proper record view.** Screenshot: Evidence → Libraries lists each reference record as one text line — e.g. "fst-m10-coarse — M10 x 1.5 • rev 3 • Checked • Wikimedia Foundation, Wikipedia — ISO metric screw thread, Selected sizes table, row M10" under Fasteners (7), and the Materials (6) rows with their Aalco citations. The Product Owner wants to open each record individually in a real UI window, not a line of text, to review the data inside it (the definition's properties, units and values; revision history; state; source citation; where it is cited). Note the fst-m10-coarse row shows rev 3 / Checked — the review states are working. At review: give reference records an Object Editor declaration per library (Materials, Fasteners, Bearings, Sections, Rate Cards …) or one generic reference-record editor that renders the definition's fields from the record's own schema, with Verify/Release/Revise on it and the citation and "cited by" sections; open on double-click and via an Open action on the row, and it must open right up from Add and Revise.

6. **Information architecture — nine sketches (Product Owner, 2026-09-14).** Transcribed as read; the Product Owner is asked to confirm. The sketches themselves are the Product Owner's own paper; the transcription below is the record.

   **Shell (every page):** top bar = TempestOS mark · Global search (centre) · Notifications · Login details (right). Left nav = **Home, Projects, Tasks, Engineering, Business** (Business added on the second sheet; "Etc." on the project sheet).

   **Home dashboard (sheets 1–2):**
   - Top-level task view, five tiles: Overdue · Due today · Due this week · Approvals (confirmed by the Product Owner) · Finance.
   - Commercial snapshot: Quotes, Invoices.
   - Project status (total): On track · At risk · Overdue · On hold — annotated "chart" (show as a chart).
   - Upcoming milestones.
   - Task list.
   - Right rail "Project view": Continue → last 3 projects; Recent → last 5; Favourite → latest accessed 5.

   **Project dashboard (sheet 3):** status tiles Active · At risk · On hold · Ready to invoice; panels Blocked projects · At risk · Ready to invoice; bottom: top-level project schedule as a simple Gantt chart — start date / end date, rough hours from the quote.

   **Engineering dashboard (sheet 4):** Open tasks · Engineering reviews.

   **Business dashboard (sheet 5):** tiles Invoiced · Overdue · Due 30 · Due 90; Accounts receivable (show all due 30 + overdue); Accounts payable (all subscriptions < 60 days, all loaded bills < 30 days); Quotes (open value; all over 7 days old to chase); Cash flow chart.

   **Projects tree (sheets 6–7):** Projects → Dashboard + Reports → Open → Project A, Project B … each with Deliverables · Requirements · Evidence · Sign off → Closed (closed less than 90 days ago) → Project C, D … → Archive (reference data for older projects, > 90 days).

   **Engineering tree (sheet 8):** Engineering → Dashboard + Reports → Tasks (Calculations · Reviews · Approvals) → Modules (Mechanical · Electrical · Structural · …) → Reference data (Standard parts · Materials library · Engineering/mathematical constants · …).

   **Business tree (sheet 9):** Business → Dashboard & Reports → Quotes (New quote · Quotes sent · Outstanding) → Invoices (New invoice · Available to invoice, i.e. completed work · Sent · Outstanding/Overdue) → Subscriptions (Hardware · Software · Premises).

   **Deltas against the v0.19.0 candidate, to raise at review:** (a) Tasks becomes a real top-level area (WP 19.2B removed it as declared-but-empty) with task tiles on Home and Open tasks/Reviews/Approvals in Engineering; (b) Business is a new top-level area holding Quotes (item 4), Invoices (today's Invoicing area) and Subscriptions/Accounts payable — subscriptions, loaded bills and cash flow are new bookkeeping scope that sits at the edge of the "not ERP" guard (D-028); (c) Projects gains Open/Closed/Archive with a 90-day rule and a per-project Sign off; (d) Engineering gains Electrical and Structural modules and a constants library; (e) Timesheets, Evidence and Reports are not on the sketched left nav — Evidence moves under each project and Reference data under Engineering; where Timesheets goes is an open question; (f) Home's right rail (Continue, Recent, Favourite) already exists in the cockpit in a different arrangement; (g) the Gantt from quote hours ties the schedule to the Quotation of item 4.

7. **Timesheets live under Business.** Product Owner: "Timesheets in business please — drop down to select the project worked and the time." So the Business tree becomes Dashboard & Reports · Quotes · Invoices · Timesheets · Subscriptions, and the entry form is a project drop-down plus the time (hours) — the current Record prompt already takes project, day, hours, billable, grade and task; keep it but make the project a drop-down of open projects and lead with project and hours.

8. **Subscriptions and bills are read from other software, never entered in Tempest.** Product Owner: the accounts-payable side (subscriptions, loaded bills, and by extension the cash-flow chart) is a direct draw from the accounting package, linked into Tempest so one dashboard shows everything; Tempest holds no bookkeeping of its own. This keeps the "not ERP" guard intact: the Business dashboard's payable and cash-flow panels are read models over the existing invoicing connector seam (Xero / QuickBooks Online expose bills, subscriptions/repeating bills and bank/cash positions; the Fake connector returns scripted values), the same way Paid is read, never set. At review: extend `IInvoicingConnector` (or a sibling read-only `IAccountsConnector`) with bills-due and cash-position reads, cache the last reading with its timestamp, show "unavailable since <time>" when the connector is not authorised, and put nothing in the store beyond the cached reading.

9. **Answers (Product Owner, 2026-09-14):** a **quote export** is wanted in this release, to test it before running the consultancy — so WP 19.5B renders the quote as a PDF (reference, date, client, lines with hours and price, totals, terms) through the same SkiaSharp path as the issue sheet, with Export on the quote and Send offering it. **Xero** is the accounting package; the Hardware / Software / Premises split of subscriptions maps from Xero's own account names and tracking categories with sensible keyword defaults, editable in Settings, and the Xero reads are the primary, best-tested path (QuickBooks Online secondary).
