## Link check (Academy landing/navigation)

**Method.** A Python script (kept in the session scratchpad, not
committed — the task asked for a check, not a permanent tool) parsed
every real Markdown link (`[text](target)`) and every backtick-quoted,
slash-containing inline path in exactly the three named locations:
`docs/academy/Contributor Learning Path.md`, `docs/academy/Academy
Index.md`, and every file under `docs/academy/00 Introduction/`. It
excluded `http(s)://`, `mailto:` and pure in-page anchors, decoded URL
percent-encoding, and resolved each remaining reference against the
tree using this repository's own two conventions: a real Markdown link
resolves relative to the file that contains it; a backtick-quoted path
resolves repo-root-relative if its first segment is a real top-level
entry (`docs`, `src`, `tests`, `archive`, `scripts`, `.github`, or a
named root file), and Academy-folder-relative (`docs/academy/…`)
otherwise — the shorthand these three documents themselves use for a
sibling Academy section (`06 Engineering Standards/…` cited from a
chapter that lives under `00 Introduction/`).

**Result: 166 references checked, 0 broken, 0 needed fixing.**
(Two of the five source files gained new citations during this Work
Package's own edits — items 15, 17–20 above — raising the count from
162 before this Work Package's edits to 166 after; every added
reference was checked and resolves.) The first run of the script
reported 34 "broken" links; all 34 were false positives from the
script's own initial, too-simple resolution rule (treating every
backtick path as repo-root-relative), corrected before this figure was
taken as final — recorded here so the number is not mistaken for links
that were actually found broken and silently left as they were.
