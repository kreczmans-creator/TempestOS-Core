# TempestOS v0.4.0
## Platform Foundation

**Release Type:** Engineering Baseline
**Status:** Extensible Platform, Foundation Closed
**Date:** 2026-07-27

---

# Overview

Version **0.4.0** completes the Platform Foundation phase of TempestOS.

This release delivers the capabilities that turn the Runtime Foundation
(v0.3.0) — a runtime that could host modules — into an actual, extensible
platform: a real module SDK, plugin loading from disk, cross-module
communication, and Host-orchestrated background work.

The objective of this release, like v0.3.0 before it, was not feature
delivery for its own sake, but the creation of a governed, deterministic
platform surface future capabilities can be built on without redesigning
what already exists.

This release is deliberately rescoped from its original plan: Navigation,
a Command Framework dispatcher, Diagnostics improvements, and Developer
Experience tooling remain unbuilt and are formally deferred to the next
milestone, not included here as an unfinished commitment.

---

# Platform Foundation

Building on the Runtime Foundation, v0.4.0 now provides:

- Module SDK (`ModuleBase`, `ModuleLifecycleBase`)
- Plugin Manifest Discovery and Loading
- A living Sample Module set (`ClockModule`, `ClockLifecycleObserverModule`)
- Dependency Injection for Discovered Modules (`ModuleMetadataAttribute`)
- Event Bus (`IEventBus`/`EventBus`)
- Background Services (`HostedServiceDiscoveryService`/`HostedServiceManager`)
- Two decimal-numbered Host Lifecycle extensions (Plugin phases `3.1`/`3.2`;
  Hosted Service phases `8.1`/`10.1`), neither requiring any change to the
  Host's existing state machine or failure model

These components extend the Runtime Foundation without modifying it —
every v0.3.0 platform-service contract is unchanged.

# Engineering Principles Demonstrated

The Platform Foundation demonstrates the following engineering
principles, extending those v0.3.0 already established:

- Architecture before implementation
- Reuse before invention (reflection-based discovery applied a third and
  fourth time; sequential batch orchestration reused for the Event Bus
  and Background Services alike)
- Deterministic runtime behaviour
- Explicit ownership
- Failure isolation, extended twice more (plugin failures, hosted-service
  failures) on the same governing rule
- Governance made checkable, not merely practised

# Baseline Statement

**Version 0.4.0 completes the Platform Foundation for TempestOS.**

Remaining Foundation Work: **NONE.**

Future platform capabilities shall build upon this foundation rather than
revisiting it, unless a genuine, documented engineering reason requires
otherwise. Any change affecting the Runtime Foundation or the Platform
Foundation this release completes shall be evaluated through the
Architecture Decision Record process and Engineering Governance before
implementation.

---

# Historical Significance

Version 0.4.0 marks the completion of the TempestOS Platform Foundation
phase — Platform Formation, Academy Formation, and Governance Formation
are all complete (see `docs/releases/Platform Foundation Completion
Report.md`).

This release concludes the platform-foundation phase of development.
Subsequent releases are expected to focus on engineering capability —
Navigation, a Command Framework, Diagnostics, and Developer Experience —
built using the foundation this release establishes, not a redesign of
it.

---

# Looking Forward

With the Platform Foundation complete, the next milestone will
concentrate on capability delivered on top of this platform. Planned
development includes:

- Navigation Architecture, then Implementation (`WP 4.6A`/`WP 4.6B`)
- Command Framework (`WP 4.7`)
- Diagnostics Improvements (`WP 4.8`)
- Developer Experience Improvements (`WP 4.9`)

These capabilities will be implemented using the Platform Foundation
established by this release.
