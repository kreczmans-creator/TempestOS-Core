# WP 10.6A — Technical Debt Review

## Purpose

The required, dedicated Technical Debt Review — confirming every
disclosed scope reduction this Work Package made is correctly recorded
as an Accepted Trade-off (`AT-##`) with a real Revisit Trigger, that no
genuine defect was found and left unfixed, and that the Technical Debt
Register's own totals are accurate after this Work Package's own
additions.

## 1. Zero New `TD-##` Items — Confirmed, Not Assumed

A `TD-##` entry records a genuine defect in already-shipped behaviour;
an `AT-##` entry records a disclosed, deliberate scope boundary. Every
one of this Work Package's own six disclosed limitations (§2, below) is
a boundary this Work Package itself chose when building genuinely new
capability, never a defect discovered in code that predates it — none
of this Work Package's own new code exhibited incorrect behaviour
against its own stated contract at any point during implementation or
testing (confirmed: the combined test suite passed on every full run
performed, with no test requiring a fix to already-committed behaviour
— the "found and fixed before commit" pattern several prior Work
Packages report simply did not arise this time, an honest observation,
not a claim of unusual thoroughness).

## 2. Six New Accepted Trade-offs, Each With a Real Revisit Trigger

| # | Trade-off | Revisit Trigger, Verified Real |
|---|---|---|
| AT-18 | Undo/Redo limited to Rename + Favourite toggle | A real, demonstrated need for broader coverage, or a real "restore" capability for soft-deleted objects being built for an unrelated reason first — both concrete, checkable conditions, not vague |
| AT-19 | Background Task progress is coarse state only | A real, demonstrated need for percentage progress on a genuinely long-running command handler — checkable against a real, named handler once one exists |
| AT-20 | Macro steps limited to `CreateDefault`-eligible commands | A real, demonstrated need for real discipline commands to become Id-invokable — the same trigger `AT-10` (`WP 6.3`) already names for its own identical root cause |
| AT-21 | Command History is a UI-surface aggregation, not a dispatcher interception | A command dispatched through a path bypassing every recorded surface, or a real, demonstrated need for audit-grade completeness — both concrete |
| AT-22 | Undo/Redo and Command History are session-only | A real, demonstrated need for cross-session persistence — checkable against real user-reported friction |
| AT-23 | No keybinding remap UI; no real external controller vendor integration | A remapping UI (low effort, already has a real `Bind`/`Unbind` API to build against) or a real vendor SDK commissioning decision (high effort, its own Work Package) |

Every trigger names a concrete, checkable future condition — never "if
we feel like it" — matching this Register's own established discipline
for every one of its other twenty-two entries, independently
re-verified against the Register's own full table during this review.
