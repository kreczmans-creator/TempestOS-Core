# WP 10.3A — Engineering Object Editors — Implementation Report

## Purpose

The complete implementation record for `WP 10.3A` — professional
graphical editors for Engineering Objects across all six disciplines,
built as one generic Object Editor Framework rather than six
independently hand-built editors, integrated with the existing
Workspace, Cockpit, and Property Inspector, without modifying any of
the twelve frozen `WP8.0B` Workspace contracts.

## 0. Scope Discipline

Direct `git status`/file-level review confirms every touched or added
file lives under `src/Tempest.Desktop/` (`Editors/`, `Views/`) or
`src/Tempest.App/Workspace/` (one new command, six registration
files), plus `tests/`. Zero files under
`src/Tempest.Core/EngineeringDomain/` or `src/Tempest.Core/Runtime/`
touched. Zero floating windows, zero Digital Thread graph, zero ribbon
— confirmed directly (§7).

## 1. The Real Gap This Work Package Found and Closed

`DocumentAreaView.BuildBody` (`WP 10.0B`) was, by its own explicit
disclosure, "never a bespoke, per-Kind rich editor... those remain
disclosed future work." Every open document tab, for every Kind,
across every one of `WP 10.1A`–`WP 10.2B`, rendered exactly three
read-only lines: Title, Kind, Id. This Work Package replaces that
placeholder with a real, working editor.

## 2. The Object Editor Framework — One Generic Engine, Not Six

`ObjectEditorView` (`src/Tempest.Desktop/Editors/ObjectEditorView.cs`)
is applied uniformly to every real Engineering Domain object across
all six disciplines — realising "Requirements editor"/"Mechanical
object editor"/"Calculation editor"/"Verification editor"/"Document
editor"/"Manufacturing editor" as the *same*, real, working editor
applied to each discipline's own real Kind(s), never six independently
duplicated implementations. `ObjectEditorView.TryCreate` attempts to
resolve the real object via `EngineeringDomainContext.Repository`;
returning `null` (the caller's signal to fall back to the original
generic body) only for a synthetic, non-repository Kind (Calculations'
own `"CalculationTemplate"`) or the Sample Explorer's own fixed,
fictional content — every real Kind across all six disciplines
resolves and gets a real editor, with zero per-Kind registration code
anywhere in `Tempest.Desktop`.

## 3. Editable Properties — Name and Content, Both Real

Two generic, uniformly-real fields, each gated per-Kind exactly like
`PropertyInspectorView`'s own established "editable only where a real
command exists" discipline:

- **Name** — `IWorkspaceManager.CanRename`/`RenameObjectAsync`
  (`ADR-0096`, unchanged).
- **Content** — `IWorkspaceManager.CanRevise`/`ReviseObjectAsync`, a
  **new**, third Kind-keyed `IWorkspaceManager` extension (`ADR-0097`
  — see §8). Every discipline's own already-existing `Revise*Command`
  becomes a factory; Mechanical, the one discipline with no Revise
  command at all before this Work Package, gets a new one
  (`ReviseMechanicalObjectCommand`), mirroring the other five exactly.

**`ADR-0063` honoured throughout**: every read (`Content`,
`Status`/`History`, relationships, validation) is a direct call
against the real Domain object; every write (Rename, Revise) dispatches
through a real, registered `IWorkspaceCommand` — this class never calls
a mutating Domain method directly.

Deeper, discipline-specific structured-field editing (Requirement
Owner/Priority, Mechanical BOM quantity, Calculation Execute, Document
Attachments, Verification Record Result) remains real, disclosed
future work (`FCR-0068`), not silently claimed here.

## 4. Dirty-State Tracking, Save/Cancel, Read-Only Mode

A local, buffered dirty flag (`ObjectEditorView.IsDirty`) — distinct
from and unrelated to `IWorkspaceView.IsDirty`, which remains
permanently `false`, unchanged, by design (every concrete
`IWorkspaceView` has documented this since `WP 8.1A`: "every mutation
dispatches through a Command and commits immediately... never buffers
a local, uncommitted edit"). This Work Package's own editor genuinely
does buffer local edits before Save — a new, Desktop-local concept, not
a redefinition of the frozen contract member. `DocumentAreaView`
reflects it in the tab header (`MarkDirty`, §5) alongside — never
instead of — `view.IsDirty` itself.

Save commits via real Commands (§3); Cancel reverts both fields to
their last-loaded values and clears dirty. The Read-Only toggle
disables both fields (and Save); flipping it on while dirty
auto-reverts, avoiding an inconsistent disabled-but-edited state.

## 5. `DocumentAreaView` — An Injectable Content Builder

`DocumentAreaView` gained a `Func<IWorkspaceView, Control>?`
constructor parameter, defaulting to `BuildDefaultBody` (the original
generic three-line body, renamed `public static` so it remains the
honest fallback) — every existing caller (`new DocumentAreaView()`,
`Tempest.Desktop.Tests`) is unaffected. `MainWindow`'s own builder
tries `ObjectEditorView.TryCreate` first. A new `MarkDirty(Guid, bool)`
method updates the owning tab's own header text in place (`" *"`
suffix), the real Desktop-local dirty-state's own visible
consequence — `DocumentAreaView` itself stays completely agnostic to
*why* a tab is dirty.

## 6. Relationship Summary and Navigation Between Related Objects

A real, flat list — both directions (`IHasRelationships.GetRelationshipsAsync`
for outgoing, `EngineeringDomainContext.RelationshipRepository.GetIncomingAsync`
for incoming, both already-permitted reads, `ADR-0063`). Deliberately
flat, never a node-link graph — `ADR-0093`'s Digital Thread graph is
explicitly out of this Work Package's own scope. Each row's own "Open
→" button calls an injected navigate callback (`MainWindow`'s own
`NavigateToObject`, wrapping the existing `INavigationService.OpenAsync`
+ `DocumentAreaView.ShowTab` — no new navigation mechanism).

## 7. Lifecycle Display

`IHasLifecycle.Status` plus the five most recent `History` transitions
(From → To, timestamp) — a direct, real read, distinct from and more
complete than `PropertyInspectorView`'s own facet-derived Lifecycle
summary (`WP 10.2A`), since this class holds the real object directly.

## 8. `ADR-0097` — The One Genuine, Disclosed Contract Extension

`IWorkspaceManager` gains `RegisterReviseFactory`/`CanRevise`/
`ReviseObjectAsync`, mirroring `ADR-0096`'s own shape exactly a third
time. Full reasoning in `ADR-0097` itself; summary: additive only,
every existing member of the twelve frozen contracts (plus `ADR-0096`'s
own five) is untouched, and it is the minimal, precedented mechanism
`ADR-0063` requires for a real, dispatched Content field.

## 9. Validation Feedback — Real, for the First Time

`IValidatable.ValidateAsync()` already existed at the Domain layer
(`ADR-0075`) but was never reachable from any Workspace/Desktop
surface — `PropertyInspectorView`'s own "Validation" section has
disclosed "no per-object validation-result read exists anywhere in the
Workspace layer" since `WP 10.2A`, and remains unmodified, still true
of the Property Facet layer specifically. `ObjectEditorView` holds the
real object directly, so it calls the real method — Errors and
Warnings both rendered, informational only, never blocking Save (§10).

## 10. Compatibility Verification — All Twelve `WP8.0B` Contracts, Plus `ADR-0096`

Independently re-read: `IWorkspace`, `IWorkspaceManager` (extended,
additively, a third time — `ADR-0097`), `IWorkspaceView`(`+Factory`),
`IWorkspacePanel`, `IWorkspaceLayout`, `INavigationService`,
`ISelectionService`, `IWorkspaceContext`, `IWorkspaceState`,
`IProjectExplorer`, `IPropertyInspector`, `IWorkspaceCommand` — zero
members changed or removed in any of the twelve; `IWorkspaceManager`'s
own three new members are the only contract-level change, precedented
identically by `ADR-0096`. Zero Engineering Domain files touched. Zero
Runtime files touched.

## 13. Summary

Every named scope item is realised: Object editor framework (new,
generic), tabbed object editors (via the existing, unmodified
`DocumentAreaView` tab strip), Requirements/Mechanical/Calculation/
Verification/Document/Manufacturing editors (all the same real
engine, applied per Kind), editable properties (Name + Content, both
real, both dispatched through Commands per `ADR-0063`), validation
feedback (real, for the first time), dirty-state tracking (new,
Desktop-local, reflected in the tab header), Save/Cancel workflow
(real), read-only mode (real), relationship summary (real, flat,
bidirectional), lifecycle display (real), navigation between related
objects (real, reuses `INavigationService.OpenAsync`). Integrated with
the Workspace (Commands, `EngineeringDomainContext`), Cockpit
(`ActionCompleted` triggers `_cockpitView.Refresh()`), and Property
Inspector (`ActionCompleted` triggers `_inspectorView.Refresh()`).
**Zero changes to any of the twelve frozen `WP8.0B` Workspace
contracts** beyond one precedented, additive `IWorkspaceManager`
extension (`ADR-0097`, mirroring `ADR-0096` exactly). Zero Engineering
Domain changes. Zero Runtime redesign. Zero floating windows, zero
Digital Thread graph, zero ribbon.
