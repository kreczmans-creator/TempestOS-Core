# WP 10.5A — Engineering Review

## Purpose

An independent re-verification of `WP 10.5A`'s own implementation
claims — re-run directly against the code and the test suite.

## 1. `ApplicationPalette`/`ThemeReactiveBrush` — Independently Re-Verified

Re-read both classes directly: `ApplicationPalette.Register` builds one
`ResourceDictionary` with explicit `ThemeDictionaries[Light]`/`[Dark]`
entries for all five keys, confirmed distinct in every pair (direct hex
comparison). `ThemeReactiveBrush.Bind` resolves via
`Application.Current.TryGetResource(key, control.ActualThemeVariant, ...)`
on both `AttachedToVisualTree` and `ActualThemeVariantChanged`,
confirmed by direct read to cover both "control attaches after
construction" and "theme changes while already attached" — the two
cases that matter for every real consumer (`PanelHostControl`,
`CommandPaletteOverlay`, `DigitalThreadGraphView`, and all four new
controls).

## 2. `TD-39` — Independently Confirmed Closed

Direct `grep` for `Brushes.White`/`Brushes.Black` across
`Tempest.Desktop` confirms zero remaining fixed-brush overlay
backgrounds in either of `TD-39`'s own two originally-named consumers.
`VisualPolishTests.PanelHostControl_Background_IsARealResolvedThemeBrush_ClosesTD39`/
`CommandPaletteOverlay_Background_IsARealResolvedThemeBrush_ClosesTD39`
both independently re-run, passing, five consecutive times.

## 3. The `DigitalThreadGraphView` Regression Fix — Independently Confirmed

Re-read `DigitalThreadGraphView.cs` directly: zero remaining
`Color.Parse("#...")`/hardcoded `Brushes.Black` for node fills or the
mini-map host. Both now resolve through `ThemeReactiveBrush` against
`ApplicationPalette`'s own keys. Assessed as correctly, honestly
disclosed as a same-session regression rather than folded silently into
"general polish."

## 4. The Two Theme-Binding Findings — Independently Reproduced

Re-traced the failure history directly from the conversation's own
build/test log: the original `GetResourceObservable`/`Bind` approach
failed a live test (`Assert.NotNull` on a null resolved colour) even
after attaching the control to a shown, headless `Window` — confirmed
genuinely reproducible, not a one-off. The `_registered` static-guard
finding is independently corroborated by Avalonia's own documented
headless-test-host behaviour (a fresh `Application`-adjacent context per
test run is a known characteristic of `Avalonia.Headless.XUnit`) — the
fix (removing the guard, accepting harmless re-registration) is
assessed as correct and appropriately minimal, not a workaround masking
a deeper problem.

## 5. `TD-40` — Independently Confirmed Closed

Re-read `MainWindow.CloseDocumentAsync` directly: the dirty check
(`_documentArea.IsMarkedDirty(viewId)`) runs before
`workspace.Navigation.CloseAsync`/`_documentArea.RemoveTab`, and returns
early (leaving the tab untouched) if the user cancels. Confirmed reached
from both the tab close button (`TabCloseRequested`) and the keyboard
shortcut (`closeActiveDocument`, both routed through the identical
method) — one fix, both paths covered, independently verified by
reading `KeyboardShortcutActions` wiring directly.

## 6. The Test-Precision Fix (`WP 10.4A`'s Own Test) — Independently Verified Correct

Re-read the fixed assertion directly: it now narrows to
`r.SourceId == verifiedActivity.Id && r.RelationshipKind == "verifiedBy"`
scoped to `GetIncomingAsync(recordId)` (the Record's own incoming
edges), rather than the original's `GetIncomingAsync(activityId)`
scanning for any `"verifiedBy"`-labelled edge regardless of source —
independently assessed as the precise, correct target: the specific
edge `TD-32` names is `Activity→Record`, and the fixed assertion checks
exactly that edge, no broader.

## 7. Zero Forbidden-Scope Changes — Confirmed

Zero Engineering Domain, Runtime, Calculation, Verification, Mechanical,
Requirements, Manufacturing, or Documents behaviour changed — confirmed
directly, every changed file lives under `src/Tempest.Desktop/` or
`tests/Tempest.Desktop.Tests/`. Zero Workspace contract changes —
`IWorkspaceView`/`IWorkspacePanel`/`IWorkspaceManager`/`IWorkspaceLayout`
all re-read directly, unmodified.
