# WP 10.3B — Architecture Review

## Purpose

An independent architectural review — whether "reuse the three
already-Kind-keyed dispatch verbs instead of inventing generic Id
invocation" is genuinely the correct design, whether the QAT/Toolbar
and Ribbon/Navigation-Framework consolidations are architecturally
sound rather than merely convenient, and whether both defect fixes
belong at their own true source.

## 1. Scope Constraints — Independently Confirmed

Re-read the controlling instruction's own nine exclusions/constraints
and fifteen-item scope list directly against `git diff --stat`. Every
touched/added file falls under `src/Tempest.Desktop/`. No file under
`src/Tempest.Core/` or `src/Tempest.App/` appears anywhere in the diff
— the cleanest compatibility result of any Work Package this release,
stronger even than `WP 10.2B`'s own "zero of twelve contracts touched"
(this Work Package touches zero files in either layer at all, not
merely zero contract members).

## 2. "No New Command Framework" — Independently Assessed as Correctly Honoured

The alternative — a generic `IWorkspaceManager`/`ICommandRegistry`
extension letting any command be invoked by Id with caller-supplied
parameters (a fourth Kind-keyed provider category, mirroring
`ADR-0096`/`ADR-0097` a third time) — was available and would have let
*every* command dispatch generically, not just three verbs. Considered
and independently assessed as correctly rejected: the controlling
instruction's own explicit "No new command framework" reads most
naturally as excluding exactly this kind of generalisation, and the
three-verb reuse already covers the two operations (Delete needs no
input; Rename/Edit routes to already-built input collection) that
structurally can be satisfied without one. Building a fourth extension
here would not have been "no new framework" in spirit even if
additive in form.

## 3. Per-Contract/Per-Layer Compatibility

| Layer | Touched? |
|---|---|
| `src/Tempest.Core/` (all of it, including `Commands/`) | No |
| `src/Tempest.App/Workspace/` (all twelve frozen contracts, plus `ADR-0096`/`ADR-0097`) | No |
| `src/Tempest.Desktop/` | Yes — one new file (`RibbonView.cs`), three modified (`CommandPaletteOverlay.cs`, `StatusBarView.cs`, `MainWindow.cs`) |

**Zero Workspace/Domain/Runtime surface touched at all** — the Ribbon
achieves everything through composition over already-public Desktop-
layer collaborators (`ICommandRegistry`, `IWorkspaceManager`,
`IWorkspace`), never needing a new capability from either layer below
it.

## 4. Consolidation Decisions — Independently Assessed as Architecturally Sound

**QAT subsuming the old Toolbar**: both controls served the identical
two actions (Palette, Theme) before this Work Package; keeping both
would have been genuine duplication, not redundant safety. Correctly
consolidated.

**Ribbon subsuming the old Navigation Framework**: the old button row's
sole function (switch area) is now one property of the Ribbon's own
tab-click handling, not a separate concern needing a separate control
— independently assessed as the correct simplification, not a loss of
capability (§`WP10.3B Engineering Review.md` §6 already confirmed
nothing is lost).

## 5. Defect Fixes — Correct Layer, Confirmed

`CommandPaletteOverlay`'s own fix stays inside that same class (the
`InvokeSelectedAsync` method that owned the original defect) — not
patched around from `MainWindow` or duplicated into `RibbonView`.
`RibbonView.Rebuild`'s own fix stays inside that same method — not
worked around by having `MainWindow` call `RefreshEnablement()` an
extra time after construction. Both fixes land at their own true
source, mirroring this project's own established "fix defects at their
own source, not one layer up" discipline (`TD-26`'s own `WP 10.1B`
precedent).

## 6. Recommendation

**Sound, complete.** Zero Workspace/Domain/Runtime files touched at
all — the strongest layering-compatibility result of any Work Package
this release; "no new command framework" independently assessed as
correctly honoured by reusing existing Kind-keyed dispatch rather than
generalising it; both consolidations assessed as genuine
simplifications, not capability loss; both disclosed defect fixes
confirmed to land at their own true source.
