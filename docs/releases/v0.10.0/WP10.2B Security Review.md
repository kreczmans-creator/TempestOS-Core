# WP 10.2B — Security Review

## Purpose

An eighth consecutive dedicated Security Review (continuing the
recovery from `WP 8.9.0`'s own disclosed "zero dedicated Security
Reviews" gap, `WP 9.0A` onward) — whether this Work Package's own new
surface (Docking, Collapse, Auto-Hide, predefined layouts, the Output
panel, `DesktopPanelUiState`) introduces any new security-relevant
concern, and whether it correctly inherits every control the platform
already enforces.

## 1. Scope

Every new/modified file under `src/Tempest.Desktop/Docking/`,
`src/Tempest.Desktop/Views/OutputPanelView.cs`,
`src/Tempest.App/Workspace/OutputPanel.cs`,
`src/Tempest.Desktop/MainWindow.cs`, `src/Tempest.Desktop/App.cs`.
Zero `src/Tempest.Core/` files touched — confirmed by direct `git
diff --stat`; this Work Package inherits every existing
authentication/authorization/persistence control unmodified, never
reimplements one.

## 2. New Findings

**None.** No new command dispatch surface (`OutputPanel` is a passive
display panel — it dispatches no `ICommand`, unlike Project
Explorer/Property Inspector's own Rename/Delete surface `ADR-0096`
added); no new data-write surface beyond a second `ISettingsProvider`
key (§3, below); no new cross-process/cross-user surface of any kind.

## 3. `DesktopPanelUiState` — Security-Relevant Checks

- **Reuses, does not reimplement, `ISettingsProvider`** — the same
  `RegisterDefinition`/`GetValueAsync`/`SetValueAsync` surface
  `WorkspaceState` already uses, inheriting whatever
  persistence-at-rest posture `ISettingsProvider`/`IPersistenceStore`
  already provide (unchanged, `TD-36` already discloses the one known
  limitation there — a working-directory-relative default root path —
  unaffected by this Work Package).
- **No secret, credential, or personally-identifying data** — every
  persisted field is a bool/double/nullable-string layout preference
  (Collapsed/Pinned/Visible/Height/last-preset-name). Confirmed by
  direct read of `DesktopPanelUiStateDto`.
- **No new permission-gated read or write** — Collapse/Pin/Output
  visibility are pure presentation state, gated by nothing today (the
  same as the pre-existing Left/Right hide toggle, `WP 10.0B`, already
  ungated) — consistent, not a regression.

## 4. `OutputPanel`/`OutputPanelView` — Security-Relevant Checks

`IDiagnosticsProvider` is already DI-public, already consumed
ungated by `StatusBarView` since `WP 10.2A` — `OutputPanelView` reads
the identical surface, introducing no new exposure. Module
names/hosted-service type names are internal platform identifiers
(`ModuleDescriptor.Name`/`Type.Name`), not user data — no
confidentiality concern beyond what `StatusBarView` already discloses
identically.

## 5. Auto-Hide Flyout — Security-Relevant Checks

The flyout reparents an **already-constructed, already-authorized**
`PanelHostControl` instance — it never constructs a second view over
data the user was not already authorized to see via the panel's own
normal docked state. No new authorization boundary is crossed by
entering/leaving Auto-Hide.

## 6. Honest, Disclosed Absences — Security Relevance

`TD-39` (fixed-brush overlay background, not theme-variant-aware) has
**zero security relevance** — a purely cosmetic finding, confirmed by
this review independently (`WP10.2B Engineering Review.md` §4).

## 7. Recommendation

**No new security-relevant finding.** This Work Package's own entire
new surface is presentation-layer-only, reuses existing, already-
reviewed platform services without modification, and introduces no
new command dispatch, no new credential/secret handling, and no new
cross-boundary data flow.
