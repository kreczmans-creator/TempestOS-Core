# WP 10.2B — Docking & Workspace Layouts — Implementation Report

## Purpose

The complete implementation record for `WP 10.2B` — a professional
dockable workspace over the existing `Tempest.Desktop` application,
built entirely without modifying any of the twelve frozen `WP8.0B`
Workspace contracts. Covers every named scope item, what was already
real before this Work Package began, what is genuinely new, and the
one genuine, disclosed finding (`TD-39`).

## 0. Scope Discipline

Direct `git status`/file-level review confirms every touched or added
file lives under `src/Tempest.Desktop/` (`Docking/`, `Views/`) or
`src/Tempest.App/Workspace/` (one new class, `OutputPanel`), plus
`tests/Tempest.Desktop.Tests/`. Zero files under
`src/Tempest.Core/EngineeringDomain/` or `src/Tempest.Core/Runtime/`
touched — **No Engineering Domain changes**, **No Runtime redesign**,
both confirmed, not merely claimed. Zero floating OS windows (the
Auto-Hide flyout is an in-window `Grid`-attached-property overlay, never
a second `Avalonia.Controls.Window`/toplevel — see §4). Zero
multi-monitor code. Zero ribbon. Zero Digital Thread graph code.

## 1. What Was Already Real Before This Work Package

A direct read of the existing Workspace/Desktop layer, before writing
any new code, found several named scope items already fully
implemented, since earlier Work Packages:

- **Saved workspace layouts** / **Restore previous layout on
  startup** — `WorkspaceState`/`ADR-0064` (`WP 8.1A`) already persists
  `IWorkspaceLayout.PanelPlacements`, open tabs, and last selection
  through `ISettingsProvider`, and restores it on the next
  `IWorkspaceState.LoadAsync`. Confirmed unchanged.
- **Reset workspace layout** — `IWorkspaceLayout.ResetToDefault()`
  already existed (`WP 8.0B`'s own contract). This Work Package's own
  contribution is a real, reachable UI affordance (`View → Layout →
  Reset Layout`) that calls it — see §6.
- **Persistent panel visibility** / **Persistent splitter positions**
  — `WorkspacePanelPlacement.IsVisible`/`Size`, both already
  round-tripped through `WorkspaceState`. Confirmed unchanged.
- **Dockable Project Explorer** / **Dockable Property Inspector** —
  both already dockable at Left/Right (`WP 10.0B`'s own `DockingGrid`).

None of these needed reimplementation. Re-verifying them directly,
rather than assuming, is itself part of this Work Package's own
Engineering Review discipline (`WP10.2B Engineering Review.md` §1).

## 2. Genuinely New: The Bottom Dock and the Output Panel

### 2.1 `WorkspaceDockPosition.Bottom` — realised for the first time

`WorkspaceDockPosition` has carried a `Bottom` member since `WP 8.0B`
— never wired to any actual dock surface until this Work Package.
`DockingGrid` (`src/Tempest.Desktop/Docking/DockingGrid.cs`) gained a
third row (`RowDefinitions`: Star / Auto-splitter / Pixel), a horizontal
`GridSplitter` spanning all five columns, and `SetBottomPanel`/
`SetBottomVisible`/`SetBottomCollapsed`/`SetBottomHeight`/
`BottomPanelResized`/`IsBottomVisible`/`BottomHeight` — the exact same
method shape Left/Right already established, applied a third time.

### 2.2 `OutputPanel` — a fourth `IWorkspacePanel` implementer

`src/Tempest.App/Workspace/OutputPanel.cs` is a new, Desktop-local
`IWorkspacePanel` implementation — `Title = "Output"`,
`DockPosition = Bottom`, a fixed `WellKnownId` constant (mirroring
`ProjectExplorer`/`PropertyInspector`'s own `TD-35`-motivated
precedent). Implementing the same, already-open `IWorkspacePanel`
interface a fourth time is exactly the extensibility that contract
already documents ("the Project Explorer and Property Inspector both
implement this") — not a change to it.

### 2.3 `OutputPanelView` — real content, honestly scoped

`src/Tempest.Desktop/Views/OutputPanelView.cs` displays a live
`IDiagnosticsProvider` read: Runtime Host State, every tracked
module's lifecycle state, every tracked hosted service's lifecycle
state — the identical "real read, never fabricated" discipline
`StatusBarView.SetDiagnostics` (`WP 10.2A`) already established,
applied to a dockable panel. **Honestly disclosed scope**: this is a
live module/hosted-service status stream, not a captured log-history
feed — `ILogSink` is write-only, with no read-back API anywhere in the
platform; adding one would be a Runtime change, explicitly out of this
Work Package's own "No Runtime redesign" scope (see `TD` discussion,
`WP10.2B Engineering Review.md` §3).

## 3. Collapsible Panels

`PanelHostControl` (`src/Tempest.Desktop/Docking/PanelHostControl.cs`)
gained a Collapse header button — a manual, in-place shrink to a fixed
`DockingGrid.CollapsedStripSize` (32px) strip, still occupying the
panel's own normal dock slot (its own expand affordance stays
reachable), distinct from Hide (`SetXVisible(false)`, which occupies
none). The strip's own direction-hinting glyph (`◀`/`▶`/`▼`/`▲`) is
derived from `IWorkspacePanel.DockPosition`, so the same control
correctly self-orients for Left, Right, and (new) Bottom.

## 4. Auto-Hide Architecture

A second header button (📌/📍) toggles Pin. Unpinning a panel:

1. Forces the same thin-strip presentation Collapse already uses
   (`PanelHostControl.IsStripShowing = _collapsed || !_pinned`), and
2. Removes its reserved dock space, handing it back to the Document
   Area (`DockingGrid.SetXCollapsed(true)`, applied via the identical
   collapsed-column-width mechanism).

Clicking the strip while unpinned raises `FlyoutRequested` instead of
expanding in place (which is what the same click does while pinned) —
`MainWindow` handles it by calling `DockingGrid.ShowFlyout(host, edge,
size)`, which **repositions the same, already-docked `PanelHostControl`
instance** (via `Grid.SetColumn`/`SetRow`/`SetColumnSpan`/`SetRowSpan`
plus `ZIndex = 100`) as a temporary overlay on top of the Document
Area — never a second, duplicate control, and never a second, floating
OS `Window`. `ShowFlyout` captures the panel's own exact prior
placement and `HideFlyout` restores it exactly.

**Deliberate interaction model, disclosed**: click-to-reveal, click-
the-Document-Area-away or `Escape`-to-dismiss — not hover-to-peek with
a dwell timer. Chosen for determinism, keyboard parity, and headless
testability (`WP10.2B UX Review.md` §3), not because hover was
attempted and found difficult.

## 5. Multiple Predefined Layouts

`PredefinedLayouts` (`src/Tempest.Desktop/Docking/PredefinedLayouts.cs`)
— a static class, zero state of its own — defines three named presets
(`Engineering`/`Review`/`Documentation`), each nothing but a fixed
combination of values already legal under `IWorkspaceLayout`/
`WorkspacePanelPlacement` plus this Work Package's own Desktop-local
Output/pin state:

| Preset | Explorer | Inspector | Output |
|---|---|---|---|
| Engineering | 240px, Left | 240px, Right, pinned | Hidden |
| Review | 180px, Left | 320px, Right, pinned | Visible, 180px |
| Documentation | 320px, Left | 240px, Right, **Auto-Hidden** | Hidden |

Applying one calls `IWorkspaceLayout.SetPlacement` (twice) plus this
Work Package's own `DockingGrid`/`PanelHostControl`/`DesktopPanelUiState`
setters — **no new Workspace-layer capability was introduced to support
"predefined layouts" at all.**

## 6. Reset Layout

`View → Layout → Reset Layout` calls `IWorkspaceLayout.ResetToDefault()`
directly (unchanged since `WP 8.0B`), reapplies both returned
placements, and resets every Desktop-local flag (Collapse/Pin/Output)
to its own documented default — the real UI affordance §1 named as
missing.

## 7. Desktop-Local Persistence — `DesktopPanelUiState`

Collapse, Auto-Hide, and Output-panel state are **not** part of
`IWorkspaceLayout`/`WorkspacePanelPlacement` — none of the three exists
in the frozen `WP8.0B` contract shape, and extending it to carry three
more concepts this Work Package's own controlling instruction never
asked for would be exactly the "contract redesign" it explicitly
excludes. `DesktopPanelUiState`
(`src/Tempest.Desktop/Docking/DesktopPanelUiState.cs`) persists this
state through a **second, sibling** `ISettingsProvider` key
(`"Workspace.Desktop.PanelUiState"`) alongside `WorkspaceState`'s own
(`"Workspace.State"`) — the identical "own JSON blob under its own
Settings key" pattern (`ADR-0064`), applied a second time to a second,
independent concern. Loaded synchronously in `MainWindow`'s own
constructor (mirroring how `IWorkspaceState`'s own load already
completes before `MainWindow` is ever constructed, `App.cs`), saved
from a new public `MainWindow.SaveDesktopUiStateAsync()`, called
alongside (never inside) `WorkspaceHost.ShutdownAsync` from `App.cs`'s
own `ShutdownRequested` handler — two independent writes to two
independent Settings keys.

## 8. Improved Document Hosting

Modestly, honestly scoped: `DocumentAreaView` itself is unchanged this
Work Package (its tab/pin behaviour was `WP 10.2A`'s own scope). The
real improvement is structural — the Document Area's own available
space is now correctly computed against **three** dockable edges
(Left/Right/Bottom) instead of two, and it is the Grid area every
Auto-Hide flyout temporarily overlays and every Collapse/Auto-Hide on
any edge hands space back to. `DockingGrid.SetCenterContent` itself is
unchanged in signature.

## 9. Compatibility Verification — All Twelve `WP8.0B` Contracts

Independently re-read, one at a time, against this Work Package's own
diff: `IWorkspace`, `IWorkspaceManager`, `IWorkspaceView`(`+Factory`),
`IWorkspacePanel`, `IWorkspaceLayout`, `INavigationService`,
`ISelectionService`, `IWorkspaceContext`, `IWorkspaceState`,
`IProjectExplorer`, `IPropertyInspector`, `IWorkspaceCommand` — **zero
members added, zero members changed, zero members removed, in any of
the twelve.** `IWorkspacePanel` gained a fourth *implementer*

This is a stronger compatibility claim than `WP 10.2A`'s own (which
disclosed one additive `IWorkspaceManager` extension, `ADR-0096`) —
**zero new ADRs this Work Package** (`WP10.2B Architecture Review.md`
§1).

## 10. One Genuine, Disclosed Finding — `TD-39`

`PanelHostControl`'s own opaque overlay `Background` is a fixed
`Brushes.White` — required once a panel can be reparented as an
Auto-Hide flyout directly over the Document Area's own content, but
not theme-variant-aware (visually wrong in Dark theme). Found by direct
inspection while designing the flyout — the identical, already-shipped,
**previously unregistered** limitation `CommandPaletteOverlay` (`WP
10.0B`, `Background = Brushes.Black`) already carries for this
platform's only other overlay control. Both surfaced and registered
together, for the first time, as `TD-39` (Technical Debt Register) and
`FCR-0067` (Future Capability Register) — a cosmetic-only finding, no
functional defect (`WP10.2B Engineering Review.md` §4).

Every named scope item is realised: Resizable panels (extended to
Bottom), Docking framework (extended to three edges), Collapsible

`WP8.0B` Workspace contracts. Zero Engineering Domain changes. Zero
Runtime redesign. Zero floating windows, multi-monitor, ribbon, or
Digital Thread graph code.** One genuine, disclosed, cosmetic finding
(`TD-39`/`FCR-0067`); one genuine, disclosed, out-of-scope governance
