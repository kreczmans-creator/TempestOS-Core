## 4. Architecture Verification

**Result: Pass — all four named ADRs independently confirmed honoured,
directly from source.**

- **`ADR-0063`** (Views read directly; every mutation dispatches through
  a Command) — confirmed by direct grep for every mutating-verb call
  pattern (`ReviseAsync`/`SetStatusAsync`/`CreateAsync`/`LinkAsync`/
  `DeleteAsync`/`RecordAsync`) across `src/Tempest.App/` and
  `src/Tempest.Desktop/`: every hit resolves inside a Command handler's
  own `HandleAsync` (the legitimate mutation funnel), never inside a
  View. The one apparent exception (`MacroManagerDialog` calling
  `_macroManager.CreateAsync`/`DeleteAsync` directly) was traced to
  `IMacroManager` — confirmed, by its own interface documentation, to be
  a Platform Service (`ADR-0036`) governing Desktop-local macro
  definitions, not one of `ADR-0063`'s own explicitly-named Engineering
  Core services (`IRequirementsService`/`IMaterialCatalog`/
  `ICalculationEngine`/`IVerificationService`) — correctly outside this
  ADR's own scope, not a violation. The `WP 10.7A` drag-and-drop Move
  handler was independently re-read: `ProjectExplorerView` never
  references `ICommandDispatcher` (confirmed by grep, one hit — its own
  doc comment stating exactly that); `MainWindow` dispatches the real
  `Move*Command` via `commandDispatcher.DispatchAsync` — the "raise
  intent, owner dispatches" pattern confirmed exactly as documented.
- **`ADR-0070`** (Command Palette is a view over `ICommandRegistry`, not
  a second registration mechanism) — confirmed directly:
  `CommandPaletteOverlay` reads `_registry.Items` (the shared registry,
  no second list), filters only by search text (never by `CanExecute`,
  so nothing is ever hidden), and invokes via `_registry.InvokeAsync`.
  The disclosed `WP 10.3B` fix (a `CommandUnavailable` event replacing a
  prior silent no-op) is present and wired.
- **`ADR-0096`/`ADR-0097`** (Rename/Delete/Revise are the only Kind-keyed
  additions to the frozen `IWorkspaceManager`) — confirmed directly by
  reading the complete member list of `IWorkspaceManager.cs`: exactly
  three `Register*Factory`/`Can*`/`*ObjectAsync` trios exist (Rename,
  Delete, Revise) alongside the twelve original `WP 8.0B` members. No
  fourth, Move-generalising, or otherwise generic dispatch member
  exists anywhere in the shipped interface. Each of the three dispatch
  methods (`RenameObjectAsync`/`DeleteObjectAsync`/`ReviseObjectAsync`)
  confirmed routing through the shared `DispatchObjectCommandAsync`
  helper (the Command Framework), not a direct service call.
- **`ICommandDispatcher`/`ICommandRegistry`** — confirmed **byte-for-byte
  unmodified** across the entire `v0.10.0` diff: `git diff --stat` against
  both files returns no output.

**No architectural shortcut was found anywhere in the `v0.10.0` diff.**
