# WP 10.3B — UX Review

## Purpose

An independent UX review of the Engineering Ribbon — whether it
genuinely reads as a professional command surface rather than a
generic button grid, whether the honest "cannot dispatch" messages are
helpful rather than confusing, and whether the QAT/Ribbon
consolidations feel coherent to a user rather than like missing
functionality.

## 1. Discipline Differentiation — Assessed

Each Ribbon tab differs by real content: a genuinely different set of
commands per discipline (Mechanical's own ten vs. Requirements' own
eighteen vs. Verification's own eleven), grouped identically (Create/
Organize/Lifecycle/Actions) but populated from that discipline's own
real registrations. **Assessed**: a user switching tabs sees a
substantively different command surface each time, not a relabelled
copy — correct differentiation, achieved through data (exactly the
same principle `WP10.3A UX Review.md` §1 already validated for the
Object Editor Framework), not through six hand-built layouts.

## 2. Honest "Cannot Dispatch" Messages — Verified Not Confusing

Three distinct message shapes, reviewed directly for clarity:

- No selection at all: `"'{DisplayName}' needs a selected object
  first."` — direct, actionable (go select something).
- Selection present but wrong Kind/capability: `"'{DisplayName}' needs
  a selected object this command applies to."` — slightly less
  specific than ideal (does not name *which* Kind), a real, disclosed
  minor gap, not a defect (the underlying `CanRename`/`CanDelete`/
  `CanRevise` predicates carry no reason string of their own to surface
  — the identical limitation `PropertyInspectorView`'s own editable-
  Name-field gating already has).
- No dispatch route exists at all: `"'{DisplayName}' needs a selected
  target or additional input this ribbon does not yet collect —
  available via Project Explorer's own context menu, or the Command
  Palette (Ctrl+K)."` — genuinely helpful: names *where* the action
  actually is reachable today, not just that it failed here.

**Assessed**: all three are a substantial improvement over the
pre-existing silent no-op (`CommandPaletteOverlay`'s own defect,
§`WP10.3B Engineering Review.md` §2) — a real, disclosed, positive UX
outcome of this Work Package, not merely a neutral fix.

## 3. Rename/Edit Routing to the Object Editor — Assessed Coherent

Clicking "Rename" on the Ribbon opens (or focuses) the same Object
Editor tab a user would reach via the Project Explorer's own inline
`F2` or context menu — **assessed as the correct choice**, not a
compromise: it reuses a UI the user may already be familiar with
(`WP 10.3A`), rather than introducing a second, ribbon-specific text-
entry affordance for the identical action. The one real UX cost,
disclosed: a user expecting an *immediate* inline rename (as `F2`
already provides) instead gets a tab-switch — a genuine, if minor,
behavioural difference between the two entry points for the "same"
action, named here rather than silently accepted as equivalent.

## 4. Recently-Used Commands — Assessed Useful, Correctly Scoped

Bounded to five, per-tab (a command only appears in the tab matching
its own Category) — avoids a single global list mixing six
disciplines' worth of unrelated recent actions. Session-only (not
persisted across restarts) — a disclosed, reasonable scope decision
for a first implementation, not a claimed-but-missing capability.

## 5. Disclosed UX Trade-offs

- **Command icons are verb-derived, not authored per-command** — every
  Rename button across all six disciplines looks identical (✏️); a
  future, real per-command icon set (`FCR-0069`) would let a Rename
  button differ visually from, say, a Duplicate button using the same
  Create-adjacent styling only by label. Functional today, less
  visually distinct than a fully bespoke icon set would be.
- **Keyboard shortcuts are not shown for any discipline command** — an
  honest reflection of the real, pre-existing gap (no discipline
  command has one today), not a Ribbon-specific omission.
- **The "wrong Kind" disabled-reason message does not name which Kind
  the command needs** — a real, disclosed minor gap (§2).

## 6. Recommendation

**Sound.** Discipline differentiation genuinely present through real
data; the three honest "cannot dispatch" message shapes are a real,
disclosed UX improvement over the pre-existing silent no-op;
Rename/Edit's own routing to the Object Editor is coherent, with one
minor, disclosed behavioural difference from `F2`; Recently-Used is
usefully, honestly scoped. Three minor, disclosed UX gaps, none
release-blocking.
