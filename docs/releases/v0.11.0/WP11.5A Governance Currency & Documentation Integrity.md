## A Note on Where This Work Package Is Filed

`v0.11.0` closed with `WP 11.4B` (`docs/releases/v0.11.0/WorkPackages.md`:
"All ten Work Packages (`WP 11.0A` through `WP 11.4B`) are now complete"),
merged to `main` (`4b1fb16`), tagged, and published. This project's own
established convention for follow-up work against an already-closed
release's own disclosed findings is to file the remediation under the
**release current when the work is actually done**, not the release that
first disclosed the gap — `WP 11.2A`'s own two disclosed findings were, in
fact, remediated this way already, under `WP 12.9.1`/`WP 12.9.2` in
`docs/releases/v0.12.0/`, not here.

This document is the exception, and the reason is disclosed rather than
silently followed: it was commissioned, by name and by path, as `WP11.5A`
under `docs/releases/v0.11.0/`. Rather than silently comply with a
now-factually-incorrect premise (that `v0.11.0` has an open next slot) or
silently relocate the deliverable to a different path than requested, the
premise was checked against the repository first (see "Before State,"
below), the discrepancy was put to the commissioning party directly, and
the explicit instruction received back was: audit, disclose, fix only what
is genuinely still drifted, and do not fabricate remediation for gaps that
are already closed. This document honours that instruction. `v0.11.0`'s
own `WorkPackages.md` — its "ten Work Packages... Complete" summary, its
status table, its closed history — is untouched by this Work Package. No
new row is added there. This document exists as a dated, standalone audit
report, filed at the requested path, not as an eleventh entry in that
closed release's own accounting.
