## What Was Done

### 1. Retired `TempestShell` as production code

Removed via `git rm` (history preserved, not deleted from the
repository's own past):

- `src/Tempest.App/Shell/TempestShell.cs`
- `src/Tempest.App/Shell/IPage.cs`
- `src/Tempest.App/Shell/PlaceholderPage.cs`
- `tests/Tempest.Core.Tests/Shell/TempestShellTests.cs`

  separately named in `WP11.3A`'s own summary sentence, but a necessary,
  in-scope consequence — `PlaceholderPage.cs` cannot be removed while its
  own test file still references it)

Both `src/Tempest.App/Shell/` and `tests/Tempest.Core.Tests/Shell/` are
now empty and no longer appear in the working tree (git does not track
empty directories).

**Obsolete references removed** — every doc-comment citing `TempestShell`
as a design precedent, across eight files, corrected rather than left
dangling:

A direct sweep (`grep -rn "TempestShell\|PlaceholderPage\|Tempest\.App\.Shell" src tests`)
confirms **zero remaining references** anywhere in source or tests.

- **`README.md`** — architecture diagram now includes `Tempest.Desktop`
  and `Templates/`; `Tempest.App` correctly described as the Internal

  qualification.
- **`docs/architecture/Platform Service Map.md`** — the Runtime Host's
  own "Consumers" entry corrected from `TempestShell` (never actually

  — an `Update, WP 11.3B` note added at the top (mirroring this
  project's own established pattern for evolving a standing document

  otherwise untouched.
- **Governance registers** — `Namespace Register.md` (`Tempest.App.Shell`
  row marked retired), `Test Register.md` (`Shell/` row marked retired),

  named occupant corrected). Each register was already independently,

  (last full review `WP 6.6`/`WP 9.1B`/`WP 5.0D` respectively); this Work
  Package performed a **narrow correction only**, explicitly disclosed as
  such in each register's own "Last Reviewed" field — not a full
  re-derivation, which remains a separate, out-of-scope undertaking.

### 4. Updated release engineering

`.github/workflows/ci.yml` and `.github/workflows/release.yml` — the
prior symmetric packaging (`WP 11.1A`/`WP 11.1B`, one artifact/zip
containing both `Tempest.App` and `Tempest.Desktop`) is replaced with
two separate, clearly-named artifacts in both workflows:

- `tempestos-desktop-release` / `TempestOS-<tag>.zip` — `Tempest.Desktop`
  alone, the shipped application.
- `tempestos-engineering-harness` / `TempestOS-<tag>-engineering-harness.zip`
  — `Tempest.App` alone, explicitly labelled.

`docs/academy/06 Engineering Standards/05-release-engineering.md`
updated to describe the corrected packaging.

### 5. Removed unsupported historical claims

`src/Tempest.Desktop/Program.cs`'s own doc comment previously asserted
*"`WP 10.0B`'s own explicit 'replace the console application as the
primary launch target' instruction"* — `WP11.3A`'s own investigation
found this phrase nowhere in any of `WP 10.0B`'s six deliverable
documents or elsewhere in the repository. Corrected to state the
now-formally-ratified position (`ADR-0101`) directly, with an explicit
note that the prior wording was found unverifiable and is not repeated.

## Verification

**`Tempest.Desktop` builds and runs.** `dotnet build -c Release`: 0
Warnings, 0 Errors. Launched directly
(`dotnet run --project src/Tempest.Desktop`, no keyboard/mouse
interaction — process launch and log observation only): the Runtime
Host started, all six Engineering Disciplines registered, every
Desktop-specific service resolved (`ISettingsProvider`,
`ICommandRegistry`, `EngineeringDomainContext`, `IRequirementsService`,
`IDiagnosticsProvider`, `IEventBus`, `IMacroManager`,
`IInputBindingRegistry`), the keyboard input binding provider
registered, and the application's own default navigation fired
(`Navigation requested to 'tempest.calculations.management'`) — real,
observed evidence the UI actually initialised, not merely that the
process started. Ran until deliberately timed out (15s); no exception,
no crash. The full `Tempest.Desktop.Tests` suite (real Avalonia headless
rendering, no mocks) was re-run in full: **202/202 passing**.

**`WorkspaceShell` still functions as an engineering harness.** Launched
directly (`dotnet run --project src/Tempest.App`, a single piped `0`
exit command via stdin — the same `StringReader`-based technique
`WorkspaceShellTests.cs` already uses, not a GUI interaction): the
Runtime Host started, all Engineering Disciplines registered, the
Workspace rendered, and the harness shut down cleanly on request — exit
code **0**, no unhandled exception anywhere in the captured output.

**`TempestShell` is completely removed.** Confirmed by direct `grep`
sweep of `src/`/`tests/` (zero matches for `TempestShell`, `IPage`,
`PlaceholderPage`, or `Tempest.App.Shell`) and by a full solution build
succeeding with `Tempest.App.Shell` no longer present as a compiled
namespace.

**Documentation accurately reflects the current architecture.**
`README.md` and `Contributor Learning Path.md` corrected and re-read in
full; `scripts/governance-healthcheck.ps1` (`WP 11.2A`) re-run against
the live repository post-change — the ADR Register check now correctly
reports **100 files, 100 register rows** (up from 99/99, picking up
`ADR-0101` automatically, no tool change required). No new Fail was
introduced by this Work Package's own changes; the pre-existing,
already-disclosed findings from `WP 11.2A` (the Academy Index "Work
Package Walkthroughs" gap; the four untracked empty-directory
references) are unchanged, exactly as expected — this Work Package's own
scope did not include closing them.

**Release workflow packages only the intended deliverables.** Both
`ci.yml` and `release.yml` re-read in full after editing: `Tempest.Desktop`
and `Tempest.App` are now uploaded as two distinctly-named artifacts in
every path (per-push CI artifacts and tag-triggered GitHub Release
assets alike) — never bundled into one, never implying co-equal status.
