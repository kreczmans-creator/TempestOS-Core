## What Was Built

`scripts/governance-healthcheck.ps1` — a standalone, read-only
PowerShell script with **no dependency on any production project**
(does not build, load, or reference `Tempest.Core`/`Tempest.App`/
`Tempest.Desktop`; pure file and text analysis). Eight checks, run in a
fixed, deterministic order, each independently reporting **Pass**,
**Warn**, or **Fail**:

| # | Check | What it does |
|---|---|---|
| 1 | ADR Register matches `docs/adr/` | Every `ADR-####` in `docs/adr/*.md` has a row in `ADR Register.md`, and vice versa. |
| 2 | Academy Index matches Academy articles | Every link in `Academy Index.md` resolves; every real article under `docs/academy/` is linked from it. |
| 3 | Release Register matches git tags | Every real `vX.Y.Z` git tag has a Release Register row; every row unambiguously marked Released has a matching tag. Skips gracefully ("where available," per this Work Package's own scope) if git or tags are unavailable. |
| 4 | Documentation Register references exist | Every unambiguous, path-shaped reference in `Documentation Register.md` resolves to a real file or directory. |
| 5 | `PROJECT_STATUS.md` references are valid | Every `vX.Y.Z` token is a real tag, at/after the current `VERSION`, or a disclosed historical exception; every path-shaped reference resolves. |
| 6 | `VERSION` matches a planned release folder | `docs/releases/v<VERSION>/` exists. |
| 7 | Release folders contain mandatory documentation | Every **tagged** release folder has release notes (either naming variant this project has used); `WorkPackages.md` is checked but only ever `Warn`s — see "Design Decisions." |
| 8 | Governance Index has no missing or orphaned documents | Same link/orphan logic as Check 2, applied to `Governance Index.md` against all of `docs/governance/`. |

A crashing check is itself reported as a `Fail`, never a silent skip —
the tool never exits without a report. Every check reads only; nothing
under `-RepoRoot` is ever written. An optional `-SummaryPath` writes the
same report to a file **outside** the repository — the script refuses to
run if `-SummaryPath` resolves inside `-RepoRoot`.

Exit code: **0** if every check is Pass or Warn; **1** if any check
Fails.

## Design Decisions

| Decision | Rationale |
|---|---|
| PowerShell, not a new .NET console project | No production-code dependency (the Engineering Requirement), no new build step for the very pipeline meant to verify builds, consistent with `scripts/new-release.ps1`'s already-established convention and this project's own tooling language. |
| `-RepoRoot` is a parameter, not hard-coded | Makes the tool testable against an isolated fixture without ever touching the real, tracked repository — the mechanism this Work Package's own failure-detection demonstration (below) depends on. |
| Free-text path extraction is deliberately scoped, not exhaustive | Governance prose contains many bare, context-relative filename mentions (`` `ADR Register.md` ``) this tool cannot resolve without guessing which sibling folder they mean. Only unambiguous, `/`-containing, extension-terminated or directory-terminated references are checked — named explicitly as a real, disclosed limitation, not silently claimed as complete coverage. |
| `WorkPackages.md` absence is `Warn`, never `Fail`, for shipped releases | `v0.9.0` and `v0.10.0` — both real, fully-governed, already-released — genuinely have no `WorkPackages.md`. Treating its absence as a hard failure would misrepresent accepted history as a defect; confirmed directly (`docs/releases/v0.9.0/`, `docs/releases/v0.10.0/` both lack the file) before writing this rule, not assumed. |
| Version tokens at or after the current `VERSION` are always valid | This project routinely and legitimately names near-term future releases in prose before they exist as a tag (`WP11.0B Architecture Roadmap.md` names `v0.12.0`/`v0.13.0`/`v1.0.0`) — planning, not drift. Only a token *older* than the current version with no tag and no disclosed exception is flagged, since that shape is what a genuine typo or fabrication would take. |
| Not yet a required/blocking CI status check | See "CI Integration," below. |

## Evidence & Findings

Three genuine defects were found and fixed in the tool itself while
building it — disclosed here per this project's "found and fixed, not
merely disclosed" convention, not silently smoothed over:

1. **A crash on multi-line-wrapped inline code spans.** This project's
   own prose hard-wraps at ~72–80 columns, so a single genuine inline
   path reference routinely straddles a line break in the raw file
   (`` `docs/releases/v0.11.0/WP11.1B Engineering\nWorkflow.md` ``). The
   first version of the path-extraction regex captured the embedded
   newline literally, which `[System.IO.Path]::GetFullPath` then threw
   `Illegal characters in path` on — found running the tool against the
   real `PROJECT_STATUS.md`, not anticipated in advance. Fixed by
   bounding span length, normalising internal whitespace, and validating
   the result against a strict path-segment character class (which also
   incidentally rejects ordinary prose that merely contains a `/`).
2. **An unhandled crash when git is available but the target is not a
   git repository.** Modern PowerShell (`$PSNativeCommandUseErrorActionPreference`)
   promotes a non-zero native-command exit code to a terminating
   exception under `$ErrorActionPreference = "Stop"`. One of three
   call sites guarded against this correctly; two did not. Found during
   this Work Package's own failure-detection testing against an isolated
   fixture with no `.git` directory (see "Verification," below) — not
   found by inspection, found by actually running the negative case.
   Fixed by centralising every git-tag lookup into one `Get-RepoTags`
   helper that never throws.
3. **An empty "warned" count in the summary line whenever exactly one
   check produced a `Warn`.** `(Where-Object {...}).Count` on a
   single-item result set returns `$null` in this environment, not `1` —
   a well-known PowerShell sharp edge. Found by reading the tool's own
   output during testing (`"Summary: 0 passed,  warned, 3 failed"`, a
   visibly missing number), not by code review. Fixed by wrapping every
   such count in `@(...)` to force array semantics unconditionally.

**The tool's first real run against this repository (after all three
fixes) found genuine, real governance drift** — not fabricated to
demonstrate value, and not fixed as part of this Work Package (see
"What This Work Package Deliberately Did Not Do"):

- **The Academy Index's "Work Package Walkthroughs" section stops at
  `WP 7.3A`.** Roughly fifty real retrospectives since — the remainder
  of `v0.7.0`, all of `v0.8.0` and `v0.9.0`, and most of `v0.10.0` — are
  never linked. This is a different document from, and a larger, more
  current instance of, the pattern `Academy Register.md` disclosed being
  found and fixed by `WP 10.2B`; this specific gap, in `Academy
  Index.md`, was previously undisclosed.
- **Three directories this project's own Documentation Register
  describes as existing (`docs/roadmap/`, `docs/diagrams/`,
  `docs/releases/v0.2.0/`) do not exist in the working tree** —
  confirmed via `git ls-tree`, they are not tracked by git at all. Git
  cannot track an empty directory; if these were ever created, a fresh
  checkout structurally cannot reproduce them without at least one
  tracked file inside. `src/Plugins/` (referenced in `WP11.0A Platform
  Architecture Review.md`'s own plugin-isolation finding) is the same
  class of gap, independently confirmed.

Both are disclosed here, in full, as this tool's own first genuine
catch — direct evidence it does what `FCR-0005` asked for.

**All implemented checks execute successfully.** Demonstrated directly
against this repository, on this branch, after every fix above:

```

==========================================

[PASS] ADR Register matches docs/adr/ (99 files, 99 register rows)
[FAIL] Academy Index matches docs/academy/ articles (154 files, 162 links)
       - Article(s) under docs/academy/ not linked from Academy Index.md: [50 files]
[PASS] Release Register matches git tags (8 tags, 10 register versions)
[FAIL] Documentation Register path references exist (46 path-like references checked)
       - Referenced path(s) that do not exist: 01 Engineering Principles/, 02 Runtime
         Architecture/, 03 Work Packages/, 04 Design Patterns/, 05 Case Studies/,
         06 Engineering Standards/, docs/diagrams/, docs/releases/v0.2.0/, docs/roadmap/
[FAIL] PROJECT_STATUS.md references are valid (14 version tokens, 93 path references)
       - Referenced path(s) that do not exist: [mix of the same bare-shorthand class
         above, plus docs/diagrams/, docs/releases/v0.2.0/, docs/roadmap/, src/Plugins/]
[PASS] VERSION ('0.10.0') matches a planned release folder
[WARN] Release folders contain mandatory documentation (8 release folders checked)
       - v0.10.0 has no WorkPackages.md (informational)
       - v0.9.0 has no WorkPackages.md (informational)
[PASS] Governance Index has no missing or orphaned documents (34 files, 43 links)

------------------------------------------
Summary: 4 passed, 1 warned, 3 failed (of 8 checks)
------------------------------------------
```

Exit code **1** — correct, given three genuine `Fail` results. All eight
checks completed without error (the earlier crashes, above, both
occurred and were fixed *before* this run).

Of the two remaining `Fail`-driving path lists, the bare items (`01
Engineering Principles/`, `02 Runtime Architecture/`, etc.) are the
disclosed, known scope limit (ambiguous shorthand this tool correctly
cannot resolve without more context) — kept visible rather than
suppressed, since even an ambiguous reference is real signal a maintainer
can act on. `docs/diagrams/`, `docs/releases/v0.2.0/`, `docs/roadmap/`,
and `src/Plugins/` are the genuine, confirmed findings above.

**The tool correctly reports failures when presented with known-invalid
conditions.** Demonstrated against an isolated, temporary fixture built
specifically for this test — never the real repository — via
`-RepoRoot`:

- A fixture with 3 ADR files (`ADR-0001`–`0003`) but a register listing
  only `ADR-0001`, `ADR-0002`, and a non-existent `ADR-0004` correctly
  reported **both** failure directions: `File(s) present in docs/adr/
  with no ADR Register row: ADR-0003` and `ADR Register row(s) with no
  corresponding file in docs/adr/: ADR-0004`.
- A `VERSION` file reading `0.9.0` with no `docs/releases/v0.9.0/`
  folder correctly reported `VERSION reads '0.9.0' but 'docs/releases/
  v0.9.0/' does not exist.`
- A fixture with no `.git` directory at all correctly triggered, then
  (post-fix) correctly avoided, the git-availability crash documented
  above — proving both the original defect and its fix against the same
  reproducible negative case.
- Every check whose expected file was simply absent from the fixture
  (`Academy Index.md`, `Release Register.md`, `Documentation
  Register.md`, `PROJECT_STATUS.md`, `Governance Index.md`) reported a
  clear, specific `Fail` with the exact missing path — never a crash,
  never a silent pass.

Result: **`0 passed, 1 warned, 7 failed (of 8 checks)`**, exit code 1 —
exactly the outcome a deliberately broken fixture should produce.

**CI successfully executes the governance health check.** See "CI
Integration," below, for what was wired in;
`docs/releases/v0.11.0/WP11.1A Implementation Report.md` already
disclosed that actual GitHub-hosted execution of this repository's CI
remains unverified in this environment (no runner available, pushing
judged outside an "await review" Work Package's own scope) — the same
disclosure applies here, honestly, rather than being silently dropped
now that a second workflow depends on it.

## CI Integration

`.github/workflows/ci.yml` gains a third job, `governance-health-check`,
alongside the existing `build-and-test` matrix and `gate`:

- Runs after `build-and-test` completes (`needs: build-and-test`,
  `if: always()` — not gated on the build actually succeeding, since a
  governance-document inconsistency is orthogonal to whether the code
  compiles, and this project's own instinct favours always producing the
  report over silently skipping it).
- Checks out with `fetch-tags: true` (the one addition beyond the
  default `actions/checkout` this job needs — Check 3 requires real
  tags, which the default shallow, tag-less checkout does not provide).
- Runs `scripts/governance-healthcheck.ps1`, writes its own report to
  the run's Job Summary, and exits with the script's own exit code.

**Deliberately not yet part of the required `CI Gate` job.** `gate`
still depends only on `build-and-test`. This is a considered decision,
not an oversight: the tool's own first run found real, pre-existing
governance drift (above) that predates this Work Package and was not
introduced by it. Wiring `governance-health-check` into `gate` today
would mean every future push and pull request fails the required check
immediately, for a backlog this Work Package's own scope — "implement
automated governance validation" — does not include clearing. The
health check is fully wired, fully visible (its own report appears in
every run's Job Summary regardless), and fully honest about its own
pass/fail state; promoting it to a required, blocking check is named
here as the natural next step **once** a follow-up Work Package closes
the disclosed drift, not deferred indefinitely or silently.

## What This Work Package Deliberately Did Not Do

- Did not fix the Academy Index's own ~50 missing "Work Package
  Walkthroughs" links, or the three untracked empty-directory
  references, or `src/Plugins/` — all disclosed above, all real, none
  fixed here. Backfilling fifty links accurately is a substantial,
  separate undertaking in its own right, not a safe addition to make
  under this Work Package's own "implement the tool" scope.
- Did not add `governance-health-check` to `gate`'s required checks —
  see "CI Integration."
- Did not configure any GitHub repository setting.
- Did not modify any ADR — a validation script choosing what to check is
  process tooling, not a platform architectural decision meeting
  Engineering Governance §5's criteria.
- Did not modify any production code, architecture document, or existing
  platform contract.
