# WP 16.1A — Enforce the Release Gate

**Type.** CI configuration plus repository-settings instruction. One
workflow file changed; no production code, test, ADR, or register.
**Branch.** `feature/v0.16.0-wp16.1a-gate`, cut from `feature/v0.16.0`.
**Closes.** Half of `TD-45`: the workflow half. The GitHub-settings half
cannot be performed from an engineering session and is handed to the
Product Owner below, with the exact settings.
**Cites.** `docs/releases/v0.16.0/v0.16.0 Release Plan.md` §3 (`WP 16.1A`);
`WP11.1B Engineering Workflow.md` §4; `FCR-0005`.

---

## What changed

`.github/workflows/ci.yml`, job `gate` (`CI Gate`):

- `needs: build-and-test` → `needs: [build-and-test, governance-health-check]`.
- The gate step now fails if **either** the build/test matrix or the
  Governance Health Check did not succeed, naming which.
- `governance-health-check` itself is unchanged: it still runs with
  `if: always()` after the build, so the governance report is produced
  even on a red build. What changed is that its result is now consumed
  by the gate instead of sitting beside it.

Why now: `WP 11.2A` shipped the health check as advisory, deliberately,
until it had proven itself on real drift. Since then it has caught real
drift at every release, and `v0.15.0` still had to backfill a 20-commit
range nobody had documented. `FCR-0005`'s own entry says the pattern was
"machine-detectable but not machine-enforced"; this closes that gap on
the CI side.

## What did not change, and why

- **`WP11.1B Engineering Workflow.md` §4 keeps its title
  "(Recommended — Not Configured)".** Retitling it before the GitHub
  setting exists would be the kind of documentation-ahead-of-reality
  drift this release is meant to end.
- **`TD-45` stays Open.** Its own text names the GitHub configuration as
  the closing action. This Work Package's report is linked from the row
  by `WP 16.2A`'s register pass; the row closes when the setting is
  confirmed.

## Product Owner action required — branch protection on `main`

No API available to this session can change repository settings (the
GitHub MCP toolset here has no branch-protection endpoint, and `gh` is
not installed). The setting is a one-time act by a repository
administrator, per `WP11.1B Engineering Workflow.md` §4:

**Settings → Branches → Add rule for `main`:**

| Setting | Value |
|---|---|
| Require a pull request before merging | On |
| Require approvals | 1 |
| Require review from Code Owners | On (`.github/CODEOWNERS` names `@kreczmans-creator`) |
| Require status checks to pass before merging | On |
| Required checks | `CI Gate` (this Work Package makes it cover governance too; `Governance Health Check` may additionally be listed for visibility) |
| Require branches to be up to date before merging | On |
| Require linear history | **Off** (the project merges with merge commits, never squash or rebase — §7.7) |
| Allow force pushes | Off |
| Allow deletions | Off |
| Do not allow bypassing the above settings | On (include administrators) |

**Verification the Product Owner can perform in under five minutes:** on
a throwaway branch, push a commit that breaks one test; open a PR; the
"Merge" button must be disabled with `CI Gate` red. Then push a commit
that only adds an ADR file without its `ADR Register.md` row; `Governance
Health Check` fails Check 1 and, after this Work Package, `CI Gate` goes
red too. Both demonstrations, once run, are the evidence that closes
`TD-45`; record their run IDs in that row.

## Validation

- `ci.yml` is valid YAML (parsed locally).
- The change is exercised by this branch's own CI run: `CI Gate` must
  show the new step name "Confirm every configuration and the governance
  check passed" and succeed with the health check at 7 pass / 1 warn / 0
  fail (a `Warn` does not fail the script, exit code 0, so the gate
  stays green on the pre-existing informational warning).
- Induced-failure evidence for the gate wiring is the Product Owner's
  demonstration above; it cannot be produced without pushing a
  deliberately broken commit, which this Work Package does not do.
