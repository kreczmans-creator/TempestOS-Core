## Repository Investigation

### 1. Where a decision record lives in this repository

- **`docs/governance/Architecture/Decision Register.md`** is the sole
  home for decisions that are not ADR-eligible. One row per decision,
  columns `# | Decision | When | Source | Type`; numbered `D-001`–`D-020`
  contiguous; every row "Verified directly from the source document
  cited in its own row." No per-decision files exist anywhere under
  `docs/` (`find docs -iname '*decision*'` returns only the register).
- **Next free number is `D-021`.** No `D-021` or higher appears anywhere
  in `docs/` or `PROJECT_STATUS.md` (`grep -rhoE 'D-0(2[1-9]|[3-9][0-9])'`
  returns nothing). The Companion branch was not searched; `TD-57`
  records that it allocated its own `TD-57`/`TD-58`, so a collision on
  `D-` numbers there is possible and is listed under Ambiguities.
- **The register's "Last Reviewed" reads 2026-07-28 (`WP 5.2`).** Twenty
  rows, none later than `v0.5.0`. This is the identical drift `TD-57`
  names for six other registers; it is not corrected here (out of this
  Work Package's scope and forbidden by the brief), and is disclosed for
  `WP 16.2A`.
- **ADR eligibility (Engineering Governance §5) was checked for each of
  the six.** None establishes a code convention, resolves a design
  tension between two technical requirements, or was defended under
  Technical Review; each is a scope, sequencing, or support-boundary
  decision. All six belong in the Decision Register, not `docs/adr/`.
  One (Q5, if the spike succeeds) may later produce an ADR-eligible
  dependency decision; that is `WP 16.5B`'s to judge.
- **No Product Owner scope decision has ever been recorded in the
  register.** Every existing row is a process or sequencing decision
  made by the engineering tier and reviewed. The plugin-support
  commitment that fired `v0.13.0`'s conditional trigger (`WP 13.0A`) was
  recorded in `Future Capability Register.md` (`FCR-0001`'s Dependencies
  field) and in prose, never as a `D-` row. This Work Package therefore
  proposes a new `Type` value, **`Product — scope boundary`**, in the
  register's existing free-text `Type` column, so the six rows are
  distinguishable from process decisions. Adopting that value is itself
  part of what approval ratifies.
- **Reservation precedent.** `WP 7.2B`/`WP 7.2C` reserved `ADR-0058`–
  `ADR-0061` in their own reports and `WP 7.3A` ratified them into
  `docs/adr/`. The six records below follow that pattern: numbered
  `D-021`–`D-026` **by reservation**, written here in the register's
  exact row format, and copied into the register verbatim only once
  approved, with the approval date in the `When` column.

   make it so, both Product Approval's: (a) merge
   `claude/v1-release-candidate-audit-ivvobl` to `main` via PR under

   literally. This branch has no dependency on which is chosen; only the
   forward references in this document resolve differently.

   brief's permissions** (`Product Roadmap.md` Phase 5.5;
   `PROJECT_STATUS.md` paragraph). Deferred, as above; the plan should
   be read as "on approval."

   records that branch allocating `TD-57`/`TD-58` independently; if it
   also allocated `D-021`+, `D-022`'s own ratification must renumber.
   Reservation, not allocation, keeps this reversible.
4. **`Product — scope boundary` is a new `Type` value** for the Decision
   Register. Approval of the six records implies approval of the value;
   if the Product Owner prefers an existing value, "Process — scope
   decision" is the nearest fit.
5. **Q5's "macOS supported" has no CI evidence** and never has. The
   record says so explicitly rather than omitting the caveat. If
   Product Approval wants "verified," `WP 16.5B` needs a `macos` CI leg
   added to its scope.
6. **Q4 changes the default behaviour of every host**, including
   `Tempest.App` and every test that spins up a `TempestHost`. The record
   assigns the mechanism to `WP 16.4B`; the plan's Wave 3 placement
   still holds, but `WP 16.4B`'s brief should add "audit every test that
   configures `Api:Port`."
7. **`WorkPackages.md` for this release lists `WP 16.0A` as "Not
   started."** It is now "Drafted — awaiting approval." That table is on
   the audit branch, not this one, and is not edited here; it is
