# Free oracles for the 40 calculators and one pack (v0.26.0)

Run each calculator with the inputs in the table, then run the same case in the named free tool.
Tolerance is the largest relative gap to accept once the inputs match exactly.
A bigger gap means a method difference (see Notes) or a defect, so log it in the verification record.

How I checked: on 2026-10-24 (rows F1, F2, F3, S7, S9, M7, M8, E7, E8, B7, B8, B9 and HPU: on 2026-10-25) I read each page through a web fetch or a search extract.
"Unconfirmed" marks a point I could not read. The tolerances are my proposals, not repository limits.
Inputs and expected values come from `docs/worked-examples/` and the calculator KATs.
Each calculator also has an independent Python script, `tools/verification/<id>.py`. All 40 exit 0 today. The pack has no script.
Those scripts re-derive the maths with the same method. They check the code, not the method.
