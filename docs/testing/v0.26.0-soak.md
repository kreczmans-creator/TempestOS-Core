# TempestOS v0.26.0: the performance and stability soak

Addendum C, Track S, item C-7. A scripted run of the real calculation services over a real SQLite database that measures time, memory and database size, and checks that nothing leaks, nothing is wrongly flagged stale and nothing issued ever changes. The last full run is written up in `docs/verification/soak.md`, with its numbers, the machine and the commit.

You do not need to run it to use the product. It is for the person who wants to know whether a long working session, a big project or a big import will behave.

## What it runs

It starts the application's own composition with no window (`WorkspaceHost`: the Evidence service, the PDF sheet renderer, all 54 calculators, the one calculation service) over a database in a temporary folder, then runs nine scenarios, each twice in one process so a leak shows as growth from the first run to the second. The first five are the specification's; the last four soak what the release added after them (record import, the demo project, the verification dashboard and the guided test).

| Scenario | What it does | What it checks |
|---|---|---|
| 500 calculation instances | Creates, runs and saves a calculation of every template from its shipped worked example, round and round, in one project. | Every one runs without a block, runs again to the same outputs, reads back unchanged, and none is stale. |
| Chains of depth 20 | Links 20 calculations deep (the upper limit of one hole fit is the nominal size of the next), changes the head, updates in order. | Every step after the head goes stale, the other chain does not, each step is current as soon as it is updated, a 21st link is refused. |
| 100 revise and supersede cycles | Revises, edits, checks (by someone else) and issues one calculation over and over, with its PDF sheet. | Every issued revision stays byte for byte as it was (its record, outputs, sheet text and PDF), and every attempt to edit one is refused. |
| 1,000 Monte Carlo runs | 1,000 runs of the Monte Carlo service at its default 10,000 samples, 1,000 more through a real calculator, 1,000 tornado sweeps. | The answers match the distributions sampled, the same seed gives the same answer, a run past each cap is refused. |
| Imports at their caps | A scan table at 5 MB and at one million rows, a CAD expression file and a parameter CSV at 5,000 parameters, the inputs CSV at 1 MB and 10,000 rows, a frame with its tables at their row caps, a reference record at every cap. | Each is read; one past each cap is refused with a plain sentence and leaves the calculation byte for byte as it was. |
| Record import at its caps | Seven Track P record templates of different shapes imported with data sized to the template; one file at every cap at once (1,001 rows, 64 columns, 4,096-character fields, 5 MB); a licensed record revised 100 times. | One past each cap (a byte, a row, a column, a character) is refused in a sentence with nothing saved; one bad row among a thousand good ones saves nothing, and a batch whose last record cannot be written leaves none of the others; no revision of the licensed record ever exports. |
| Demo project installed and removed | Installs and removes the demonstration project 20 times with a real project (one issued calculation, a pack, a scan profile, a record) beside it. | The real project is the same, document for document, after every install and every removal; the removal deletes the demonstration's calculations, packs and scan profiles and nothing else; the database grows only by the soft-deleted objects a removal keeps by design, the same every cycle; an issued demonstration calculation makes the removal refuse. |
| Verification dashboard built repeatedly | Builds the dashboard 40 times on a store with 10,000 reference records and 1,000 finished guided runs; exports it to markdown and PDF. | Every build gives the same rows, none is slower than the first, building writes nothing; the time per build is the measurement. |
| Guided runs to the run cap | Starts a guided run, records all 110 steps, finishes it, 1,000 times; then deletes the older finished runs. | The 1,001st start is refused with the cure named; the deletion keeps every template's manual status; no calculation or Evidence record changes; the time to read the run store is measured as it grows. |

## Running it

The scaled-down soak (about a tenth of the numbers) is part of the ordinary Desktop test run and takes about two and a half minutes:

```
dotnet test tests/Tempest.Desktop.Tests --filter "FullyQualifiedName~Tempest.Desktop.Tests.Soak"
```

The full soak runs the specification's numbers, takes about 25 minutes (25.0 on the last run, with the load average at 4 to 20 on 4 processors), and rewrites `docs/verification/soak.md` (keeping the notes a person wrote in it):

```
TEMPEST_SOAK=full dotnet test tests/Tempest.Desktop.Tests --filter "FullyQualifiedName~Tempest.Desktop.Tests.Soak.SoakFull"
```

`TEMPEST_SOAK_LOG=<file>` appends a line per step to a file, so a long run can be watched. `TEMPEST_SOAK_DUMP=<file>` makes the scaled-down run write what it measured. `TEMPEST_SOAK_ONLY=6,7` with `TEMPEST_SOAK_REPORT=<file>` runs only the scenarios numbered (at full scale) and writes that file instead of `docs/verification/soak.md`.

## What counts as a problem

- **A leak**: after the second run's host is disposed, the managed heap is more than 4 MiB above what the first run left and still rising on a third run; or the process holds more open handles than after the first run; or any handle is still open on the database's files.
- **A stale-flag error**: a calculation flagged stale with nothing changed, or not flagged when its upstream changed.
- **An immutability breach**: an issued revision that differs in any way from what was issued, or an edit to one that is not refused.
- **A cap not enforced**: a file or request past a documented cap that is read, or refused with an exception instead of a sentence.

A problem found is written as a failing test first, then fixed; the soak's own tests (`SoakHarnessTests`, `SoakLeakDetectorTests`) prove the leak check can fail.
