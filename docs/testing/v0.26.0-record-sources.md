# v0.26.0 bundled reference records: sources and licence status

This list is for the owner. It answers comment 5 of 2026-10-29 and its refinement 5a.

## What the owner asked

Many calculators showed missing reference records. The owner asked us to fill them from reference websites.
He said we need not use the standards themselves. He asked us to mark each record that comes from a paid standard by way of another site.
He will arrange the licences later.

## What ships

TempestOS now ships bundled record sets. Each set is a CSV file in a Track P record template's format.
The files are in `src/Tempest.Calc/Tempest.Calc.Library/RecordSeeds/Data`.
`RecordSeedCatalogue.cs` beside them holds each set's sources and licence status.

At start-up, TempestOS saves each set once, through the ordinary record import.
So each set passes every rule a person's own file passes: units, ranges and the calculators' hard limits.
A set already in the store is skipped. A person's own record is never changed or deleted.

## How each record is marked

- Every record names its main source, the date it was read, the table or clause, and the URL.
- Every value carries the same source, so a sheet that uses it cites it.
- The licence holder field states the licence status, for example "Secondary source — licence to confirm".
- The notes list every source with its URL, read date and licence status. They say how the values were taken and cross-checked.
- Where a page reproduces a paid standard's table, the notes say so: "Reproduces EN 10025-2 Tables 7, via Roymech".
- A set from a manufacturer or a secondary site is locked against export until the licence is settled. So is every set that comes from a paid standard.
- Derived sets and open-data sets are not locked. Open data are NASA POWER and NOAA records.
- Who entered it reads "TempestOS (bundled reference records)".

## Rules the values follow

- No value was typed from a paid standard document.
- Each value comes from an open web page, a maker's datasheet, an open dataset, or a formula.
- Most sets were checked against a second source. Where two sources disagreed, the safer value was kept. The notes say which.
- Where no lawful open source was found, the kind stays empty. The table below says why.

### How each set was taken

- `snapfit-friction-bayer`: Low and high ends of each range on steel as printed. Same-plastic pairs are derived as the high end times the factor the table gives in brackets (Table 3 note; its worked example uses PC on PC = 0.50 x 1.2 = 0.6). Cross-check: the SABIC excerpt gives PBT 0.35–0.40 and POM 0.20–0.35, as here. Neither end is conservative for every check: use the high end for the assembly force and the low end for the retention.
- `spring-wire-a228-gibbs`: The minimum tensile strength of each listed diameter (the conservative end of the band), converted from psi (x 0.00689476 MPa) and from inches (x 25.4 mm). Cross-check: the preview pages give 1.0 mm at 2150 MPa minimum and 2.0 mm at 1950 MPa; the sheet gives 2172 MPa at 1.016 mm and 1944 MPa at 2.032 mm.
- `spring-endurance-zimmerli`: Zimmerli's pulsating test points: unpeened S_sa = 241 MPa at S_sm = 379 MPa, shot-peened S_sa = 398 MPa at S_sm = 534 MPa, for spring steels under 10 mm whatever their strength. Derived: S_e = S_sa. A Goodman line from S_e to any S_su passes on or below Zimmerli's point, so this S_e is conservative for every wire.

## What stays missing, in short

Two required kinds stay missing on purpose. Both are `material.conductivity`, for room heat loss (B4) and Glaser (B7).
That record is a wall's layer build-up, so each project enters its own.
The other kinds left empty belong to one exact product, such as a motor or a transformer. Or no open source was found for them.
