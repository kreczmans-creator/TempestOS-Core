# TempestOS v0.26.0 — testing runbook

Use this on your Windows desktop to test the whole v0.26.0 line in order. It covers everything built since v0.25.3. That is the worksheet calculators, Addenda A, B and C, and the legacy-calculator replacement first planned as v0.27.0. Nothing is released or tagged.

Four companion files sit beside this one in `docs/testing/`:

- **`v0.26.0-owner-test-pack.md`** — the one ordered pack. It has eight parts. They are (1) build and install, (2) record entry from the Track P templates and (3) the demo project. Next come (4) the highest-liability calculators, (5) the chains and (6) the remaining calculators. The last two are (7) security spot checks and (8) the sign-off sheet. This runbook is the short route through the same tests. Go to the pack when this runbook says "see the pack".
- **`v0.26.0-test-values.md`** — one input set and its expected outputs for every worksheet calculator (87 sets, 54 calculators). Use it in step 5. It marks the 14 sets whose expected value is a hand calculation or needs your judgement.
- **`v0.26.0-known-defects.md`** — defects already found (fixed ones with their test, open ones with the owner decision they wait for). Check it before you log a fault.
- **`v0.26.0-soak.md`** — what the performance and stability soak runs and what it found. You do not need to run it.

**The Addendum C screens.** Four screens help you test. They sit under Engineering → Modules → Calculations, except the demo, which sits in Settings.

- **Guided test** walks you through the steps below. It opens each worksheet with its inputs, compares the outputs and keeps your results. The steps in sections 4, 6, 7, 8 and 9 and every worked example of section 5 are guided steps. Press **Copy results sheet** at the end. It gives the table of section 11.
- **Verification** is the dashboard. It covers every calculator and chain. It shows the known-answer results, the open defects, the records you have not entered and your own manual-test status. It is read-only.
- **Reference records** enters a whole record table from a grid or from a Track P CSV template (section 7).
- **Demo project** (Settings) installs and removes an invented press cell with every chain built (pack Part 3). The Guided test has no step for it.

**How this runbook maps to the pack.**

| Runbook step | Owner test pack |
|---|---|
| 1 Get the build, 2 Run the automated tests, 3 Start the app, 4 Smoke test | Part 1 |
| 7 Imports and records (the records screen) | Part 2 |
| Install the demo project (Settings) | Part 3 |
| 5 Every calculator, highest liability first | Part 4 (the highest-liability calculators), then Part 6 (the rest) |
| 6 Linked chains and packs | Part 5 |
| 8 Lifting behind the flag; 9 Legacy records | Part 4 (S8) and Part 7 (the flag); the legacy records stay here |
| Security spot checks | Part 7 |
| 11 Results sheet | Part 8 (sign-off sheet) |

Plan on about one day for steps 1 to 6 and half a day for steps 7 to 10.

---

## 0. Before you start (5 minutes)

1. Read `v0.26.0-known-defects.md`, top section only. Addendum C Track S C-1 fixed 130 of the 145 findings (4 Critical, 50 High and 76 Medium). 8 wait for an owner decision (5 High and 3 Medium). 7 Medium are still open. Do not rely on a calculator for a result an owner-decision row touches. Do not log listed defects again.
2. Have a results sheet open. Section 11 gives a template.
3. You need: Windows 10 or 11 x64, Git, the .NET 10 SDK (any 10.0.3xx), and the network once for `dotnet restore`.

## 1. Get the build (10 minutes)

Run this in PowerShell:

```powershell
dotnet --list-sdks                         # expect a 10.0.3xx line
cd $HOME
git clone --branch release/v0.26.0 https://github.com/kreczmans-creator/TempestOS-Core.git TempestOS-Core-0260
cd TempestOS-Core-0260
git log -1 --format="%h %s"                # expect the final merge on release/v0.26.0 (10085408 or later) or later
Get-Content VERSION                        # expect 0.26.0
dotnet restore src/TempestOS.slnx --locked-mode
dotnet build src/TempestOS.slnx --configuration Release --no-restore -p:TreatWarningsAsErrors=true
```

**Pass:** `Build succeeded.` with 0 warnings and 0 errors.

## 2. Run the automated tests (40 minutes, mostly unattended)

```powershell
foreach ($p in 'Engine','Sheets','Library','Calculators','FluidPower','Import') {
  dotnet test "tests/Tempest.Calc.Tests.$p" --configuration Release --no-build
}
dotnet test tests/Tempest.Core.Tests --configuration Release --no-build
$env:TEMPEST_TEST_TIMEOUT_FACTOR = '3'
dotnet test tests/Tempest.Desktop.Tests --configuration Release --no-build
python scripts/check-licences.py           # if Python is installed
```

**Expected (Linux, on the release branch with C-1 and C-3 to C-7 merged; `docs/build-log/STATUS.md` holds the latest figures):**

| Suite | Pass | Skipped |
|---|---|---|
| Engine | 465 | 0 |
| Sheets | 145 | 0 |
| Library | 1003 | 1 |
| Calculators | 2320 | 0 |
| FluidPower | 118 | 0 |
| Import | 625 | 0 |

A timing test can fail on a busy machine. Run it again on its own. If it passes alone, note it and move on. Any other failure is a fault: record it.

## 3. Start the app on a clean data folder (5 minutes)

```powershell
Get-Process Tempest.Desktop -ErrorAction SilentlyContinue | Stop-Process
$root = "$HOME\TempestOS-Test-Data"
dotnet run --project src/Tempest.Desktop/Tempest.Desktop.csproj --configuration Release --no-build -- --persistence-root $root
```

- The title bar must read `TempestOS 0.26.0 (<commit>)`, with the commit from step 1.
- To start again from nothing, close the app and delete `$root`.
- The log is `$root\logs\tempest-<yyyyMMdd>.log`. The date in the name is UTC.
- Create or open a project (rail: **Projects**). Links, packs and the saved list work inside one project.
- Open **Settings** and use **Switch person…** to sign in. The Guided test needs a signed-in person.

## 4. Smoke test (15 minutes)

Owner test pack, Part 1, section 1.6. In the Guided test these are steps `smoke-1` to `smoke-6`.

1. Rail **Engineering** → **Modules** → **Calculations** → **Worksheets**. The catalogue lists 52 worksheets. The two lifting worksheets are hidden while the Lifting feature is off.
2. Press Ctrl+K and type `accumulator`. **Accumulator sizing (gas law)** appears. Open it.
3. On the form, press **Import inputs (CSV/JSON)**. Paste the contents of `docs\worked-examples\fluid-power\fp.accumulator\clamp-circuit-bladder-accumulator\inputs.json`. The tip under step 5 copies a file to the clipboard. The governing bar reads PASS. `V0` is 31.6562 L.
4. Type `Smoke test` in **Calculation name**. Press **Save as calculation**. The calculation appears in **Saved calculations**.
5. Press **Record check**, then **Issue** (reference `TEST-001`, client `Test`). The status becomes Issued and the form becomes read-only.
6. Open the issued PDF: Engineering → Modules → Calculations → **Calculation register**, or the project's Evidence. It opens and shows the calculation.

**Pass:** every step does what it says. If the app does not start or the catalogue is empty, stop and record it.

## 5. Every calculator against its test values (4 to 6 hours)

Open `v0.26.0-test-values.md`. For each set:

1. Open the template named in the heading.
2. Import the set's `inputs.json`. This is the quickest way, and it brings in tables. Or type the inputs from the table.
3. Compare every expected output. It must match to the digits shown. Then compare the governing check, both PASS/FAIL and its utilisation.
4. Record Pass or Fail for each set. For a Fail, record the output, the expected value and the value shown.

To copy a file to the clipboard, run this in PowerShell:

```powershell
Get-Content -Raw "docs\worked-examples\<discipline>\<template>\<example>\inputs.json" | Set-Clipboard
```

Suggested order: highest liability first. The pack follows Track P's order (`docs/verification/risk-triage.md`).

- **Highest liability** (owner test pack, Part 4). A wrong pass here can hurt a person. Enter the records they need first (Part 2).
  - Electrical safety: E4 conductor sizing, E5 fault protection.
  - Lifting, behind the flag: S8 and the lifting lug (step 8).
  - Pressure parts: F2 accumulator, F1 cylinder, F3 O-ring gland, B6 sealed system.
  - Steel: S6 base plate, S7 lateral buckling, S1 section properties, S4 connections, S3 member checks.
  - Rotating and bolted parts: M3 bolted joint and bolt group, M4 shaft, M6 weld group, M7 spring.
- **The remaining calculators** (Part 6), in Track P's order.
  - High liability: E1 motor sizing, M2 fits and press fit, E6 load budget and E8 containment. Also B1 pipe and pump, B2 psychrometrics, B7 Glaser and B9 insulation.
  - Medium and low: M5, S2, S5, M1, M2c, M8, S2b, S9, E2, E3, B3, B8, B4, B5, E7, M9, E9.
  - The legacy replacements (the former v0.27.0 work): bearing-life-basic, fatigue-miner, material-margin, shaft-stress, thermal-expansion, thin-vessel, column-buckling, fillet-weld, plane-wall, thermal-chain.

14 sets are marked **For your review** in the test values file. Their expected value is a hand calculation or needs your judgement. The Guided test leaves them to you.

The lifting worksheets (`struct.lifting` and `mech.lifting-lug`) come in step 8.

## 6. Linked chains and packs (2 hours)

Use the pack scripts T-C1 to T-C15 in the owner test pack, Part 5. Each one does the following:

1. Create the pack from its template (left column → **Calculation packs** → pick → **Create pack from template**).
2. Check the values carried by every link against the pack README in `docs\worked-examples\packs\<pack>\README.md`.
3. Change one upstream input. Every downstream step shows `STALE`. **Check the pack** is refused.
4. Update the linked inputs in order. The pack checks and issues.

Run at least these four:

- drive train;
- hydraulic power unit (chain 1);
- actuated linkage (chain 5);
- electronics enclosure (chain 10).

## 7. Imports and records (1 hour)

Owner test pack: Part 2 (records) and Part 3 (the demo project, no guided step). Sections 5.16 and 5.17 cover W1 and W2.

- **W1 CAD import:** owner test pack T-W1 (section 5.16). Import an NX `.exp`, a SolidWorks design table and a CSV. Re-import a changed file, and the dependent sheet goes stale.
  - A comma-delimited CSV with a decimal comma must be refused unless its numbers are quoted.
- **W2 scan import:** owner test pack T-W2 (section 5.17). Load the Zeiss groove CSV and check the statistics. σ_within is c4-corrected; see the test values.
- **W3 materials and licensed records:** T-W3 and T-REC (sections 2.9 and 2.8). A record marked licensed never leaves in an export, in any revision.
- **C-3 records screen and CSV import:** owner test pack Part 2, sections 2.2 to 2.5 (R20 to R30). A worksheet that lacks records (Conductor sizing) lists the required ones. Each has a **Fill** link to Engineering → Modules → Calculations → Reference records. Import a record template (from `docs/verification/record-templates/`) filled from your own copy. A wrong unit, a bad row or a malformed file saves nothing. A good file saves the whole table, licensed by default, with the file's SHA-256 stamped. No button exports a record.

## 8. Lifting (S8 and the lifting-lug port), behind the feature flag (1 hour)

See owner test pack section 4.6 (T-S8) and section 4.6.2 (the S8 review checklist).

1. With the flag off, neither lifting worksheet is listed. A saved lifting calculation refuses to open or run. The refusal names the admin setting.
2. Switch the flag on. Run PowerShell as administrator:

   ```powershell
   New-Item -Path 'HKLM:\SOFTWARE\Policies\TempestOS\Features' -Force | Out-Null
   New-ItemProperty -Path 'HKLM:\SOFTWARE\Policies\TempestOS\Features' -Name Lifting -PropertyType DWord -Value 1 -Force | Out-Null
   ```

   Restart the app. Both lifting worksheets appear. The log records the source.
3. Run the `struct.lifting` test set from `v0.26.0-test-values.md`.
4. Sign-off with four different people, using **Switch person…**:
   - one prepares it;
   - a second attests;
   - a third checks;
   - a fourth countersigns. The statement must be 20 characters or more.

   Each wrong person is refused. Any edit after the attestation voids it.
5. The issued sheet says:
   - "design calculation, not a thorough examination";
   - that signatures are not authenticated;
   - "Optional feature: …".
6. Switch the flag off again:

   ```powershell
   Remove-ItemProperty -Path 'HKLM:\SOFTWARE\Policies\TempestOS\Features' -Name Lifting
   ```

Do not use S8 for real lifts until two things are done. Record the BTH-1 / EN 13155 review (owner test pack, section 4.6.2). Authenticate signatures.

## 9. Legacy records (30 minutes)

Copy a v0.25.3 data folder to a scratch `$root`. If you have none, the repository carries two old databases: `tests\Tempest.Calc.Tests.Library\Fixtures\legacy-v0.25.3.db.gz` and `legacy-v0.26.0-rc1.db.gz`. Decompress one with 7-Zip. It is a single gzip file. Save the result as `tempest.db` in an empty folder. Then use that folder as `$root`. Start the app on it.

- Legacy calculations open as read-only archive sheets.
- **Compare** shows the old and new values side by side.
- A legacy lifting record stays read-only while the flag is off.

## 10. Decisions only you can make

The full list is in the handover (`docs/handover/v0.26.0-handover.md`, Addendum C). It has one line for each open row, with its id. The owner test pack, section 8.8, repeats it. The main ones are here. Record each answer in `docs/decisions/v0.26.0-DECISIONS.md` or tell the next session:

1. **Known defects (Addendum C Track S).** C-1 has fixed 130 of the 145 findings (4 Critical, 50 High, 76 Medium). 8 wait for your decision: 5 High and 3 Medium (`v0.26.0-known-defects.md`, DECISIONS DC-03, DC-05 and DC-07). 7 Medium are still open or partly fixed (DC-07, DC-08).
2. **S8 lifting (DB-13).** Record the BTH-1 / EN 13155 review (owner test pack, section 4.6.2). Decide how signatures get authenticated before the flag is ever switched on.
3. **Svg.Custom, MS-PL (DB-08).** Approve it with its notice, or have the SVG renderer replaced.
4. **Reference diagrams (DI-08).** 27 Addendum A/B templates have no reference diagram. Decide whether the release waits for the drawings.
5. **F2 1.3.x (DB-09).** Re-run any emergency-stroke accumulator sheet issued under 1.2.0.
6. **Unconfirmed and Secondary known answers.** Check them against your printed copies (owner test pack, Appendix A).
7. **Clause numbers quoted from memory.** Check BS 7671 522.8, the LOLER and PUWER regulation numbers, ISO 12241, and the EN 13155 edition and clauses. Also check M8 2/3 against 0.67, and S9 γ_M1 1.1.
8. **Housekeeping.** Delete the remote branch `v0.26.0/addA-7b-chains` and the local tag `v0.26.0-rc1`. Decide DA-01: when to tag, release and merge to `main`.
9. **Accepted for v0.26.1 (DB-12).** Confirm, or ask for them now.
10. **Template versions (DC-14).** Before the first release, decide whether superseded template versions stay resolvable. A calculation checked or issued on an older version cannot be re-run after a version bump.
11. **Soak findings (DC-15).** Lower the frame caps (recommended), raise the 4 MB store cap, or store large tables elsewhere. Choose how revision labels after Z read.
