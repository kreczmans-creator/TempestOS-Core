**What this pack covers.** The twelve Addendum A calculators (M4, M5, M6, S4, S5, S6, B4, B5, B6, E4, E5, E6), result linking (L1) with the Saved calculations list and the Calculation packs panel, the five linked chains, reference records with the licence lock, the independent check, and the sixteen v0.26.0 base templates they build on. Sections 1 to 9 follow the order the addendum asks for (§A8).

**How to use it.**

- Work top to bottom, or follow the order in section 9.
- Every script has a **Result** column. Leave it blank until you test. Write `P` (pass), `F` (fail), `B` (blocked) or `N` (not run), and a short note.
- Expected numbers come from the repository's own known-answer (KAT) cases and from running the real calculators headless on those cases laid over a new sheet's defaults, which is what the form does. Most KATs are analytic: they were computed independently, not copied from a book. A pass here shows the build matches its own specification. Section 4 lists the thirteen KATs that still need a primary source, and the sources nobody has pinned yet.
- The form shows results to about five significant figures; the governing bar shows the utilisation to three. The KAT tolerances are tighter. Where they are tighter, compare with the *Form shows* column.
- A new sheet opens on the template's declared defaults only. Tables are empty. Some values have no default at all. A blocked sheet says what to enter next. Every script says what a new sheet shows before you type.
- Standards are cited by clause or regulation number only. This pack contains no standards text and no table values from BS 7671, BS EN 60204-1, IEC, CIBSE or MCS. The only table-like numbers are test values that the repository marks as invented (the E4 ampacities and factors, the bearing `Y` of 0.8) or illustrative (the B4 layer conductivities).
- Warnings are not failures. Record the ones you see.
- Names such as `L1 motor` are yours to choose; use the ones in the script so the steps read the same.

## 1. Build and run on Windows from a clean clone

**You need.** Windows 10 or 11 x64, Git, and the .NET SDK. `global.json` pins SDK `10.0.302` with `rollForward: latestFeature`, so any 10.0.3xx SDK or later feature band of 10.0 builds it. No workloads, Visual Studio, Node, Python, Docker, database or licence file are needed. The network is needed once, for `dotnet restore`.

**Steps.**

```powershell
# 1. Check the SDK
dotnet --list-sdks

# 2. Clean clone of the release branch (keep it out of any other working tree)
cd $HOME
git clone --branch release/v0.26.0 https://github.com/kreczmans-creator/TempestOS-Core.git TempestOS-Core
cd TempestOS-Core
git log -1 --format="%h %s"      # expect 510f337c or later

# 3. Locked restore, as CI does (fails if a lock file does not match)
dotnet restore src/TempestOS.slnx --locked-mode

# 4. Release build with warnings as errors, as CI does
dotnet build src/TempestOS.slnx --configuration Release --no-restore -p:TreatWarningsAsErrors=true
```

Expected: `Build succeeded.` with `0 Warning(s)` and `0 Error(s)`.

**Automated tests** (the Calc suites run in seconds; run them before you touch the app):

- The title bar reads `TempestOS <version> (<commit>)`. The commit must match `git log -1 --format=%h`. If it does not, you are running a different build.
- To start again from nothing, close the app and delete `$root`.
- No CI step launches the windowed app on Windows (`PHYSICAL_REVIEW.md` §1). Your launch is the first Windows run of this build. Note any window problem separately from the calculator results.
- Create or open a project (rail: Projects) before the linking, pack and record scripts. Links, packs and the Saved calculations list work inside one project. With no project open, nothing is listed and a pack cannot be created.

**Where the calculators are.** Rail: Engineering. Then Modules → Calculations → Worksheets. The same worksheets also sit under Disciplines → (discipline) → Worksheets, and Ctrl+K finds each by name. The older calculators are under Calculations → Calculators.

**The worksheet form, in one paragraph each.**

- *Left column.* The catalogue, then two panels. **Saved calculations** lists the open project's calculations as `name · template title · rev A · status`, with an amber ` · STALE` at the end of a stale one, and has an **Open** button. **Calculation packs** has a **Pack template** picker, a **Pack title** box, **Create pack from template**, **Packs in this project**, **Calculations in the selected pack** with **Open pack member**, a **Check the pack** block (the checker, read-only and set to the signed-in person; **Checker's organisation**, **Check statement**, the outcome picker, **Check pack**, **Reopen pack**) and an **Issue the pack** block (**Issue reference**, **Client**, **Issue pack**).
- *Right column.* Each input is a row `symbol — description`, a value, a unit picker, a source picker (manual, drawing, spec, assumption, evidence, reference, link) and a source reference. The *Recalculating…* marker shows while the sheet updates. Below the inputs are the governing bar (PASS or FAIL with the utilisation, or `Blocked — …`), the results, the checks, the notices and **Show working**. A stale calculation shows an orange `Stale — …` banner, and **Update linked inputs** (a draft) or **Update to revision n** (a checked one) beside it.
- *Buttons.* **Save as calculation** (it reads **Save changes** once saved), **Record check**, **Issue**, **Revise**, **Export inputs (CSV)**, **Import inputs (CSV/JSON)** and, on the base plate, **Attach external report…**. A saved draft also shows the **Link an input to another calculation** row (**Link input**) and, if its template declares record kinds, the **Reference records** panel (**Apply record**, **Save inputs as record**).
- *Tables.* Table inputs have no row editor in this release (D-37). They arrive by **Import inputs (CSV/JSON)** from the clipboard, as JSON or as the CSV the form exports. An import re-seeds the whole form, so import first and type the single values afterwards.
- *Open over unsaved edits.* If the form holds edits that are not saved, the first press of **Open** only says `The form has unsaved changes. Save them first, or press Open again to discard them and open '<name>'.` A second press for the same calculation discards them.

## 3. Manual test scripts

### 3.0 How the scripts work

Each per-calculator script follows one pattern.

1. Open the worksheet (`Engineering → Modules → Calculations → Worksheets`) and read the governing bar before you type: a new sheet opens on the declared defaults only, and the script says what the bar reads (`Blocked — …` with the next thing to enter, or the reading of the defaults).
2. Load any table inputs by import (PowerShell block, then **Import inputs (CSV/JSON)**). Do this first.
3. Type or pick the single values listed, then wait for *Recalculating…* to clear.
4. Compare the results, the governing bar and the checks with the expected column.
5. Run the variation steps. Each one changes an input and has an expected FAIL, a block, or a changed number.

**Inputs.** Every case is the first Confirmed known-answer case of the calculator (its `TestCases`). The expected values are that case's `CalcExpectedValue` list, with its relative tolerance. The *Form shows*, governing-bar, check and notice texts come from running the calculator on the case laid over a new sheet's defaults.

**Governing bar format.** `PASS — <check name>: utilisation <u>` or `FAIL — …`, with `u` to three significant figures. A utilisation at or below 1 passes.

**Typical notices.** Tabulated inputs raise a warning of the kind "a tabulated value not taken from a reference record". That is expected until you apply a record (section 5). It is a warning, not a failure. The sheet prints the repeated ones as one line listing the symbols; the form keeps one per symbol.

**Cell format.** A table cell with a number carries a unit (`"Unit":"mm"`). A text cell carries `"Text"`. A yes/no cell carries `"Flag"`. The JSON in the scripts is exactly the form the import reads. A blank cell is the same as no cell.

**Sources and Check.** A check or an issue is refused until every input has a source other than *manual*. Values you type in a per-calculator script are *manual*, so those scripts stop before Check. The worked examples carry sources on every input, so T-00, T-L1, T-IND and T-REC use them. The packs' example inputs carry the source `assumption: example input — replace with your own`.

### 3.C The five chains (A7): create a pack, follow the values, break an upstream input, mend it, check, issue

**How the chain scripts work.** Each script runs in the **Calculation packs** panel of the worksheet form. You need an open project. **Use a new project for each chain script**: calculation names are unique in a project, and several chains share step names (for example `Motor sizing` and `Enclosure heat`). A second pack in the same project is refused with `The project already holds a calculation called '<name>' (step '<key>'); … cannot be instantiated here twice, or beside a calculation of that name. Rename the existing one first.`

The pack templates are built in and carry example inputs. Every example input is recorded with the source `assumption: example input — replace with your own`, so the packs can be checked. ### T-REC Reference records and the licence lock

Part 1 tests the mechanism on M5, because M5 does not demand an independent check, so you can check and issue alone. The numbers are the repository's test values, not the SKF figures; the lock does not care. Part 2 sets up the E4 records from your own copies.

**What the lock does (§A5, DA-23).** A value taken from a record marked *Licensed source* never leaves the program as a value:

- The CSV export (**Export inputs (CSV)**) writes the symbol and the record pin and no value: the reference reads `record:<32 hex digits>@<rev> · licensed value withheld`. A licensed table is written as its own row only, with no rows.
- A CSV or JSON re-import of a withheld scalar is **blocked** until the record is applied again. A withheld table comes back empty with a warning, and the sheet is blocked.
- An issued sheet, a pack sheet and the preview withhold the **rows** of a table pinned to a licensed record. They print the record pin, its citation and `rows withheld (licensed record); the values used appear in the working`. A scalar from a licensed record is the value used and stays on the sheet.
- The lock follows the provenance, not the numbers (DA-18): if you retype a licensed value with another source, it exports.

## 5. Licensed-record setup

**Rule (§A5).** No BS 7671 or IET table, BS EN 60204-1 table, IEC 60364 table, CIBSE or MCS design-data table, Eurocode National Annex table beyond small factor sets, SKF or Schaeffler aISO diagram, Peterson chart or Roark table ships in source, seeds, fixtures or KATs. **No reference record ships with the product at all.** You enter the values from your own licensed copy or from manufacturer datasheets. This pack lists no table values.

**What a record holds.** Kind, title, revision, source title, edition **and amendment** (record keys must include the amendment, because sources disagree on what an amendment changed), table or clause, licence holder, who entered it (the signed-in person), a **licensed source** flag, and the values. A record is never edited: a change saves the next revision. A calculation pins the revision it used. A record revised after use makes the calculation stale ("Apply the record again"), at every depth of a chain, and a pin to a revision that does not exist counts as stale.

**When to tick *Licensed source*.** Tick it for values copied from a standard or guide you hold under licence (BS 7671, BS EN 60204-1, CIBSE, a National Annex table). Whether to tick it for manufacturer datasheet values depends on the manufacturer's terms. That is your call (section 7).

### 5.2 How to enter a record

1. Open the worksheet, import any table inputs, type the single values, and **Save as calculation**. The records panel shows only for a saved draft whose template declares record kinds.
2. In the panel pick the record kind. Fill Title, Source title, Edition and amendment, Table or clause and Licence holder. All five are required. Tick **Licensed source (never exported)** where it applies.
3. Press **Save inputs as record**. The record takes the form's current values for that kind's symbols, and the inputs now cite it.
4. On another draft of a template that uses the same kind, pick the record under **Take values from** and press **Apply record**. The inputs take the values and cite the record as their source, with the edition as the revision.

The record form always saves a new record at revision 1. Later revisions exist only in the Library service and its tests.

### 5.3 How the licence lock behaves

Grounded in `CalcInstanceService.Records.cs`, `CalcCsv.cs`, `CalcInputJson.cs`, `CalcSheetBuilder.cs` and their tests.

| Path | Behaviour |
|---|---|
| **Export inputs (CSV)** (worksheet) | Passes through `WithholdLicensedAsync`. An input whose source is a licensed record keeps its symbol and its record pin, loses its value, and reads `record:<id>@<rev> · licensed value withheld`. Unlicensed values export. A table is exported cell by cell with each cell's unit and source (so table-cell links round-trip); a table pinned to a licensed record is written as its own row only, with no rows. |
| **CSV or JSON re-import of a withheld value** | A withheld scalar is **blocked**: `<symbol>: this value was withheld on export (licensed record) and is not in the file; apply the record again, or enter the value from your own copy.` (CSV adds `Row <n>: ` in front.) Nothing is imported until you apply the record again or enter the value. A withheld table comes back empty with a warning, and the validator blocks the run. It never comes back as the template default. |
| `ExportRecordAsync` (the record itself) | Refuses a licensed record with: `Record '<title>' holds values from a licensed source (<source>, <edition>); its values are never exported.` Not reachable from the Desktop; tests only. An unlicensed record exports as CSV with its citation in one quoted cell. |
| Issued sheet, pack sheet, preview and PDF | Rows of a table pinned to a licensed record are withheld: the sheet prints the pin, the record's citation and `rows withheld (licensed record); the values used appear in the working`. A scalar from a licensed record is the value used and stays. That is the user's own calculation, so issuing is allowed. A pin to a revision that does not exist is judged by the record's latest revision. |
| Revision of a licensed record | Stays licensed. A revision cannot clear the flag. |
| A record saved from inputs that cite a licensed record | Becomes licensed, so licensed values cannot be laundered into an exportable record. |
| Calc-pack export, record attachments | No such export path exists today. Any new one must use the same guard (DA-06). |
| Known limit (DA-18) | The lock follows the **provenance**, not the numbers. If you retype a licensed value with another source, it exports. |
