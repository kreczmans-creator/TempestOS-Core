# W1 — CAD parameter import (`Tempest.Calc.Import`, ADR-0171)

**Scope.** Brings parameters out of a CAD file into the inputs of a draft calculation, with provenance on every value, and re-imports a changed file as a diff that updates the draft (and so makes linked calculations stale through the existing machinery). Formats: NX expression files (`.exp`) and NX expressions in a workbook (`.xlsx`); Creo relations and parameters as text; SolidWorks equations (text) and design tables (`.xlsx`); Onshape variables as CSV or JSON; and a generic CSV/JSON schema (below). The files are untrusted. **Nothing is evaluated**: an expression with a reference, a function or an operator is kept as read-only text and cannot be mapped to an input as a number. W1 is a workflow, not a worksheet calculator: it has no template, no hash and no sheet of its own; its mark on a sheet is the provenance of each imported input and the import record on the instance.

**Method.**

1. *Read.* `BoundedInputReader` streams the file to at most 5 MB (stopped at the cap, not after it), under a 10 s limit and the caller's cancellation, takes its SHA-256, and for a text format decodes strict UTF-8 (a BOM is dropped; UTF-16/32 and invalid bytes are refused) and refuses any control character other than tab, CR and LF. A workbook goes to `XlsxReader` (hand-written, no package): entry count, names, declared sizes, expanded:compressed ratio and the bytes actually produced are checked against caps; macros, DTDs and entities are refused; external links are not followed; formula cells give their **cached value only**.
2. *Classify.* A right-hand side is a literal only when it is exactly a number (in the declared format) with an optional unit, a boolean word, or a quoted string. Anything else is an expression (CAD expression files) or a text value (data cells in a design table or CSV). Numbers use the declared decimal mark (decimal point by default, decimal comma by setting, optional grouping); a number in the other notation is **refused**, never reinterpreted, and an expression that looks like one gets a notice. Units resolve through the engine's `UnitCatalog` (NX spellings such as `MilliMeter` and `Degrees` by alias); an unknown unit leaves the value unmappable.
3. *Map.* A named, versioned **mapping profile** maps CAD names to template input symbols (`W`) or to a cell of an existing table row (`contributors[2].nominal`, row zero-based), with an optional `assumedUnit` for a value the file states without a unit. The value is checked by dimension against the input's unit (and angle, ratio and count are kept apart), converted into the input's own unit, and refused with a message otherwise. Names in the file that the profile does not list are **reported** (unmapped; or read-only expression), profile names the file lacks are reported (refused when `required`), a name assigned twice is refused, and while anything is refused nothing is applied.
4. *Provenance.* Every imported value carries `CalcProvenanceKind.CadImport`: reference `cad:<system> <version>|<part>|<part revision>|<file SHA-256>|<import time, UTC to the minute>|<CAD parameter name>` (at most 200 characters; the part and parameter names are shortened first, the hash never), revision `<profile id>@<profile version>`. CAD version, part name and revision come from the file where it states them and can be entered by the person (which wins). The instance also keeps a `CadImportRecord` per source (system, profile, part): file name and hash, who and when, and every parameter of the file as imported.
5. *Apply and re-import.* `CalcInstanceService.PreviewCadImportAsync` shows everything above plus the diff against the previous import and what the calculation would block or warn about afterwards, changing nothing. `ApplyCadImportAsync` updates the **draft** through the ordinary input update (the import record commits in the same write); a calculation linked to the draft goes stale if the draft's outputs changed. The diff lists added, removed and changed parameters and which of them move an input; a parameter that disappeared leaves its input at the last imported value. A checked, issued or superseded calculation is never changed in place: revise it first (the revision carries the import record).

**Inputs.** The file (≤ 5 MB), its format (offered from the extension and a sniff), a mapping profile, and optional entries: CAD version, part name, revision, number format (decimal comma), design-table configuration, workbook sheet. Limits (`ImportLimits.Default`): 100 000 rows, 256 columns, 4096 characters per field, 128 per name, 5000 parameters, 256 workbook parts, 64 MB expanded in total and 32 MB per part, ratio 100:1 above 1 MB; `ImportLimits.Scan` raises rows to 1 000 000 for W2.

**Outputs.** The draft's inputs with provenance, the import record, the diff, and CSV reports of the preview and the diff (`CadImportReport`, every text from the file defused against spreadsheet formulas). In the worksheet form: *Import CAD parameters…* beside *Import inputs (CSV/JSON)*, on a saved, unedited draft: choose file, format and profile (or load a profile as JSON), read the preview (mapped / refused / unmapped / read-only expressions / missing, the changes since last time, what the calculation would block), then *Apply import*.

**Formats and the generic schema.**

| Format | Reads | Notes |
|---|---|---|
| NX `.exp` | `[unit]name=rhs`, optional `(Type)`, `//` comments (also trailing, outside quotes) | Header comments `NX <version>`, `Part: <name>`, `Revision: <x>` are read when present. `(Point)`, `(Vector)` and similar are expressions. |
| NX `.xlsx` | A header row with Name, Formula, Value, Unit, Type, Comment (aliases accepted); without a header, columns name, value, unit | A formula that is not a literal is an expression (its Value column is shown only as the "reported" value). A Value cell that is a spreadsheet formula gives its saved result, flagged. |
| Creo text | `name = rhs` relations, `/* … */` comments (also across lines), `IF/ELSE/ENDIF` (assignments inside are expressions), parameter lines `NAME TYPE VALUE [unit]` (REAL, INTEGER, STRING, YES_NO) | Creo states no units in relations: map with `assumedUnit`. |
| SolidWorks equations | `"name"= rhs`, `'` comments | Quoted names inside the right-hand side are references, so the line is an expression. A unit may follow the number (`40.5mm`, `90deg`). |
| SolidWorks design table | Title cell `Design Table for: <part>`, a header row of parameter names, one row per configuration (or per column, by setting) | One configuration is read (the first, or the one named); `$`-headers are text. |
| Onshape CSV / JSON | Columns `name`, `expression` and/or `value`; or the variable tables of the REST API (`variables` lists) | A leading `#` is dropped from names. A JSON `value` with a `type` but no unit is read as SI (LENGTH metres, ANGLE radians) and a notice says so. |
| Generic CSV | Header with `name` and `value` (and any of `unit`, `expression`, `text`, `description`) | A `value` that is not a number is **text**; an `expression` is read-only. Delimiter detected (`,` `;` tab). |
| Generic JSON | `{ "schema": "tempest.cad-parameters/1", "cad_version", "part", "revision", "parameters": [ { "name", "value" (number, string or boolean), "unit", "expression", "text", "description" } ] }`, or the bare list | |

Mapping profile JSON:

```json
{
  "id": "nx-stack", "version": 1, "title": "NX stack lengths to M1",
  "system": "nx", "templateId": "mech.tolerance-stack", "ignoreCase": false,
  "number": { "decimal": "point" },
  "entries": [
    { "cadName": "plate_len", "target": "contributors[0].nominal" },
    { "cadName": "gap_min", "target": "minimum", "assumedUnit": "mm", "required": true }
  ]
}
```

**Limitations.** Reads parameters, not geometry or assemblies. A mapping applies to inputs of the draft and to cells of table rows that already exist (it never adds a row). Creo and SolidWorks text and the NX workbook layout are read as documented here; real exports vary by version and locale. One configuration of a design table per import. A workbook feature beyond cell values (styles, dates as dates, tables) is not read. The preview's "would block" list is the calculation's own validation; an out-of-range value is applied and then blocks the draft exactly as if typed. Staleness downstream is the existing coarse rule: any change in the draft's outputs.

**Test cases.** `tests/Tempest.Calc.Tests.Import`: golden sample files per CAD system under `Samples/` (invented parts); the bounded reader (oversize, endless and stalled streams, cancellation, BOM, UTF-16, invalid UTF-8, control characters); number parsing (point, comma, grouping, the other notation refused, NaN/Infinity/overflow/Unicode digits); paths (traversal, UNC, devices, streams, reserved names, root containment, links); CSV in and out (RFC 4180 cases, caps, injection prefixes, round trip); the workbook reader (cached value only, zip bomb by size and by ratio, a lying directory, macros, DTD/entity bombs and XXE, external relationships, caps, truncation); mapping (dimension mismatch, assumed unit, angle/ratio/count, expressions refused, unmapped/missing reporting, table cells, duplicates, system/template mismatch); provenance and diff; profile JSON; and CsCheck fuzz/property tests (random bytes, token soup, single-byte edits and truncations of every sample, 5 MB worst cases) holding the documented-refusal contract. `tests/Tempest.Calc.Tests.Library/Chains/CadDrivenToleranceChainTests.cs`: chain 3 — an NX `.exp` into an M1 tolerance-stack draft, a linked M2 fit, a re-import that stales it. `tests/Tempest.Desktop.Tests/CalcSheets/WorksheetCadImportTests.cs`: the view-model path in the form. **Unconfirmed (owner check against real exports):** the NX `.xlsx` column names, a Creo parameter export, and the Onshape REST variable value units; the samples are invented from the formats' documented shape.
