# DC-14 — Calculations on an earlier template version, and revision labels after Z (DC-15) (`Tempest.Calc.Library`, `Tempest.Desktop.CalcSheets`, ADR-0177)

**In plain terms.** Every worksheet template has a version (`mech.shaft@1.6.0`). A calculation remembers the version it was made on. When a template is revised to a new version, the calculations made on the earlier one are not lost and are not quietly moved: the worksheet tells you which version they were made on, whether the version now installed gives exactly the same numbers, and how to carry them forward.

**What you see when you open one.**

- *A draft.* Its inputs open as a new, unsaved sheet on the current version, named `<name> (<new version>)`. An input the new version renamed is carried under its new name; one the new version no longer has is named in the message and left out. Check the inputs and Save to keep it as a new calculation. The old draft is left exactly as it was.
- *An issued (or superseded) calculation.* The sheet as it was issued, read-only, with a status line that says: which version it was made on and which version replaced it; whether a re-run on the installed version comes out exactly as stored ("re-ran on `id@1.1.0`, which has replaced `id@1.0.0`: all 7 stored outputs and 2 stored checks come out exactly as stored") or, where it does not, which values differ and that it stays as stored ("cannot be re-run exactly on …: sigma is 66 MPa where it was 60 MPa. It stays as stored, read-only."); and the way forward: **Revise** starts the next revision as a draft on the current version with the inputs carried. The issued record is never changed by opening it or by a re-run.
- *A checked calculation.* Its stored results (outputs, checks, warnings, who checked it) read-only, with the same sentence. It cannot be issued on a version that is not installed; **Revise** carries it to the current version, then check and issue it again.
- *A calculation made by a newer build than this one.* Shown as stored; open it in a build that has that version.

**What "re-runs on its own version" means.** The formulas of a template version are code, and the product ships one current version of each template. The list of every version that ever shipped, with the fingerprint of its content, is the template version manifest (`tests/Tempest.Calc.Tests.Library/TemplateVersionManifest.json`, add-only, embedded in the product). A version on that list is always resolvable: the worksheet knows what it was and what it became. Where the installed version reproduces every stored output and check exactly, the re-run is reported as such; where it does not, the stored sheet stands and the sentence says what differs. Where a particular version must stay literally re-runnable, its calculator can be kept beside the current one under its own version; the worksheet then runs it as itself, and new sheets still start on the current version. The trade-off is in ADR-0177.

**New sheets** always start on the current version. The template tree lists only current versions.

**An input that came to mean something else.** A version may keep a symbol but change what it stands for (an axis swapped, a width that became a depth). The template says so on that input (`MeaningChangedAt`, the version; `MeaningWas` and `MeaningNow`, in plain words), and a value stored under that symbol by a calculation made before that version is never carried into a new sheet, a revision or a link: the draft upgrade leaves it out and names it ("d meant the width of the plate on `id@1.1.0`; since `id@1.2.0` it means the depth of the plate, so its stored value was not carried: enter it afresh."); Revise refuses with the same sentence and says to start a new calculation on the current version, reading the other inputs from the stored sheet; a link from such a revision is refused, an existing one is reported stale and is never moved by "update links"; a pack binding saved from such a version is refused. A value stored under an input's old name (an alias) keeps its meaning. An old record that holds one input under two of its names with different values carries neither, both named, instead of one being chosen for you.

**An input whose unit changed.** A version may change the unit an input is entered in by default (bar to kPa). A stored value that carries its own unit is unaffected. A stored value with no unit of its own (a bare number) is read in the default unit of the version it was made on, never the new one: a bare 0.3 stored while the input was in bar is 0.3 bar (30 kPa) wherever it is shown, re-run or carried, and the draft upgrade and Revise carry it with that unit made explicit. The template says so on that input (`UnitChangedAt`, the version; `UnitWas`, the unit before). A bare number on a record that carries no version at all (an inputs file, a CSV, a legacy record) cannot be told apart and is refused with one sentence naming the symbol and both units: "p_margin: the stored value has no unit and the record does not say which template version it was made on, so it cannot be read: p_margin was in bar before version 1.3.0 and is in kPa since; enter it with its unit." A new sheet starts in the new unit with the new default.

**What is refused, and the sentence.** Editing, checking, issuing, attesting, countersigning, linking into, importing into, or issuing a pack containing a calculation whose version has been revised is refused with one sentence: "Calculation 'X' was made on `id@1.0.0`, which has been revised to `id@1.1.0`, so …" and what to do. Nothing says "no longer registered" unless the template really is gone from the build.

**Revision labels (DC-15).** Revisions are lettered A, B, … Z, then AA, AB, … AZ, BA, … ZZ, AAA, as spreadsheet columns are. A calculation whose first revision was a number carries on in numbers. Labels made before this change (Z+, Z++) still read and sort as the 27th, 28th … revision, and the revision after one of them carries on in letters (Z+ is followed by AB). Lists order labels by the order the revisions were made, not alphabetically, so AA comes after Z and AAA after ZZ.

**Limits.** A re-run names at most the first three differences in its sentence and lists at most 20 differing symbols; a stored-results summary prints at most 500 rows a section and says how many more there are. The manifest is refused over 4 MB or with a line that is not `id@version` and a 64-character hash.
