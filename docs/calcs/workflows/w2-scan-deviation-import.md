# W2 — Scan deviation import → statistics → Cpk → M1 / F3 / M2 (`Tempest.Calc.Import.Scan`, ADR-0172)

**Scope.** Reads scan or inspection deviation tables (ZEISS or GOM Inspect tables, multi-stage tables, PolyWorks and Geomagic Control X text) through the person's own column profile, computes the statistics of each feature over N parts, and pushes a fitted normal distribution into the inputs of a calculation — an M1 tolerance-stack contributor, an F3 measured groove row, or a single input such as an M2 fit's size — with provenance on every value. A re-import is a diff that updates the draft and so makes linked calculations stale. The files are untrusted. W2 is a workflow, not a worksheet calculator: it has no template, no hash and no sheet of its own; its marks on a sheet are the provenance of each fitted value and the import record on the instance. **The PDF table path is not built** (dropped under the §B2 drop order); export the table as CSV or `.xlsx`.

**Method.**

1. *Read.* `BoundedInputReader` (5 MB, strict UTF-8, no control character; `.xlsx` through `XlsxReader`, cached values only), `CsvReader` or a whitespace splitter under the profile's delimiter, `LocaleNumber` under the profile's declared decimal mark. Row cap 1e6; at most 64 files. A header the profile names that the file lacks refuses the import and lists the headers the file has. A data row with more fields than the header is refused, blank extra fields included, and so is a value under a column with no header; the same file twice and a total over 20 MB are refused. With the number format undeclared in the profile, a comma-delimited table whose values are all written as whole numbers is blocked, and so is a whole number followed (in a column nothing is mapped to) by digits with a leading zero, row by row; stating the number format lifts both. A blank cell is missing (not zero); text that is not a plain finite number is reported and treated as missing; a row without an actual value (or nominal + deviation) is reported and not used; markup and links in names are removed and reported.
2. *Rows.* Value = actual, else nominal + deviation, else the deviation alone (a deviation-only population about zero). Limits = nominal + the tolerance deviations (upper ≥ 0 ≥ lower), or the absolute limits, per the profile. Features are grouped by stage and name (case-insensitive by default). Stage and serial come from a column, else from the stage/serial entered for the file, else from the profile.
3. *Statistics* (`ScanStatistics`): x̄ = Σx/N; s = √(Σ(x − x̄)²/(N − 1)). **Overall σ** = s. **Within σ** = √(Σⱼ Σ(x − x̄ⱼ)² / Σⱼ(nⱼ − 1)) over consecutive subgroups of the stated size; with **no subgrouping (size 1) the within σ is s, so Cp = Pp and Cpk = Ppk**. Subgroups are cut by position before any outlier is left out. **The pooled σ is c4-corrected**: the pooled variance is unbiased but its square root is not, so with subgroups the within σ is the pooled σ divided by c4(d), d = Σ(nⱼ − 1) + 1 (c4(n) = √(2/(n − 1))·Γ(n/2)/Γ((n − 1)/2), formed with the log-gamma function); the divisor is shown on the output (`ScanFeatureStats.WithinC4`, `WithinBasis`, the `within_c4` column of the statistics CSV and the statistics line of the import form), and with no subgrouping nothing is pooled and nothing is corrected (c4 is blank). Cp = (USL − LSL)/(6σ_within), Cpk = min(USL − x̄, x̄ − LSL)/(3σ_within); Pp, Ppk the same with s. One limit: Cpk/Ppk for that side, no Cp/Pp. σ = 0: no index. *Normality:* Anderson–Darling A² = −N − (1/N) Σᵢ (2i − 1)[ln Φ(zᵢ) + ln(1 − Φ(z_{N+1−i}))], zᵢ = (x₍ᵢ₎ − x̄)/s; A*² = A²(1 + 0.75/N + 2.25/N²); p from the D'Agostino–Stephens piecewise approximation (cited: Anderson and Darling 1954; D'Agostino and Stephens 1986, section 4.4); verdict at the stated level (default 0.05). *Outliers:* Tukey's fences, reported, kept unless the person asks to leave them out. *Minimum N:* fewer than 2 parts: not computable; fewer than 8: normality not assessed; fewer than 30 (adjustable): capability warning.
4. *Push* (`ScanMapper`). The profile maps `feature` (optionally at a `stage`) to a target: `D` / `D:sigma` / `D:nominal` / `D:min` / `D:max` (a single input), `contributors[2]` (an existing stack row: nominal from the scan, `shift` = fitted mean − nominal, `sigma` = the measured σ where the table has that column (M1 2.1.0), `upper` = +kσ, `lower` = −kσ with the stack's own k for the worst case, `distribution` = normal), `measured{D_g}` (the measured-dimension row for D_g: `mean`, `sigma`, normal; added or replaced). Units are checked by dimension and converted; a spread by scale only. A feature whose σ is zero is never pushed. For `mech.iso286-fit` only `D:nominal` and deviations from the nominal into `ES_override`/`EI_override`/`es_override`/`ei_override` (max, min or mean less the nominal, in µm) are allowed.
5. *Provenance.* `CalcProvenanceKind.ScanImport`, reference `scan:<software version>|<stage>|<serials>|<alignment>|<SHA-256>|<time, UTC to the minute>|<feature>` (≤ 200 characters; free text shortened, never the hash or the time; the hash is that of the file, or of the set of files when a feature's parts came from several), revision `<profile id>@<version>`. The alignment is what the person entered. The instance keeps a `ScanImportRecord` per profile (files and hashes, software, alignment, who and when, every feature fitted with the values written). A value claiming `ScanImport` provenance stands on save only if a record holds that exact provenance and value at that place (`ScanImportVerifier`); otherwise it becomes a Manual entry and the person is told which. A claim on a whole table never stands; a scan-imported table is issuable while every number in it has a source that is enough to issue with. Records are kept while a value still cites their file by hash. A created calculation cannot cite one.
6. *Apply and re-import.* `CalcInstanceService.PreviewScanImportAsync` shows the statistics, the mapping, what was reported, the diff against the previous import and what the calculation would block or warn about afterwards, changing nothing. `ApplyScanImportAsync` updates the **draft** through the ordinary input update; a calculation linked to the draft goes stale if its outputs changed. A checked, issued or superseded calculation is never changed in place.

**Inputs.** One or more tables (each ≤ 5 MB) with the stage and serial for a table that has no column for them; a scan profile (stored, versioned, or loaded as JSON); optional entries: software version, alignment name, subgroup size, minimum parts, whether to leave flagged outliers out. Limits (`ScanSettings.Limits`): 1 000 000 rows, 256 columns, 4096 characters per field, 128 per feature name, 5000 features (counting stages), 30 s.

**Profile JSON.**

```json
{
  "id": "zeiss-groove", "version": 1, "title": "ZEISS Inspect groove table",
  "software": "zeissInspect", "unit": "mm", "delimiter": "auto", "headerRow": 1,
  "toleranceMode": "deviationsFromNominal", "templateId": "mech.tolerance-stack",
  "number": { "decimal": "point" },
  "columns": { "feature": "Element", "nominal": "Nominal", "actual": "Actual", "deviation": "Deviation",
               "upperTolerance": "Upper tol.", "lowerTolerance": "Lower tol.", "serial": "Serial", "stage": "Stage" },
  "features": [ { "feature": "D_g groove root", "target": "contributors[0]", "required": true },
                { "feature": "D_s bore", "target": "measured{D_s}", "stage": "OP20 finish" } ]
}
```

A column is a header text, or a position `#3`. A whitespace-separated text report is read with `"delimiter": "whitespace"` and positions.

**Outputs.** The draft's inputs with provenance, the import record, the diff, the statistics and problem reports as CSV (`ScanImportReport`, every text from a file defused against spreadsheet formulas). In the worksheet form: *Import scan deviations…* beside *Import CAD parameters…*, on a saved, unedited draft: choose tables (with stage/serial), a profile, the facts about the measurement; read the statistics, the mapping, what was reported and what changed; *Apply import*; *Cancel reading* stops a long parse.

**Limitations.** Normal fits only (no uniform or triangular fit). A table does not carry production order, so the within σ needs a stated subgroup size and no moving-range estimate is made. The mapping applies to inputs of the draft and to existing stack rows (it never adds a stack row; a measured-dimension row may be added). A tolerance given as deviations must have upper ≥ 0 ≥ lower; otherwise use absolute limits. A text report with trailing words in a data row is refused. IgnoreCase defaults to true and merges names that differ only in case (reported). The header spellings offered as suggestions, and the layouts of real exports, are **unconfirmed** — checked in the owner test pack against real files. A fitted distribution is as good as the sample and the alignment; M1's and F3's own checks decide whether the result passes.

**Test cases.** `tests/Tempest.Calc.Tests.Import`: statistics against python3 (`math.fsum`, `math.erfc`, the published formulae) and a ten-value hand calculation (mean 10.003, s 0.0188856, Cp = Pp 0.8825, Cpk = Ppk 0.8296; subgroups of five: pooled σ exactly 0.02 on 8 degrees of freedom, c4(9) = 0.96931, σ_within 0.020633, Cp 0.8078, Cpk 0.7593; the uncorrected 0.02 gave 0.8333 and 0.7833, about 3 % optimistic; c4 against the published table and `math.lgamma`); the N = 30 reference tables (ZEISS-style, three features); a GOM-style two-stage table with semicolons and decimal commas; a PolyWorks-style text report; Geomagic-style tab table; a workbook; stage and serial per file; blank, NaN, Infinity, `1e999`, other-notation, markup and link cells; outliers; profile mismatch (headers, delimiter, number format, duplicate header, position); ragged rows; caps (rows at a small limit and at 1e6, files, features, time, cancellation); mapping into stack rows, measured rows and single inputs with unit conversion and refusals; provenance round-trip and caps; profile JSON; CsCheck fuzz/property tests (random bytes, token soup, header + soup rows, arbitrary doubles, edits of every sample and of a workbook, random profile JSON, arbitrary mapping). `tests/Tempest.Calc.Tests.Library/Chains/ScanToSealChainTests.cs`: chain 2 — a scan table into an M1 groove-root stack and into F3's measured rows, F3's groove root linked to the stack, a re-scan that makes F3 stale; provenance checks (an edited or forged claim is refused). `tests/Tempest.Desktop.Tests/CalcSheets/WorksheetScanImportTests.cs`: the view-model path in the form, including a real asynchronous `FileStream`.
